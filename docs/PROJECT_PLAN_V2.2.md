# Siderfolio V2.2 开发文档｜Agent 长期记忆与上下文管理

**日期** 2026-11-26　**目标版本** `v2.2.0`　**实施基线** `v2.1.0`（`5873ba8`）　**状态** 待开发、待验收

支持用户在新会话中复用已保存的研究背景与偏好，在长对话中延续早期目标，并用来源区分历史记录、当前要求和已核验的科研结果。沿用单 Agent、PostgreSQL 和 pgvector，前端从现有设置页进入记忆管理。Multi-Agent 按既有路线顺延。[版本路线图](ROADMAP.md)

## 2. 记忆采集和管理

- **用户控制。** 「设置 → 记忆管理」提供搜索、筛选、查看来源、新增、编辑、删除和候选审核。首版对既有账号默认关闭自动提取、跨会话注入和历史对话检索，三个开关可分别控制。单条记忆支持暂停或恢复跨会话使用。用户说「记住我主要用 Python 做数据分析」时，可直接保存明确、范围唯一的普通偏好并返回回执。关闭注入后保留可管理的记录，重新开启前不向模型发送这些记录。
- **自动提取。** 用户开启后，从刚完成轮次中用户亲自表述的内容提取结构化候选，附原句定位和建议范围。候选经用户确认后进入长期记忆。跳过、拒绝或删除后，原轮次的同一内容不应立即再次被提议。首版先做有界的本地规则，已配置并经过核对的小模型可补充提取能力。自动整理不可用时仍可手动保存。自动过程禁止从文献、附件、工具返回和模型回答推断用户身份或偏好，凭据、联系方式及敏感个人信息排除在自动提取之外。
- **范围。** 全局个人记忆仅当前账号可用。项目记忆绑定当前账号、项目 ID 和可核验的项目来源，只在所属项目读取。将信息从项目转为全局记忆须由用户显式选择。首版每条记忆仅保留一个范围，避免跨空间重复生效。
- **更新。** 同范围内按类别及规范化内容判重。用户明确修改后，旧版本从检索中撤下，新版本记录来源和修订号。遇到「研究方向已转变」或参数冲突但未明确替换时，先显示候选与现有项，由用户决定合并、替换或保留。历史观察、模拟结果与用户偏好分开记录，用户修改参数不覆盖旧实验。
- **撤销。** 删除记忆时同时撤销搜索索引、向量及注入缓存。源会话、轮次或项目被删除、改写或失去访问权时，源材料和相关派生片段停止被引用，按来源关系重新校验受影响的记忆。旧回答和既有备份按原有保留策略管理。

建议数据契约包含记忆 ID、所属范围、类别、摘要、状态、修订号、创建／变更时间，以及来源类型、来源会话或项目、轮次和版本。手工录入项标为「用户手工录入」。候选、正式记忆和摘要分别记录用途，候选不参与模型上下文。按账号通过现有私有 schema 持久化，更新和删除使用版本检查，重复确认返回同一结果。来源正文仍由原业务记录管理。[身份与存储实现](../src/astroagent/identity.py)

## 3. 历史检索与长对话压缩

### 3.1 跨会话检索

1. 从服务端实际登录账号、当前会话归属和开关算出允许检索范围，再排序。个人空间可使用已允许的个人历史，项目空间只召回同一项目的历史，另可叠加获准的全局个人记忆。
2. 先用现有 PostgreSQL 做关键词匹配，支持中文短词和英文术语，并加上相关性门槛。同账号同范围内去重后再限制条数。可选使用已有本地嵌入与 pgvector，固定模型版本和维度。模型缺失、版本不符或索引未就绪时继续使用词法检索。
3. 给模型提供最少量的片段和真实源定位。回答引用早期内容时，用户可打开原会话对应轮次，核对当时参数、日期、工具与来源。历史引用的文献条目、查询坐标和计算结果保留「历史」标签。用户要求最新结果时按现有规则重新调用工具。

### 3.2 当前会话压缩

在早期历史即将被轮次或字节上限移出时，优先保留其已确认目标、关键条件、待解决问题和结论来源，并记录摘要覆盖的 ID、首末轮次与各轮版本。摘要与原文分开存放。首版仅整理已完成轮次，沿用原窗口的失败提示及工具结果引用规则。源轮次更新或删除后，旧摘要停止注入，必要时按仍可读的原文重建。

摘要生成按会话和输入版本去重，限制每轮可整理的数据量。摘要预算不足、模型超时或没有可用摘要时，恢复现有近期窗口，保留遗漏提示。压缩既有工具结果时保留关键单位和原始引用，历史模拟结论仍需回查对应参数与产物。压缩只生成派生文本，旧对话可完整打开和导出。

### 3.3 组装顺序与预算

当前用户指令优先于已存偏好，之后是当前项目的有效约束、会话近期窗口、较早摘要及相关记忆。记忆与历史片段标记为参考数据。内容冲突时采用用户本轮明确条件，必要时提问。当前批准的工具、项目权限和外发字段仍由服务端执行。名称解析、ADS 文献入库、MCP 外发、绘图和 N 体提交分别沿用既有验证及确认。

首轮拟采用检索最多 5 条记忆、3 个历史片段、摘要最多 4 KiB 的默认上限。所有新增数据一起计入现有总消息字节预算并预留工具参数及输出空间，相关性低的可选片段优先裁剪。按模型可获取的真实 Token、调用次数和耗时验证压缩收益。任何追加的模型调用计入账号配额并预先告知用量来源，默认复用本地处理和缓存，失败时继续常规对话。

## 4. 页面、接口与运维

- 在个人设置增加「记忆管理」，记录显示分类、范围、来源及生效状态。项目总览按需显示本项目的记忆和待确认项。会话运行详情显示本轮使用过的记忆或历史引用、摘要覆盖范围以及降级原因，敏感正文只在原有权限页面读取。
- 筛选和表单下拉统一复用 `UiSelect`。进入页面、修改筛选、打开弹窗或完成写操作时自动同步。读取和操作错误使用 `StatusNotice` 顶部浮层，字段即时校验沿用表单规范。移动端和键盘交互纳入验收。[UI 设计规范](UI_DESIGN_SPEC.md)
- API 增加记忆偏好、查询、新增、编辑、删除和候选审核。由已登录账号推导所有者，由服务端核对项目归属。现有对话接口保留原行为，扩展字段为可选，向运行详情提供可回查的引用标识。接口定稿后同步生成 OpenAPI 和 TypeScript 类型。
- 使用独立测试库验证新增表、索引、备份恢复和回退。停止功能时保留旧会话与科研数据。删除真实数据、正式迁移及生产发布走各自授权。日志只记录时间、状态、计量和必要的关联 ID，禁止记录完整记忆、摘要、凭据、附件或用户原文。[开发与发布手册](DEVELOPMENT_AND_RELEASE.md)

## 5. 开发顺序

| 阶段 | 主要任务及退出条件 |
| --- | --- |
| M0 数据与权限契约 | 建立数据模型、来源与版本规则、开关默认值及预算基线。用合成数据定义个人空间、同一项目和跨项目的读取边界。 |
| M1 个人记忆闭环 | 建表和接口、自动候选、手工保存、编辑删除、关键词检索及个人设置。新对话能够使用已确认的记忆并定位原轮次。 |
| M2 长对话与历史检索 | 完成摘要生成和失效、预算降级、历史对话检索和引用。基于固定长对话对照原窗口，核对字段、单位和历史更新后的一致性。 |
| M3 项目记忆与联动 | 按 P1 范围添加项目管理、冲突处理、可选向量召回和技能联动。沿用原工具权限，并完成升级、备份和回退演练。 |

## 6. 验收标准

| 场景 | 必须验证的行为 |
| --- | --- |
| 跨会话个性化 | 用合成账号保存「研究不同外部环境下的双星团动力学演化，主要使用 N 体模拟」后，在新会话问「找几篇和我研究方向相关的论文」。启用记忆时可追溯该研究方向，并按现有 ADS 入口检索。P1 另核对基于此上下文匹配文献技能。关闭跨会话使用后，同样的问题请求补充研究方向。 |
| 用户控制与冲突 | 自动提取关闭时不产生候选。用户拒绝候选、编辑、删除、暂停单条记忆、移动来源或关闭检索后，旧内容不再进入下一轮上下文。当前用户要求与旧偏好冲突时采用当轮要求。 |
| 长历史与证据 | 用超过 24 轮的固定样例核对压缩前后模型输入、重要条件、量纲及来源。摘要失败时近期历史仍可使用。原始内容和导出保持完整，历史条件能返回原轮次核查。 |
| 账号、项目与工具权限 | 至少两个账号和两个项目覆盖访问、引用、停用和删除。越权数据不得进入检索结果、模型请求或迹线。旧笔记中的指令无法授权 MCP 外发、直接入库、运行绘图或提交任务。 |
| 故障、预算和升级 | 覆盖模型未配置、超时、额度耗尽、中文词法召回、向量禁用或失效、旧版本数据库升级和回退。记录相同样例的召回、上下文字节、实际 Token 和耗时，未知用量如实标注。 |
| 页面与旧业务回归 | 记忆管理支持桌面、窄屏和键盘操作。核对提示浮层、下拉交互和来源跳转，既有会话、项目、知识库、技能、天文查询和工具确认继续可用。 |

开发预览沿用本机 5173。验收由用户安排，使用隔离数据库和合成数据，证据存入 `docs/test-records/v2.2.0/<类型>/<UTC时间>/`，分别记录通过、失败、跳过和依赖限制。
