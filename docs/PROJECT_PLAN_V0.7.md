## 1. 范围与现状

V0.6 提供项目、会话、命名快照、单工具重跑、比较及 ZIP 归档恢复。原有 `POST /api/v1/chat` 为单次无状态接口；Vue 前端和 FastAPI 独立运行，本地 SQLite 保存业务状态。本版在项目中新增**两个固定模板**，不让模型生成或执行任意代码、SQL、ADQL 或流程定义。

| 模板 | 输入 | 固定步骤 | 交付 |
| --- | --- | --- | --- |
| `gaia_field` | 名称或 ICRS 坐标、半径、数量、可选质量筛选、选定图种 | 名称输入时 SIMBAD 解析 → Gaia 圆锥查询及现有程序统计 → 可选绘图和单轮导出 | 带条件、来源、完整交付行、统计和图表的快照与 ZIP |
| `ads_evidence` | ADS 检索式、可选排序、单页范围 | ADS 检索 → 程序构造摘要证据表 → 项目快照与表格导出 | 原书目、原摘要、明确的缺失标记、检索条件和来源 |

V0.6 测试记录显示接入 SIMBAD 哈佛镜像后的当次联网验收 21/21 通过；这只说明当次环境与时点，不能保证本版实现时外部服务可用。详见 [V0.6 测试记录](test-records/v0.6.0/README.md)。保留已有失败记录及镜像实际来源，V0.7的验收由用户在发布前安排，本轮不运行。

本版不增加通用流程编辑器、任意代码执行、自动生成科研结论、跨项目自动关联、成员判定、消光校正、年龄/质量拟合、全文下载、RAG、队列、定时任务或多用户。可由用户显式逐步继续，但不承诺关闭进程后后台运行、硬取消或自动恢复。

## 2. 用户体验与固定流程

项目内新增“科研流程”入口：选择模板、填写明确参数、预览步骤与可能访问的数据源，再由用户启动。页面显示步骤次序、状态、已用参数、时间、来源、警告、错误、输出与恢复操作；运行不依赖模型，浏览历史不访问外网。用户可以查看和导出结果，也可保留失败记录。

### 2.1 Gaia 视场候选源

1. **输入**：名称模式接受非空 SIMBAD 名称；坐标模式接受 ICRS 赤经、赤纬（度）。两者互斥。半径和数量必填，遵守现有 Gaia 查询边界；质量筛选和距离估计仅在用户显式指定时启用。
2. **名称解析**：名称模式调用现有 SIMBAD 服务，保存实际查询名称、来源 URL、时间、主/镜像来源和响应。失败或坐标缺失时停止依赖步骤，不能使用模型记忆或预设坐标。坐标模式跳过解析并记录用户直接输入，不伪造 SIMBAD 来源。
3. **查询与统计**：使用实际坐标调用现有 Gaia DR3 服务，保留实际 ADQL、筛选、参考历元、完整数据和既有程序统计。SIMBAD 坐标仅按原坐标直接用于查询，明确未做自行传播。
4. **输出**：形成与 V0.4 导出兼容的结构化响应及项目命名快照；用户可选择 `proper_motion`、`parallax_histogram`、`observed_cmd`，最多三种，调用既有导出器。绘图数据不足、失败或包超限应显示原因，不能影响已有查询快照。

圆锥结果只是位置候选源，不代表星团成员；程序统计仅描述返回行。未知总命中数、筛选、截断及溢出须保留。距离仅按现有可选近似规则计算；负视差与零视差保留，观测颜色—星等图使用视星等，不据此断言年龄或质量。

### 2.2 ADS 摘要证据表

1. **输入**：要求用户确认实际 ADS 检索式、排序、年份条件（如有）及单页参数，重新使用 `LiteratureQuery` 约束；不把中文主题自动翻译、扩大年份或改写查询后静默执行。主题辅助编写可以在界面展示建议，但用户确认的实际式子才可执行。
2. **检索**：调用现有 ADS 服务，记录检索式、`database:astronomy`、排序、页码、`total_found`、返回篇数、UTC 时间和来源；保留完整作者、标题、摘要、DOI、bibcode、出版信息和被引数。
3. **证据表**：由程序逐篇生成固定列：bibcode、标题、作者、年份、期刊、DOI、原始摘要、摘要状态、来源链接和查询时间；缺失值明确标注。按实际返回顺序生成，不推断方法或结论，不将摘要描述为全文。
4. **输出**：保存原 ADS 结果与命名快照；证据表可下载 UTF-8 BOM CSV，处理危险文本和长字段，保留原始值于 JSON。无匹配返回空表及明确状态；ADS 失败保留错误，不产生虚假条目。

首版不调用模型生成摘要或中文翻译。证据表是书目与已返回摘要的整理，不宣称系统性综述或文献穷尽；任意论文内容均只视为不可信数据。

## 3. 实体与来源

| 实体 | 需要持久化的信息 |
| --- | --- |
| `WorkflowRun` | UUID、所属项目、模板 ID 与版本、已验证参数、创建/更新时间、整体状态、当前步骤、运行修订号、执行环境与来源标记 |
| `WorkflowStep` | 固定步骤 ID 与版本、执行序号、状态、精确输入、依赖输出引用与摘要、开始/结束 UTC 时间、耗时、输出摘要、错误和警告 |
| `StepAttempt` | 步骤每次执行的 UUID、幂等键、起止时间、状态、服务端实际参数/数据源、输出及安全错误 |
| 输出 | 完整结果或快照引用、确定性计算输入摘要、输出哈希、模板与程序版本；用户下载文件的清单 |

记录步骤、查询和程序输出之间的关系。保存完整响应，不用模型的十行裁剪视图代替交付数据。状态区分 `pending`、`running`、`succeeded`、`failed`、`skipped`、`interrupted`；`skipped` 明确原因。运行状态按步骤聚合，查询的 `success / not_found / error` 和导出的 `success / partial` 单独记录，不能用“流程完成”掩盖查询失败或跳图。

模板 ID 与模板版本不可变，参数规范化后保存原值与实际执行值。后续代码升级不能悄悄修改已有记录；历史中保留旧版本信息，而非宣称可以在新版中字节级重现。

## 4. 执行与中断恢复

首版使用同步有界请求，由用户显式启动或继续；不引入后台工作队列。每次请求按固定顺序执行到完成或失败，模型/数据库调用期间不持有 SQLite 写事务。每步先在短事务中保留 `running` 和幂等键，执行后以事务保存结果及终态，成功输出在下游执行前已持久化。

同一运行最多一个执行请求，所有外部查询与 V0.6 共用现有执行槽和服务超时；满额直接返回忙并允许用户稍后重试。提交使用请求 UUID 和预期运行修订号：同键同请求返回原操作状态，异体冲突为 409，不触发额外调用。用户关闭页面不代表远端请求已取消；重连通过 GET 读取状态。

服务启动时将遗留 `running` 尝试标记 `interrupted`。中断时远端请求可能已经执行但本地尚未保存结果，**不能保证外部调用恰好一次**。页面说明此不确定性，用户确认后可创建新尝试；只有持久化的成功步骤在校验通过时可复用，不自动重新运行或收取模型费用。

继续前比较模板版本、规范化参数、上游输出摘要、实际数据源、软件版本及快照完整性；按步骤声明自身依赖。全部吻合且成功输出仍存在才可复用。任何不匹配、文件缺失或旧模板不支持时显示失效原因，禁止静默复用；用户可创建新的流程运行并从头执行。失败或中断步骤产生新 attempt，保留所有旧错误和时间。流程输入创建后不可更改，改参数通过新建运行实现，避免历史被重写。

V0.6 项目/快照删除、移动操作必须检查流程引用：被运行引用的快照禁止删除，直到用户显式删除关联运行；删除项目时明确列出流程及输出，按事务处理，已有 V0.6 会话保留语义不变。运行中拒绝删除或迁移相关实体。

## 5. 接口与交互契约（实现代码已写入，待验收）

以下新增路径归于现有 `/api/v1`，保持旧聊天、项目、归档和导出接口兼容，UUID、请求类型和未知字段严格校验。错误继续使用现有安全 `ErrorResponse`。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/v1/workflow-templates` | 返回两个模板、版本、输入约束和固定步骤，不访问外部服务 |
| `POST /api/v1/projects/{project_id}/workflows` | 根据模板与显式参数创建运行，201；创建不启动查询 |
| `GET /api/v1/projects/{project_id}/workflows` | 列出项目内运行和状态 |
| `GET /api/v1/projects/{project_id}/workflows/{run_id}` | 返回参数、步骤、attempt、引用及来源；支持刷新恢复 |
| `POST /api/v1/projects/{project_id}/workflows/{run_id}/execute` | 用户明确执行或继续，传 `client_request_id` 与 `expected_revision` |
| `GET /api/v1/projects/{project_id}/workflows/{run_id}/outputs/{output_id}` | 读取已登记结果或下载文件，禁止客户端提供任意路径 |
| `DELETE /api/v1/projects/{project_id}/workflows/{run_id}` | 用户确认后删除运行记录及其专属引用；不删除独立命名快照 |

执行请求在同步处理完成时返回 200 及最终状态；重复请求遇到进行中返回 202 和同一运行 ID，可通过 GET 查看。访问不存在或错误归属为 404；幂等冲突、修订过期、运行中或引用被占用为 409；输入和依赖无效为 422；请求过大为 413；外部服务或执行槽忙采用既有错误语义。失败步骤保存可读状态，不因为 HTTP 200 就宣称科研查询成功。

页面提供模板参数预览、实际查询、逐步结果、跳过/失败原因、来源、输出下载、继续与新建运行。导入或历史结果标明来源可信边界；流程不能自动打开外部链接或执行外部文本。

## 6. 配额、归档和兼容

延续 V0.6 单用户、本机、单 worker 和 SQLite 事务边界。当前代码限制每项目最多 50 次流程运行、每步最多 5 次尝试、每运行最多 20 次执行请求、单流程记录及单文件最多16 MiB，超过时明确拒绝；每个模板最多 4 步。流程数据、快照与执行预留计入现有全库 256 MiB 业务预算。现有项目/会话/快照及每项包体上限不因本版自动放宽。流程输出若无法在现有导出 2 MiB 请求和 ZIP 边界内完整生成，则说明失败原因，不裁剪原查询。

项目归档需要扩展格式以保存运行、步骤、attempt、参数、来源和输出关联，且恢复后可查看与导出。定义归档 schema `2`：同时保留 V0.6 schema `1` 导入；schema `1` 导入后项目不含流程。V0.7 导出 schema `2`，V0.6 对未知格式应拒绝，不能承诺旧版读取新版包。只有经过明确兼容检查的无流程项目可提供用户显式选择的 schema `1` 导出；不得丢弃已有流程伪装为完整备份。

schema `2` 固定五成员：`manifest.json`、`project.json`、`conversations.json`、`snapshots.json`、`workflows.json`。最后一项保存运行、尝试、操作、引用与base64编码的持久输出；格式1仍为原四成员。实际字节/解压上限、唯一成员、路径、严格 JSON、哈希和事务导入沿用 V0.6 安全边界。导入一律创建新 ID 和独立副本，逐层重映射引用，保留原始时间与 `imported_unverified` 标记；导入不执行流程、访问数据库或调用模型。这里“数据库”指 SIMBAD / ADS / Gaia 外部服务；本地 SQLite 仍需事务写入。导入的未认证流程不能自动继续；用户可在确认参数后新建运行，得到本服务实际来源。

SQLite schema3新增流程、执行请求、持久输出与快照引用表；升级前生成 `migration-v3-<UTC时间>.sqlite3` 一致性备份。本轮未启动服务或迁移个人数据库。迁移失败事务回滚、未知高版本拒绝降级写入。既有真实格式数据库副本、V0.6 schema `1` 归档和新格式导入导出必须进行自动回归；测试不操作个人数据库。
