# AstroAgent 开发文档 V0.5：Web 界面与连续对话

**文档日期：** 2026-10-28  
**文档状态：** 已实现并完成本地验收；2026-10-29 按用户指令进入源码发布流程，完整联网仍有 SIMBAD 缺口  
**功能基线：** V0.4 发布提交 `670ffe5`：SIMBAD / ADS / Gaia 查询、程序统计及快照导出  
**开发版本：** 包与OpenAPI均为 `0.5.0`  
**技术方案：** Vue 3 + TypeScript + Vite + Vue Router + Pinia；FastAPI API；SQLite 本地业务库  
**本次目标：** 用户在本机网页中完成连续提问、核查结果、预览 Gaia 图表和下载数据包。

后续迭代统一见 [版本路线图](ROADMAP.md)。本文确定 V0.5 的实现边界；路线图中的更远期能力不能自动并入本版。

## 1. 基线、问题与目标

### 1.1 已有能力与核对边界

编写时检查了 `agent.py`、`api/chat.py`、`api/exports.py`、`schemas.py`、`export_schemas.py`、`exports.py`、`plots.py` 与现有开发/验收文档：

| 项目 | V0.4 工作区行为 | V0.5 目标 |
| --- | --- | --- |
| 查询 | `POST /api/v1/chat`，每次仅接收 `message` | 原接口保留，网页使用独立会话接口 |
| 上下文 | `AstroAgent.chat()` 每次重建消息列表 | 服务端为同一会话准备有界历史上下文 |
| 数据 | 三类完整结构化结果，模型仅见裁剪视图 | 网页读取完整响应，不从回答文本反推数据 |
| 导出 | `POST /api/v1/exports` 接收快照和显式图种，返回 ZIP | 网页提供选择、预览和下载入口 |
| 使用入口 | 接口与 `/docs` | 增加中文本机网页，继续保留 `/docs` |
| 历史 | 无跨请求会话存储 | 本地保存会话及逐轮结果，可刷新和重启恢复 |

M0已保存实际基线提交、原有规划差异及文档副本；未覆盖用户预先编写的规划。V0.5的实测记录独立保存，不把README链接或V0.4发布豁免作为本版验收证据。

[V0.4 测试记录](test-records/v0.4.0/README.md) 已记载 SIMBAD 超时、名称→Gaia 与三工具完整成功路径未通过。该记录是历史实测，不证明实施 V0.5 时仍然不可用；需要重新验证。过去对某次发布的豁免不自动适用于 V0.5。

### 1.2 必须交付

1. 独立 Vue 中文前端：会话列表、提问区、回答区、三类结果卡片、图表与导出区，通过 API 连接后端。
2. 本地单用户会话：新建、列表、读取、改名、删除；保存每轮输入、响应、来源、警告和状态。
3. 连续对话：能理解明确的“刚才的视场”“上一轮第一篇论文”等引用；歧义、历史缺失或查询失败时请求补充。
4. 查询结果核查：完整表格、单位、条件、来源时间、截断与错误；区分旧结果与本轮新查询。
5. 显式选择某轮结果和 Gaia 图种后预览 PNG，并下载与预览一致的 ZIP。
6. 旧聊天、导出、健康检查与现有失败降级行为回归；提供离线、真实 HTTP、浏览器与联网验收记录。

### 1.3 范围之外

本版定位于可信本机上的单用户工具，前后端默认仅监听 `127.0.0.1`；后端单进程、单 worker，前端作为独立工程运行和构建。暂不提供账号、跨用户隔离、公网/LAN 部署、云端同步、共享链接、移动应用、流式 token、任务队列、后台任务、硬取消、自动重试或多 Agent 编排。

不增加论文全文下载、PDF 上传、RAG、向量库、BibTeX / Zotero 写入、任意 ADQL、全星表下载、自动翻页、自定义执行代码或新物理推断。Gaia 的原有限额、科学近似和候选源边界继续适用。项目归档与多步骤科研模板安排在后续版本。

## 2. 用户流程与界面契约

### 2.1 默认页面

桌面采用左侧会话列表、中间对话、右侧结果详情；窄屏改为可切换面板。默认显示最新回答与结果摘要，完整查询条件、长摘要、ADQL 和逐项错误可展开。页面不得要求用户配置工具名、拼接 JSON 或理解会话修订号。

首屏包括输入框、发送按钮、新建会话，以及“坐标圆锥查询”“指定 DR3 编号”“ADS 文献检索”示例。示例注明是待发送的问题，不展示成已经取得的科研结果。页面启动和打开旧结果不调用模型，也不自动执行示例。

```mermaid
flowchart LR
    A[打开本机网页] --> B[新建或恢复会话]
    B --> C[提交问题或追问]
    C --> D[服务端构建有界上下文]
    D --> E[现有三工具查询与程序分析]
    E --> F[保存本轮完整结果]
    F --> G[回答与结构化结果]
    G --> H[显式选择某轮结果和图种]
    H --> I[复用导出器生成 ZIP]
    I --> J[预览 PNG 与下载同一个包]
```

### 2.2 结果展示

| 内容 | 展示规则 |
| --- | --- |
| 模型回答 | 与数据库结果分区；默认按纯文本展示，保留换行，不解释原始 HTML |
| SIMBAD | 名称、标识符、坐标/坐标系、类型、光谱、缺失值、来源与时间 |
| ADS | 实际检索式、年份、排序、本页/总命中数；逐篇标题、作者、DOI、摘要及来源；总结注明“根据摘要” |
| Gaia | DR3、表名、ICRS 中心/半径或精确编号、质量筛选、单位、参考历元、完整交付行与程序统计 |
| 编号/空值 | `source_id` 始终是字符串；缺失值显示“未提供”，不能显示为零 |
| 状态 | 同时显示本轮 `success/partial/error` 和各工具 `success/not_found/error`；无匹配不能标成网络故障 |
| 截断 | 显示交付数量、`truncated`、`archive_overflow`；未知总数保持未知，不以网页分页推算总命中 |
| 历史 | 标明轮次、查询 UTC 时间及“历史结果”；浏览器可另显示北京时间，但不得改写原始 UTC |

表格分页或折叠只改变显示，不能丢掉 API 完整行。网页不重算距离、样本统计、直方图或颜色，避免形成第二套科学计算逻辑。来源链接只开放经验证的 HTTP(S) 地址；以纯文本呈现其他地址。

### 2.3 交互状态与失败

- 发送后显示“正在处理”，禁止同一会话重复发送；未实现工具进度事件前，不显示虚构的工具运行步骤或百分比。
- 数据库超时、模型失败、部分成功、输入错误和本地存储失败分别提示；`ErrorInfo.code` 可在详情中查看，主界面用可理解的中文。
- 断开浏览器请求只表示客户端停止等待，不承诺远端工具或模型已经取消。刷新后可读取原请求状态；不自动重新执行。
- 缺少模型密钥时仍可打开网页、读取历史、预览/导出已保存结果；提示在服务端配置，不在网页输入或保存密钥。
- 删除会话前确认影响范围；删除操作不删除用户已下载到其他目录的文件。运行中的会话拒绝删除或改名并提示稍后重试。

## 3. 架构与本地存储

### 3.1 技术选择

采用前后端分离，在同一仓库新增 `frontend/` 独立工程。前端使用 Vue 3 单文件组件、Composition API 与 `<script setup lang="ts">`，TypeScript 定义接口和界面类型，Vite 负责开发与构建，Vue Router 管理页面与会话路由，Pinia 保存跨组件交互状态。浏览器端只负责交互与展示；科研计算、上下文选择、数据验证和模型调用均由后端执行。

后端沿用 Python / FastAPI / LangChain 与同步工具执行，只提供 API、健康检查和接口文档。前端与后端分别安装依赖、启动、测试和构建；本版不把前端页面放入 Python wheel，也不要求 FastAPI 提供 SPA 页面。前端包管理统一使用 npm，提交锁文件；Node 与依赖的实际支持版本在实施 M0 核对并固定，不直接依赖浮动的 `latest` 构建。

业务数据库选用 SQLite，通过 Python 标准库接口和显式 schema 迁移实现。它服务于后端本地的会话、轮次、查询快照与上下文记录；前后端分离不要求数据库也独立成服务，浏览器只通过 API 访问数据。V0.5 不增加 PostgreSQL、Redis 或向量数据库服务。

默认数据库文件为工作目录下 `.astroagent/astroagent.sqlite3`，配置可指定服务端数据目录，必须位于后端本机磁盘；不放在多台机器同时读写的共享盘。实施时将数据目录、SQLite 主文件及伴随文件加入忽略规则；库文件、用户会话和真实凭证不进入源码归档。

选择 SQLite 的依据是当前单用户、短事务和有限并发的定位，以及无需单独管理数据库服务。SQLite 的单写者边界要求继续采用下文短事务与有界并发；网页独立运行不会改变该约束。更换数据库的条件见 3.5，不把本版选择描述为任意规模部署方案。

### 3.2 数据模型

| 实体 | 必须保存的字段与关系 |
| --- | --- |
| `Conversation` | 随机 UUID、纯文本标题、创建/更新时间、单调递增的轮次修订号 |
| `Turn` | 随机 UUID、所属会话、顺序号、`client_request_id`、用户原文、接收/完成 UTC 时间、执行状态、完整 `ChatResponse` 或安全错误 |
| `ContextRecord` | 本次实际选入的历史轮次/结果引用、遗漏原因、上下文策略版本、投递字符数；不存密钥或模型内部推理 |
| `Artifact` | 随机 UUID、所属会话/轮次、快照摘要、规范化图种、生成器版本、内存中的 ZIP 和创建/过期时间 |

`Turn` 的完整响应 JSON 与用于模型的历史视图分开保存；历史视图的裁剪不能改写完整响应。模型原始响应不得覆盖程序生成的 `results`、`literature_results`、`gaia_results` 和 `sources`。

会话与轮次写入 SQLite；生成的 ZIP/PNG 仅进入有界内存缓存，重启后消失。历史会话和图种仍在时可显式重新生成，新的导出时间/版本可能改变字节，不能声称与旧包逐字节一致。

### 3.3 事务、并发与恢复

提交轮次时，在短事务中检查修订号、请求幂等键、配额与运行锁，预留存储后记录 `running`，然后结束事务。模型、数据库请求和绘图期间不持有 SQLite 写事务。终态结果与来源在一次事务中提交；原始查询状态与轮次执行状态分开保存。

同一会话只运行一轮；进程内全局最多两轮模型任务，不排队。服务端拒绝超额请求，前端显示重试按钮，由用户显式决定是否重试。不同浏览器标签页使用修订号检测冲突，不能悄悄覆盖彼此的问题或结果。

重启时将遗留 `running` 记录改为 `interrupted`，释放预留和锁；不自动重放可能收费的请求。单进程限制要在启动文档中说明，并在不受支持的多 worker 配置下拒绝启用会话服务。

### 3.4 前后端开发、构建与对接

| 场景 | 前端 | 后端与 API |
| --- | --- | --- |
| 本机开发 | Vite 监听 `http://127.0.0.1:5173`，端口占用即失败，不悄悄换端口 | Uvicorn 监听 `http://127.0.0.1:8000`，单 worker |
| 默认 API 请求 | 统一 API 客户端使用相对地址 `/api/v1/...`；图片和下载沿用后端返回的相对地址 | Vite 将 `/api` 与 `/health` 代理到 8000，保留 API 路径及实际浏览器 Origin |
| 直接跨源联调 | 只有显式配置时才使用 `VITE_API_BASE_URL` 指定 API 所在 origin；默认为空 | 后端按明确 origin 白名单处理 CORS 与预检；不使用通配放行 |
| 构建与运行验收 | 独立生成 `frontend/dist/`，通过静态服务器提供页面及 SPA 路由回退 | 静态服务器代理 `/api`、`/health` 到 API；不得把这些路径回退为 `index.html` |

前后端分离是工程、构建和 API 边界；部署时可由反向代理提供统一访问地址，不强制使用不同域名。Vite 开发服务器只用于开发，构建产物运行验收须使用独立静态服务；具体本机运行命令和代理配置在实施时一起交付，不能只交付一个需要自行猜测服务地址的 `dist`。

前端 API 模块集中处理 JSON、安全错误、二进制下载、请求幂等键及状态恢复，不在每个组件重复拼地址。浏览器状态不是权威数据库；刷新后以服务端记录恢复，Pinia 不保存密钥，不用 `localStorage` 代替完整会话库。

使用 `fetch` 等浏览器请求能力对接 API；模型密钥、ADS token、数据库路径和代理目标不由用户消息控制。`VITE_` 环境变量只用于可公开的构建配置，不能包含凭证。后端 `.env` 与前端环境文件分开，避免把服务端秘密打进 JavaScript。

前端类型与后端 OpenAPI 保持一致；UUID、严格编号字符串、可空字段和枚举需有契约检查。TypeScript 类型不能替代后端运行时校验。路由切换、请求断开或组件卸载不等于后端执行取消。

### 3.5 数据库演进与迁移边界

V0.5 的关系记录采用普通表、主键/外键、唯一约束和索引，完整 `ChatResponse` 以严格 JSON 文本保存。`source_id` 继续作为字符串，UTC 时间采用统一序列化格式。持久化访问集中于仓储接口，API 和 Agent 不直接散落 SQLite 专有 SQL，也不以全文 JSON 检索代替明确的关系字段。

后续需要多用户、多个后端实例或持续并发写入时，主业务库目标选 PostgreSQL，并在对应版本规划迁移；若这些需求提前出现，提前评估，不机械等到 V2.0。迁移包括新适配器、schema/类型转换、数据导入、完整性核对、备份/回滚和实际并发测试，不能承诺修改连接字符串即可无缝完成。

论文文件、ZIP 和 PNG 不因增加数据库就全部作为大二进制写入业务表；V0.5 仍按产物缓存契约处理。V0.8 知识库索引单独评估，SQLite 业务库的选择不预先决定向量存储方案。

## 4. 新增接口契约（已实现）

### 4.1 路由与兼容性

| 方法与路径 | 语义 |
| --- | --- |
| 前端 `GET /`、会话页面及资源路径 | 由独立前端服务提供；属于网页路由，不新增为 FastAPI 页面接口 |
| `POST /api/v1/conversations` | 新建会话，201；可选标题，省略为“新会话” |
| `GET /api/v1/conversations` | 按更新时间倒序列出会话元数据，不夹带全部结果 |
| `GET /api/v1/conversations/{id}` | 元数据及轮次摘要；不触发外部请求 |
| `PATCH /api/v1/conversations/{id}` | 修改纯文本标题，200 |
| `DELETE /api/v1/conversations/{id}` | 删除该会话的轮次与产物缓存，204 |
| `POST /api/v1/conversations/{id}/turns` | 提交一轮并等待完成；正常返回 200，重复的运行中请求返回 202 |
| `GET /api/v1/conversations/{id}/turns/{turn_id}` | 读取指定轮次及完整响应，支持刷新恢复 |
| `POST /api/v1/conversations/{id}/turns/{turn_id}/artifacts` | 显式选择图种，生成并缓存一个 ZIP，201 |
| `GET /api/v1/artifacts/{artifact_id}/manifest` | 获取该包的清单，200 |
| `GET /api/v1/artifacts/{artifact_id}/figures/{figure_id}` | 获取清单登记的 PNG，200 |
| `GET /api/v1/artifacts/{artifact_id}/download` | 下载该次生成的原始 ZIP，200 |

原 `POST /api/v1/chat` 仍只接收 `message`，仍无状态，不自动创建会话；原 `ChatResponse` 不增加必填字段。原 `POST /api/v1/exports` 的输入结构、资源上限、客户端来源标记和下载行为保持兼容；健康检查和 `/docs` 保留。

### 4.2 请求与响应

新建/改名标题为去除两端空白后 1–80 字符；新请求逐层拒绝未知字段。UUID、严格整数、枚举和空白输入由服务端校验。

轮次提交示例仅说明输入结构，ID 由客户端实际生成：

```json
{
  "message": "把刚才视场的 RUWE 上限改为 1.4，其他条件保持不变，重新查询。",
  "client_request_id": "31a9d6ec-fd5e-460d-b808-bd27580f635a",
  "expected_revision": 3
}
```

`message` 沿用 1–4000 字符限制。`expected_revision` 是非负严格整数，用于检查提交所依据的会话版本；服务端每接受一次新轮次增加一次修订号，失败或中断也占用轮次，不重复使用编号。

轮次响应外层含 `conversation_id`、`turn_id`、`revision`、`execution_status`、时间、`context`、可空 `response`、可空 `error`。`execution_status` 为 `running/completed/failed/interrupted`：`completed` 表示获得了可交付 `ChatResponse`，其内部仍可能 `partial/error`；无可交付响应时为 `failed`。轮次查询通过 HTTP 200 描述已经记录的执行状态，不把业务失败转成成功查询。

`context` 至少列出 `included_turn_ids`、`omitted_turn_ids`、`referenced_results`、策略版本和裁剪警告。结果引用使用 `{turn_id, family, result_index}`；不能把不同轮次的第零次 Gaia 查询当成同一数据集。

产物请求只接受 `plots`，语义沿用 V0.4 `PlotSpec`，最多三项；`[]` 表示仅数据包。快照从指定轮次读取，客户端不能替换本接口的快照。201 响应提供 `artifact_id`、快照摘要、`export_status`、过期时间、清单/图片/下载的相对 URL；图像条目以服务端生成的 `figure_id` 标识，不能接收任意文件路径。

### 4.3 幂等、错误与读取恢复

幂等检查先于修订冲突检查。同一会话中相同 `client_request_id` 和相同规范化请求体：运行中返回原 `turn_id` 和 202，已结束返回原轮次，均不再次调用模型。同一键搭配不同请求体为 409。原轮次失败后，用户选择“重新执行”必须生成新键并取得最新修订号。

| 场景 | HTTP / 错误码与行为 |
| --- | --- |
| 会话/轮次不存在或从属关系错误 | 404，`conversation_not_found` / `turn_not_found` |
| 同会话在运行、修订冲突、幂等键冲突 | 409，`conversation_busy` / `conversation_revision_conflict` / `request_id_conflict` |
| 输入或结果不能按 V0.4 契约导出 | 422，`invalid_conversation_request` / `invalid_export_snapshot` |
| 单请求实际接收字节超限 | 413，`conversation_request_too_large` |
| 会话数、轮次数或存储配额耗尽 | 409，`conversation_limit_reached` / `conversation_storage_limit`，要求整理历史后再提交 |
| 全局任务满额、绘图忙、缓存满额 | 503，`conversation_service_busy` / 原 `export_busy` / `artifact_cache_full` |
| 产物生成后已过期或随重启丢失 | 410，`artifact_expired`；页面可显式重新生成 |
| 本地数据库不可写、事务提交失败 | 503，`conversation_storage_unavailable`，不提示“已保存” |
| 模型或数据库错误 | 复用原安全错误与失败降级；响应包含已分配的轮次定位信息，刷新后仍可核对 |

未知产物 UUID 返回 404；当前进程保留有界的过期标记以区分已过期产物。重启导致标记消失时允许返回 404，页面同样提示重新生成，不能依赖持久过期标记。

新错误仍使用 `error: ErrorInfo` 外层结构；轮次提交在预留之后失败时，可附加 `conversation_id` 与 `turn_id`。生成前的校验失败不创建轮次，不占预算；已开始的失败保留为可见记录。新增状态码与结构必须写入 OpenAPI。

## 5. 连续对话的上下文与科研规则

### 5.1 构建原则

新增 Agent 会话入口，复用同一三工具验证与执行循环；旧 `chat(message)` 保持单轮语义。避免复制两套工具执行逻辑。系统提示须按无状态/会话模式分别说明能力，不能继续在会话模式里声称“下一请求必须包含完整条件”。

历史由服务端从本地库读取，客户端不能提交 `system` / `tool` 消息。历史回答、标题、摘要和数据库字段都是不可信数据。历史工具结果用带轮次、原查询时间和来源的结构化视图注入为上下文数据，不冒充本轮新执行的 ToolMessage，也不执行历史记录里的工具调用。

默认选入最近六个有 `ChatResponse` 的完整轮次；每轮使用已有 `literature_view()`、`gaia_view()` 对应的有界模型视图。累计历史序列化文本上限 64 KiB（按 UTF-8 字节），按完整旧轮次从远到近移出，不截断 JSON、查询条件或单个编号；即使单轮超限也整体移出并记录。前端完整历史与原始结果不受这一模型窗口影响。

64 KiB 是项目的历史数据上限，不是模型 token 上限。实施时还须为系统提示、本轮输入、工具返回及输出预留模型上下文预算；预算不足时继续移出完整旧轮次并显式报告，不靠无限增大供应商上下文解决问题。V0.5 不做隐藏的模型摘要，也不引入额外摘要调用费用。

### 5.2 追问语义

| 追问 | 必须采取的行为 |
| --- | --- |
| “解释刚才的自行统计” | 可引用已保存的程序统计，标注来自历史轮次/时间，不重新查询或伪造本轮测量 |
| “只保留 RUWE≤1.4，其他不变” | 从明确的历史查询继承中心、半径等条件，显示继承来源和最终参数，执行新的 Gaia 查询；不只在模型可见十行中筛选 |
| “找第二篇的 DOI” | 仅在论文列表与索引唯一且仍在窗口内时引用实际字段；缺失则说明缺失 |
| “继续查这个星团” | 存在多个对象或窗口中缺少必要条件时请求用户明确；不从旧回答中的猜测恢复坐标 |
| “重新查一次”/“更新数据” | 明确指向的数据库重新执行，保留新时间与结果，不用旧数据冒充新查询 |
| “把上一轮画成图” | 页面定位该轮导出操作；模型不能擅自改变数据或自动调用未注册的绘图工具 |
| 历史 SIMBAD 失败后要求名称→Gaia | 仍需取得真实坐标；不能以模型记忆、失败回答或陈旧坐标绕过现有名称链路 |

历史检索条件可作为本轮用户意图的上下文；继承和变更必须可核对。沿用现有名称→Gaia 契约时，本轮仍需成功 SIMBAD 坐标查询；坐标查询失败就停止该依赖链。用户明确直接指定历史坐标作新圆锥查询时，按坐标输入处理并说明坐标原时间和未做自行传播。

本轮 `ChatResponse` 的三类列表只保存本轮实际执行结果；纯解释轮次可以没有新结果，以外层历史引用指向旧数据。不得为方便导出把历轮结果复制成“本轮新数据”。用户要导出旧数据时，显式选取原轮次。

三工具轮数和调用上限仍按每次新提交计算，历史重放、浏览、画图和下载不增加模型调用。重试产生的新轮次单独计预算并明确可能产生模型用量。

### 5.3 科学边界

继续保留 Gaia DR3 发布版、单位、参考历元、最大交付行数、质量条件、未知总数、截断及服务端溢出。距离近似仍仅在显式请求且符合既有条件时产生；视差保留负值/零值，自行不再乘赤纬余弦。

网页分页、用户筛选显示、追问和历史恢复不能升级样本的科学意义：位置候选源不是成员；观测颜色—星等图不是已校正绝对星等 HR 图；视差直方图不是距离分布；摘要总结不是阅读全文。

## 6. 图表预览与下载一致性

服务端从指定轮次取完整快照，构造现有 `ExportRequest`，调用同一 `build_package()`。预览服务只读取该 ZIP 的清单与 PNG；不另外计算图表，不从模型视图取前十行，不让浏览器解压任意上传文件。

内部调用也必须重新验证 `ExportRequest`，并检查完整序列化请求体的 2 MiB 限制，不能因绕过原 HTTP 中间件而放宽旧导出边界。缓存生成与删除会话之间需原子检查从属关系，删除后不能重新挂入已删除会话的产物。

清单中的相对路径只用于在内存中定位白名单成员，不作为文件系统路径。对清单登记的 PNG 核对大小与 SHA-256 后，通过 `image/png`、`nosniff`、`Cache-Control: no-store` 返回；ZIP 下载返回本次缓存原字节。图片缺失、图被跳过或哈希校验失败均不得展示占位图片冒充成功。

同一产物的预览与下载必须对应相同快照、图种和生成器版本；用户改选图种或轮次后使当前产物失效，重新点击生成。缓存键包含完整规范化快照摘要、图种和生成器版本，不仅使用前端索引。不同轮次或不同会话不复用身份标识。

V0.4 的 `provenance="client_supplied_snapshot"` 和 `source_authenticity_verified=false` 继续保留，不因快照来自本地历史就改成认证观测。会话只提供本地记录关系，哈希只证明包内完整性。

快照若超过原导出接口上限或与当前导出契约不兼容，网页明确禁用该项导出并解释原因；不静默删除字段或裁剪样本来通过验证。查询的完成状态、导出的状态和图表跳过原因独立展示。

## 7. 配置、资源与访问边界

下列为 V0.5 的设计默认值，实施时验证边界并写入配置模型；固定上限不得由浏览器提高。

| 项目 | 设计值 / 行为 |
| --- | --- |
| `ASTROAGENT_DATA_DIR` | 默认工作目录下 `.astroagent`，仅服务端配置；启动时检查可写性 |
| `ASTROAGENT_ALLOWED_ORIGINS` | 服务端显式 origin 列表；本机默认包含 `http://127.0.0.1:5173`、`http://localhost:5173` 以及 8000 端口的两种本机接口文档 origin；同时用于写请求检查与按需 CORS |
| `VITE_API_BASE_URL` | 前端公开构建配置，默认空字符串；非空时为 API origin，不含 `/api/v1` 后缀，不含任何密钥 |
| Vite 开发端口 | 5173，`host=127.0.0.1`、`strictPort=true`；代理目标默认 `http://127.0.0.1:8000` |
| 会话/轮次 | 最多 20 个会话、每会话 40 次已接受轮次（含失败/中断）；不自动删除历史 |
| 会话请求体 | 最多 32 KiB 实际接收字节，覆盖分块；仅支持未压缩 JSON |
| 持久内容 | 单轮完整序列化记录最多 16 MiB；全库业务内容预算 256 MiB，新轮次先预留 16 MiB |
| 上下文 | 最近六个完整可交付轮次，历史序列化视图最多 64 KiB；显示被移出数量 |
| 执行 | 同会话一轮、全局两轮；非阻塞占用，满额拒绝，不增加任务队列 |
| 单包/绘图 | 沿用 V0.4：最多三张图、完整导出请求体 2 MiB、未压缩文件总量与 ZIP 各 16 MiB，以及原绘图互斥 |
| 产物缓存 | 总 ZIP 字节最多 64 MiB、最多八个产物、15 分钟有效；过期释放，满额拒绝新生成 |
| 过期标记 | 当前进程最多保留最近 128 个 ID；只用于区分 404/410，不保存旧包 |

256 MiB 是序列化业务内容及预留预算，不是 SQLite 文件的物理大小保证。索引、日志和空闲页另占空间；不在每次删除时自动执行压缩维护。完成结果超出单轮预留上限时，记录明确的 `turn_result_too_large` 失败，不能截断后标为完整交付；失败记录使用固定的小型预留。

数据库不可写时，独立前端、后端健康检查与旧无状态接口应仍可启动，会话接口明确返回存储不可用；首次迁移失败不得悄悄新建空库覆盖历史。迁移前创建一致性备份，校验 schema 版本，失败回滚；未知的更高版本数据库拒绝降级写入。不能把运行中复制一个 SQLite 主文件直接当作完成备份的证据。

开发默认使用 Vite 代理，后端仍需按白名单验证实际浏览器 Origin；反向代理不会自动授予来源信任。直接跨源模式的 CORS 只允许已配置 origin、必需方法与请求头；实际方法/写入校验独立于 CORS 预检，不能以浏览器限制代替服务端检查。后端 Host 白名单和 Vite allowedHosts 采用明确本机范围，不设置任意主机放行；命令行无 Origin 调用仍满足本机 Host 与 JSON 限制。这些约束不等价于账号认证，无法防御同机已获权限的程序。

数据库路径、密钥与异常堆栈不传浏览器；请求日志不记录密钥、Authorization、完整会话或论文摘要。页面不加载外部脚本，不解释数据库文本中的代码。无登录版本不提供“改成 0.0.0.0 即可安全部署”的说明。

### 9.3 显式联网验收

`--live` 计划开启真实模型与数据库，产生模型用量，不与默认测试混用。至少执行：Gaia 圆锥→修改质量条件追问→核对实际参数与新来源；ADS 查询→引用具体论文；精确 DR3 查询→距离解释；SIMBAD 名称→Gaia；三工具部分失败与正常成功路径；由相应真实轮次完成预览和导出。

缺凭证或外部失败按实际失败记录，不能默认为跳过。SIMBAD 失败时保留 Gaia / ADS 成功数据和失败状态；既检查失败降级，也单独保留尚未通过的完整成功路径。旧版某次发布豁免不自动满足本版验收。
