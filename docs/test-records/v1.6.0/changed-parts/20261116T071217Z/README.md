## 发现并修复的问题

1. **头像源像素上限未严格生效。** Pillow 原先只在超过阈值时警告，仍会处理部分超出预设像素预算的压缩图片。改为解码前检查总像素，不再临时改写 Pillow 全局像素上限，避免并发请求互相影响。
2. **快速更新头像可能仍显示旧图。** 原版本参数只精确到秒，同一秒内的更新可能使用相同地址。改为微秒级版本参数，并核对会话信息和上传返回值一致。
3. **使用统计误计及模型归类。** 排除等待中、执行中和已跳过的任务；资产/任务总数仍保留真实记录数。绘图模型优先读取真实请求中的 `model_id`，保留旧 `model` 字段兼容。明确这是已保存的模型请求记录，不是服务商计费次数。
4. **部分 Token 数据显示成零。** 已知输出但未知输入时，输入改为“—”，不伪造为零；总量仅汇总已记录的部分。
5. **窄屏个人资料被裁切。** 截图发现用户名和登录时间在 320px 下超出内部阅读区，虽然根页面没有横向溢出。修正个人资料网格和名称、邮箱、时间的宽度/换行限制，并增加内部元素边界检查。原图保留在 `screenshots-initial/`，修复后见 `screenshots-final/`。

首轮 `profile-baseline.xml` 保留像素限制及头像版本两项失败；`profile-postgres-initial/tests.xml` 保留统计预期 4、实际 8 的失败。修复后相同边界与数据断言通过，没有降低阈值。

## 关键覆盖

- PNG、JPEG、WEBP、GIF 转为 256px PNG；附加非图片尾部不保留；EXIF 隐私内容清理；空、损坏、SVG、BMP、超过 5 MiB、超过预设总像素均按边界拒绝。
- 真实鉴权与 CSRF：匿名不能查看资料或头像；上传缺少 CSRF 被拒绝。坏图片不覆盖已存头像；替换、读取与移除正常，头像响应不可跨账号复用。
- 两个虚构账号分别访问头像和统计，不能借用对方头像 URL 读取对方图片，也不能删除对方头像。统计仅在本人业务命名空间汇总。
- 独立旧身份库移除新增头像列/表后执行兼容检查，账号身份、邮箱保留，新增头像存储可用；此演练不在日常库执行。
- 冻结统计样本含完成、失败、执行中、等待和跳过状态：模型请求记录应为 4，已知 Token 为 20，科研查询和资产数按样本逐项核对。另一账号统计为零且不包含前一账号模型名。
- 个人资料中的内联用户名编辑支持取消及提交，并同步侧栏；头像变更、移除、上传拒绝和读取错误都有浏览器验证。
- 个人资料在 1440、1280、1024、981、980、768、390、320 CSS px 下检查阅读区内部和页面边界；切换侧栏、进入/离开资料页保留未发送的问题，不自动发送请求。相关设置、项目、来源关联、知识库、流程、查询、绘图确认及键盘/减少动态效果回归均通过。

- 初始代码规范检查中 `local_access.py` 有一处格式问题，已格式化；新增测试的一处长 SQL 也已拆行，最终 Ruff/ESLint 均通过。
- 原普通账号设置标题已改变，测试更新为当前“账户安全与登录”。设置页已移除单独的状态刷新按钮，旧测试失败；改为进入概览后使用浏览器刷新，保留“失败后清除旧就绪状态”的断言。两浏览器复验通过。
- 初次类型契约检查的系统临时目录含 `#`，生成工具将路径误作 URL 片段，报 EISDIR。改用仓库内独立临时目录后 `--check` 通过，未手工修改生成类型或跳过契约校验。
- 一个初版测试未给 5 MiB 合成参数指定短 ID，导致 Windows 环境变量长度错误和过大的日志。改为短测试 ID 后正常执行；压缩保留原始失败，见 `profile-initial.txt.gz`、`profile-initial.xml.gz`。
- **首轮上述异常诊断将继承的 ADS 环境凭据带入日志。现存普通日志和压缩副本已脱敏，并检查私有配置中的实际值；工具会话历史无法通过修改仓库文件撤回。** 后续测试显式清空继承凭据，数据库验收脚本也清空模型/身份/SMTP 凭据后再交给虚构账号夹具配置。未轮换、覆盖真实密钥；记录不包含明文凭据。详见 `log-redaction.json` 与 `privacy-scan.json`。
