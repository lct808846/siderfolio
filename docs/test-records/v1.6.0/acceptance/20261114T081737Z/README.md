## 失败及修复均保留

- 初次Ruff发现149项问题；格式、导入及余下长行已修正，最终检查通过。
- 原业务测试依赖旧启动方式，先因入口不存在旧仓储属性失败，继而因测试依赖未标注Request和公开Swagger约定变更失败。旧合约夹具已显式独立；V1.6生产认证不设测试开关、不提供匿名回退。公开文档关闭的断言按新约定更新。
- 前端旧API单元夹具未准备CSRF且把Headers当普通对象，修正夹具后保留原幂等、二进制类型和不重试断言，并额外检查CSRF头。
- 独立QA端口5174先被硬编码5173的容器可信origin拒绝，现改为只信任经AuthSettings校验的精确origin。首次容器初始化失败日志保留，复验成功。
- 浏览器首次用了被日常实例占用的5173，未重用或停止其来满足测试，改用独立5273/8101；真实身份栈固定5174。绘图合成测试过宽的路由拦截误吞了身份请求；后台审计测试错误要求重复事件只有一行，分别修正测试后复验通过。
- 首次真实科研脚本错误读取SIMBAD字段，且只判断结果数组非空，没有检查供应商成功状态。原始记录保留，不作为最终通过依据。复核已保存轮次发现SIMBAD/Gaia成功、ADS为 `ads_not_configured`；无需重发SIMBAD/Gaia。为V1.6私密配置补入项目已有的ADS凭据后重新请求，`ads-configured-retry.json`确认实际成功并返回1篇文献。受保护的V1.5设置未覆盖。

## 使用、数据与资源边界

当前本机入口为 `http://127.0.0.1:5173`，新账号从 `/register` 验证邮箱并自行设密。没有默认用户、默认密码、首用户自动管理员或个人管理员账号；首次管理员仍按本机受控维护流程安排。个人数据清空按后续授权执行，不能称为数据迁移成功。

私有环境、QQ授权码、认证密钥和旧库备份都在 `.astroagent` 下，不进入源码。DPAPI配置备份绑定当前Windows用户，不能视作跨机器可恢复备份。独立QA容器及其自有数据库/执行器卷结束后移除，旧V1.5服务停止；共享Ollama模型卷、原始GGUF、嵌入模型与个人V1.6卷保留。最终占用见 `final-resources.txt` 和 `final-disk.json`；Docker镜像共享层不能简单相加。

网页、后端和不可信绘图任务没有Docker Socket。内部受信执行器仍控制同一Docker守护进程，残余风险未因增加登录而消失。绘图继续受网络关闭、非root、只读根、内存/CPU/PID上限及超时约束。本轮实际两引擎执行和账号状态提交边界通过；不声称覆盖所有恶意程序或隔离漏洞。

本次部署采用显式允许的本机HTTP，HTTPS Cookie属性有自动检查，但没有部署公网TLS反代、跨机器、GPU或强对抗多人生产环境。旧数据认领/合并及其全部故障分支不属于本次“清空后使用新库”路径。现有开发版的这些检查不能等同于全面安全认证或V1.6稳定版发布。

清理后快照：六个个人容器空闲内存合计约468 MiB，不含Docker Desktop/WSL宿主开销；D盘空闲约49.61 GiB。模型推理和索引时用量会增加。Docker全局镜像16.35 GB、卷2.611 GB、构建缓存9.244 GB为当时逻辑统计，含共享层和旧镜像，不能相加作为本版独占磁盘；Qwen既有模型身份匹配，模型文件2497293689字节。
