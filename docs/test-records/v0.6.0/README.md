## 已验证的功能与边界

- schema1→2前生成SQLite一致性备份；用含完整100行响应的V0.5格式合成库验证原轮次JSON保持、迁移失败回滚及恢复。未升级、复制或归档个人实际数据库。
- 项目与会话关联、移动、改名/删除、乐观修订、全库预算和各自配额通过。原会话和轮次保留；快照完整响应及其SHA-256不因改名、重跑或删除来源而改变。活动引用可置空，原始编号保留。
- 三种工具的单条直接重跑均在离线受控服务中验证：参数来自完整快照，执行前确认；显式断言不构造模型Agent。旧新快照独立，执行状态与科研响应状态分开，原请求键先于修订检查，同键异体409、运行中202；共享最多两个执行槽，失败仍有定位记录。
- 比较不触网或调用模型，重复输入结构相同。保存条件、来源、计数、状态和软件版本，缺失/null/未知不转成零；只显式按精确字符串source_id或bibcode比较交付编号，不把样本变化解释成总体或成员变化。
- 固定四成员项目ZIP逐文件哈希核对，通过完整校验后才在单事务导入另一份空库，新UUID映射和重跑活动关系可核对。坏包、重复/非法成员、符号链接、未知版本/字段、非有限/重复JSON、坏引用、写入失败和超限均拒绝，未留下部分数据。实际压缩膨胀与导入/归档忙时拒绝另有测试。
- 导入及再次保存导入轮次始终标 `imported_unverified`；删除原项目后来源等级仍保留。哈希只能验证包内一致性。恢复的完整快照可重新生成单轮预览/ZIP，预览PNG与下载包内容一致。
- HTTP实际杀停运行中的合成重跑、重启服务，确认轮次和重跑均为 `interrupted`，原键读取不会重放；随后核对完成数据持久化、归档到新库、完整响应/来源/哈希、新ID和项目删除保留会话。全部临时服务先退出再清理专用库。
