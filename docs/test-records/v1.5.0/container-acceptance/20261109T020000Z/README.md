# V1.5 Docker Desktop 容器验收记录（2026-11-09）

对象为工作区开发版 `1.5.0.dev0`，基于 `62daa42`，非固定提交或发布证据。本目录名为原先选用的记录编号，并非验收实际开始时间。验收使用独立 Compose 项目 `astroagent-v15`、新建数据库卷、合成文本和文档；没有连接或迁移既有 PostgreSQL，也没有修改科研文件。合成数据及备份仍保留在该独立测试环境中，不应视为生产数据。

## 结果

- 固定基础镜像并构建、启动六项服务，复用现有绘图镜像及只读嵌入模型；现有 Qwen 权重离线导入新模型卷。最终启动命令返回成功，见 `compose-final-retry.txt`。在首次尝试中曾发现模型卷权限、Windows 换行影响数据库密码、执行器连接关闭和前端健康检查等问题，修正后复验；中间失败日志保留。
- 合成会话真实远程回答、文献上传与语义索引、确认引用后回答、Python 绘图/PNG/压缩包通过，见 `container-smoke.json`。Gnuplot 首次因模型生成的字体语法错误失败；完善生成约束后重试成功，初次错误与重试结果均保留。单次成功不保证任意模型生成脚本均正确。
- 真实绘图作业验证网络不可用、只读根文件系统、无密钥与 Docker Socket；符号链接输出被拒绝，超时任务终止。实际容器检查为用户 65532、无网络、只读根、256 MiB、进程数上限 32；另配置 CPU 上限、去除全部 capabilities、no-new-privileges、30 秒超时。见 `sandbox-live.json` 和 `desktop-http.xml`（7 项边界测试通过）。
- 独立新建数据库的凭据验证通过；对该测试库备份并在另一个全新隔离数据库恢复，记录数量、绘图输出及语义向量摘要一致；临时恢复项目已清理。仅重启该测试数据库后，应用重连且合成项目保留，见 `reconnect.json`。测试库备份位于被忽略的 `.astroagent/container-acceptance/`，不含原有科研数据。
- 本地 Qwen 实测人工建议标题、自动命名、摘要、格式整理及查询条件提取均完成；提取样本正确识别 M45 与 5 arcmin，并将坐标标为缺失。见 `local-model-title.json`、`local-auto-title.json` 和 `local-text-tasks-retry.json`。第一次文本任务运行被执行环境的本地网络权限阻止，见 `local-text-tasks.json`；随后授权连接本机端口重试成功。这是小样本功能检查，不构成全面模型质量评估。
- Chromium 与 Edge 均检查真实容器网页的桌面和 390 像素窄屏，2 项通过；前端 lint 和类型检查通过。Host/Origin 拒绝非法来源，见 `container-smoke.json`。未测试 Gaia（用户允许因网络跳过）、SIMBAD/ADS 的完整外部查询，GPU 推理、跨机器部署、所有 V1.5 功能和完整版本发布验收。

## 资源与安全限制

本机是约 15.4 GiB 内存；Qwen 加载时 Ollama 峰值约 4.41 GiB，宿主机可用内存最低观测约 436 MiB，冷启动标题约 30.59 秒，随后自动标题约 15.22 秒；实际负载可能不同。空闲时六个容器合计约 379 MiB（模型卸载后的一次快照）。Docker 总计镜像约 13.91 GB、构建缓存 5.28 GB、卷 2.548 GB，这些为全部现有 Docker 资源的逻辑统计，并非本次新增磁盘量。D 盘当时余约 26.8 GiB；复用权重仍需单独导入到模型卷，因此会占用额外空间。

网页、后端和不可信绘图作业均不挂载 Docker Socket；执行器无公开端口，仅内部连接并验证令牌、约束输入。但执行器本身必须访问同一个 Docker Desktop 守护进程：Socket 即使只读挂载，也不限制 Docker API 权限，一旦执行器或凭据被攻破，可能控制其他容器和可访问的宿主挂载；与独立虚拟机隔离不等价，不适合公网多用户或强对抗环境。前置入口容器有网络出口，但无密钥和 Socket。GPU、内核逃逸及 Docker 守护进程漏洞没有通过本次测试排除。

已删除此前下载的 Ubuntu 安装镜像；未使用或修改用户已有 VMware 虚拟机。随后根据用户要求，删除了此前为 AstroAgent 导入但未启动的独立虚拟机目录（约 1.75 GiB）；用户原有虚拟机未删除。当前环境仍为运行中的合成测试部署，开发改动尚未提交、推送或发布。
