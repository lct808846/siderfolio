# Siderfolio V2.1 开发文档｜Agent 技能与工具扩展

**日期** 2026-11-26　**目标版本** `v2.1.0`（`5873ba8`）　**实施基线** `v2.0.7`（`6694ce4`）　**状态** 本地验收已留证；云端发布校验、生产外部 MCP 联调与会后增量收尾待验收（详见 [实施说明](development/v2.1.0/IMPLEMENTATION.md)）

本版继续使用单 Agent。用户可以在对话中选择科研技能，或由 Agent 根据当前意图匹配。技能提供研究步骤和核查要求，工具负责实际查询、生成草案或执行已经授权的操作。首版交付统一工具目录、三个内置技能和一条受控的外部 MCP 接入链路。Multi-Agent 顺延，其他科研方向见[版本路线图](ROADMAP.md)。

## 2. 技能系统

### 2.1 首批技能

| 技能 | 匹配意图 | 预期交付与边界 |
| --- | --- | --- |
| 天体识别与视场查询 | 用户给出天体名或坐标，要求确认对象或查找邻近候选源 | 按需调用 SIMBAD 和 Gaia DR3。显示解析对象、坐标系、查询半径、筛选及截断。名称未解析时先澄清或使用用户确认的坐标。Gaia 结果标为候选源。 |
| 天文文献检索与整理 | 按主题、对象、年份或作者查找文献，整理结果或保存指定条目 | 调用 ADS，输出题目、年份、bibcode／DOI 及来源。分清书目、摘要与校验过的原文。用户明确要求保存时，沿用已核验结果范围和现有文献库幂等写入。项目 RAG 片段沿用现有选择及发送确认。 |
| 科研绘图与 N 体实验准备 | 用已有结果出图，或准备可执行的小规模数值实验 | 绘图保留数据引用、坐标和单位。N 体草案列出粒子参数、单位、引擎、采样和物理假设。孤立点质量模型沿用现有 2–128 粒子范围。运行脚本、提交模拟分别走原有确认和隔离执行入口，运行完成后从任务记录查看轨迹与能量诊断。 |

### 2.2 格式、选择与版本

- 技能以 `SKILL.md` 管理。首版解析 YAML 头部的 `name`、`description` 和可选元数据，正文为 Markdown 研究步骤。服务端登记稳定 ID、版本、内容摘要、允许使用的工具 ID 及匹配意图，工具授权以服务端目录为准。首版内置技能随仓库发版，支持维护者在仓库新增和修订，浏览器提供选择和个人启停。[Agent Skills 格式规范](https://agentskills.io/specification)
- 选择顺序为本轮用户显式选择、项目上下文与当前意图的自动匹配、普通对话。清晰匹配时每轮最多载入一个技能。意图冲突、必填条件不足或工具不可用时，给出必要的澄清或继续普通对话。自动匹配可在个人设置关闭，用户可在发送前取消本轮选择。
- 匹配阶段使用短描述及结构化意图，选定后才加载正文。正文只提供做法。技能、文献、工具返回内容中的指令无法改变身份、工具权限或确认范围。首版技能内容限文本，引用仅可指向随版本审核的静态资料。
- 每轮开始时固定技能版本和工具清单摘要，追踪写入标识与版本。用户关闭某项能力或管理员撤销授权后，下一次实际调用重新核对资格。查看历史只读已存结果，重跑按当前权限创建新尝试。

## 3. 工具目录与外部 MCP

### 3.1 服务端调用流程

`当前账号和项目 → 确定技能 → 生成当轮可用工具 → 模型提出调用 → 服务端校验及执行 → 结构化结果与运行详情`

目录项至少包含稳定工具 ID、来源、输入及输出契约、访问范围、副作用等级、可用条件、预算和失败类型。可用范围按用户权限、项目归属、服务状态、技能范围及用户确认取交集。模型看到的定义和实际调用都来自该次目录，工具执行时再次核对权限、参数、配额和确认状态。

| 工具等级 | 例子 | 执行条件 |
| --- | --- | --- |
| 站内或已配置的只读查询 | SIMBAD、Gaia、ADS。RAG 原文发送沿用其专用授权 | 当前轮次意图与参数有效，在现有频率和结果范围内执行 |
| 外部只读查询 | 已审核的 MCP 科研查询 | 服务和工具均已获准。调用前展示目标服务及将发送的字段，按该轮查询范围确认。确认绑定账号、项目、轮次、工具定义和实际参数，参数或权限变化后重新核对 |
| 站内业务写入 | 从本轮已核验 ADS 结果保存到个人文献库 | 当前用户明确要求保存且条目范围明确时，复用现有直接入库路径。范围不明时先澄清 |
| 运行任务和脚本 | Python／Gnuplot 执行、REBOUND／PeTar 提交 | 草案由 Agent 生成，执行由用户在原入口确认，沿用参数版本、摘要、配额及幂等保护 |

保留现有每轮调用上限及上游配额，外部工具另受更小的调用预算。参数非法、服务不可用或额度耗尽时记录可区分的失败类别。允许在剩余预算内继续使用可用工具，并在回答里标明使用过的来源和缺失数据。结果仅在已通过完整校验后计为成功。

### 3.2 外部 MCP 首版验收范围

- 外部服务默认关闭。管理员通过现有 MFA 后台管理运营者预配的连接，查看状态、发现工具并按项批准。首版接入至少一个可控的只读 Streamable HTTP 服务，用独立 HTTPS 测试端点完成全流程验收。工具名以服务器标识隔离，外部工具无法占用内置名称。
- 先核对固定协议修订、服务身份与支持能力，再分页读取 `tools/list`。服务端状态包含最近一次成功发现时间、批准的工具清单、定义摘要及失败原因。列表在打开管理面板、配置变更和缓存到期时自动同步。发现结果可用于审查，只有已批准、定义未变且服务启用的工具能进入目录。工具移除、定义变化或连接失效时停止相应调用，更新定义后重新审核。[MCP 传输规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports) · [MCP 工具规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)
- 外部连接受部署端固定主机、端口、路径和出站策略约束。校验连接最终地址，拒绝内网、环回、云元数据及重定向请求，凭据仅由服务端引用。请求按逐项批准的字段构造，工具结果按大小和结构收敛为可显示的数据。完整会话、账号凭据、RAG 原文与原始科研附件留在原有受控路径。
- 首版按需调用外部只读工具；外部写入、任意 URL 或本地命令注册、自动下载执行技能脚本、OAuth 自助授权及 MCP 工具市场后续单独设计。连接、发现、调用各自设定超时、响应上限和并发控制。超时或响应异常时显示实际状态，避免无预算的自动重试。
- 现有 `stdio` 路径继续使用固定三项工具契约。外部服务停用、失联或协议不兼容时，用户仍可使用普通聊天及原天文工具，直连与本地 MCP 的既有切换语义保持有效。

## 4. 页面、持久化与追踪

- 查询工作台输入区提供「技能」选择。明确显示自动匹配、显式选择及本轮使用的技能。个人设置显示可用技能、适用任务、所需工具和自动匹配开关，沿用现有导航、项目上下文和窄屏布局。
- 现有后台增加「MCP 工具」管理区，负责人可以查看工具名称、来源、授权范围、定义变化和最近错误。普通用户只看到获准能力及外部调用数据确认。数据随页面进入、弹窗打开、筛选及写操作同步。读取和操作错误用 `StatusNotice` 顶部浮层，运行详情保留已记录的失败信息。[UI 设计规范](UI_DESIGN_SPEC.md)
- PostgreSQL 存储按账号隔离的技能偏好及管理员管理的服务、工具审批与审计记录。服务器运维配置只存凭据引用。新增数据使用可独立迁移的表或版本化配置，旧会话与项目记录保持可读。用户禁用技能、移除服务或调整工具权限后，历史运行仍展示当时的标识和状态。迁移在独立数据库验证，正式库变更按发布手册另行授权。
- 复用运行详情记录技能命中方式与版本、工具来源、协议修订、调用耗时、结果数量和错误类型。保存文献、生成图或提交任务时关联原业务产物 ID。数据按账号及项目访问权限查询。日志排除密钥、完整请求、用户原文及文献正文，未知用量继续显示为未知。

接口按能力新增技能目录、个人偏好和管理端服务与工具审批。现有对话请求通过可选字段传递本轮技能选择，旧客户端省略字段仍可对话。外部查询确认绑定尚未执行的轮次，拒绝过期或重复提交。同步接口和 SSE 对同一操作使用相同的权限及幂等规则。接口定稿后同步 OpenAPI 快照和生成的 TypeScript 类型。

## 5. 实施顺序

| 阶段 | 开发与退出条件 |
| --- | --- |
| M0 基线和契约 | 盘点模型适配器、既有工具入口、固定 MCP 契约和典型运行追踪。建立工具目录与各权限等级的代表样例，记录 `v2.0.7` 对照结果。 |

| M2 外部 MCP 与管理 | 实现受控传输、分页发现、审批、停用和调用。用受控端点证明至少一个工具可从发现走到实际调用，未批准或定义已改变的工具不可用。 |
| M3 追踪、升级与验收 | 对齐 UI、OpenAPI 类型和运行详情。用独立数据库验证升级与回退步骤，完成多账号、故障及科学结果对照后再安排发布。 |

## 6. 验收标准

| 覆盖 | 必须记录的结果 |
| --- | --- |
| 技能匹配 | 三个内置技能各有显式选择和自动匹配用例。关闭自动匹配、歧义输入及所需工具失效时，页面和结果与实际执行一致。 |
| 科研工作流 | SIMBAD 名称解析与 Gaia 查询可追溯到实际坐标及筛选。ADS 检索后按明确范围保存，重试复用原入库记录。绘图与 N 体草案可核对数据和单位，确认前无脚本执行或新计算任务。 |
| MCP 生命周期 | 受控端点覆盖发现分页、批准、调用、定义变更和停用。覆盖超时、无效参数、超大输出和协议不兼容，记录是否调用了上游以及最终用户状态。既有直连与本地 MCP 查询正常。 |
| 权限与数据 | 两个独立账号验证技能偏好、项目数据、运行记录隔离。工具声明、远端返回内容和技能正文中的越权指令均无法扩大授权。验证被禁止的地址、未获准字段及凭据不会出现在外发请求或日志中。 |
| 兼容及恢复 | 旧会话、项目、文献、任务和历史追踪可打开。验证功能开关关闭后的常规调用、尚未就绪的 MCP 服务以及独立数据库升级／回退。 |
| 页面与评估 | 桌面与移动端核对选择、确认、停用和错误浮层。沿用既有样例比较来源正确性、任务成功率、工具调用数、耗时与 Token 用量。保存成功、失败、跳过及环境限制。 |

验收使用独立测试数据库及合成数据。真实上游联调需记录工具、配置和限制，模拟响应与真实服务结果分别记载。验收证据写入 `docs/test-records/v2.1.0/<类型>/<UTC时间>/`。开发在本机 5173 进行。正式验收、生产配置和指定版本发布按[开发与发布手册](DEVELOPMENT_AND_RELEASE.md)执行。
