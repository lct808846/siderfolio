## 1. 背景与范围

V0.8 已有本地 PDF / Markdown 文档版本、FTS 关键词检索、可定位原文的摘录、项目快照、两条固定科研流程及格式 3 归档。当前知识库入口与聊天、流程各自使用；聊天不会自动读取个人文献。V0.9 的集成由用户显式建立关联，旧数据不会自动合并或产生隐含引用。

[V0.8 验收记录](test-records/v0.8.0/README.md)记录了当次 Windows / Ubuntu、本地浏览器、联网和合成检索评估。合成集结果不代表真实个人文库表现，也不能替代 V0.9 对当前提交的测试。复杂 PDF 排版、公式和图表提取仍可能缺漏。

本版必须交付：

1. 项目总览能看到会话、快照、流程和文档；用户可在同一项目内显式关联查询/流程结果与本地文献证据。
2. 关联展示精确来源、版本、时间、状态及原文定位；可以解除关联而不删除原始数据。
3. 增加可导出、可恢复的项目关联记录，兼容格式 1–3 的导入，并明确新版归档的旧版本边界。
4. 形成从干净环境安装、升级、备份恢复、评估和卸载的书面操作及可重复验收方案。
5. 固定 V1.0 候选支持矩阵与已知问题，回归原有 API、科学规则、隐私与资源限制。

本版不引入自动全文下载、OCR、向量检索、模型基于全文生成回答、账号、多用户、远程部署、任意脚本执行、成员判定或物理参数拟合。V0.8 的本地词法检索和摘录式回答继续适用；命中不代表科学命题获得证明。

## 2. 用户流程与信息边界

```mermaid
flowchart LR
    A[打开项目] --> B[查看会话、快照和科研流程]
    B --> C[打开知识库并检索原文]
    C --> D[用户选择具体证据和项目结果]
    D --> E[保存显式关联与用途说明]
    E --> F[查看结果、文档位置及关系状态]
    F --> G[导出项目或完整备份]
    G --> H[在独立临时库恢复并核对]
```

在项目总览中列出来源对象和关联状态，提供直接跳转，不重复复制一份可变结果。用户打开 Gaia / ADS 快照或流程输出后，可进入同项目知识库检索并选择证据；确认后建立关系。用户可在会话轮次与证据之间手动建立关系，但旧聊天模型不会因此读取全文，也不会把手动关联写进当时的 `ChatResponse`。

关联类型为 `user_reference`，只能表示“用户将此文献片段与此项目结果关联”，不能自动标为证明、支持、反驳、成员判定或同一研究对象。用户可填写不超过 1000 字的说明；说明是用户文本，不能当作原文或程序测量。界面分别展示数据库测量、ADS 摘要、用户提供的文献原文、用户备注和模型回答。

提供项目内总览、关联列表与详情；在移动端保持可读。若证据已删除、原文缺失、结果已删除、引用无权限归属或位置校验失败，显示相应失效状态并允许解除关联；不能用当前版本或同名文档替代历史原文。

## 3. 关联模型与有效性

新增 `ProjectLink`：UUID、所属项目、目标类型及目标 ID、证据 ID、创建 UTC 时间、用户说明、记录版本和关联状态。目标类型限 `conversation_turn`、`snapshot`、`workflow_run`，必须在同一项目；证据必须指向该项目中已有的 V0.8 证据记录及其固定文档版本、页/行位置和内容摘要。流程关联到运行整体，页面可继续查看原步骤来源，不猜测某段文献对应哪个计算步骤。

创建前验证两端归属、记录状态和证据位置；导入的 `imported_unverified` 标记随来源显示。每项关联仅记录用户选择的关系，无法认证观测真实性。相同目标和证据只允许一个活动关联，重复提交返回原关联，不复制证据；改备注通过带修订号的更新处理。关联的查询、文献版本和证据不能被静默修改。

目标删除、会话移出项目或文档删除时，保留最小标识及状态为 `target_unavailable` 或 `evidence_unavailable`，不再显示或导出已删除的原文；重新出现同名对象不能自动恢复关系。解绑是唯一永久删除该关联记录的用户操作。删除项目遵守既有“会话保留、项目数据删除”语义，并在确认界面列出关联数量。运行中及并发修改沿用现有冲突控制。

项目总览展示来源分类：查询工具、实际数据源 URL / UTC 时间、快照与流程版本、文献版本/哈希/页行、用户说明及导入真实性标记。哈希验证字节一致性，不认证论文或数据库来源；不因关联而修改已有 `sources`、回答或科学统计。

## 4. 接口与数据流（实现代码已写入，待验收）

旧 `/api/v1/chat`、会话、项目、流程、知识库、单轮导出契约保持兼容。新增 API 均在 `/api/v1/projects/{project_id}` 下，遵循现有 UUID、错误结构、Host/Origin 和本机访问限制。

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| GET | `/overview` | 返回项目各类对象摘要及关联状态，不触发外部查询 |
| GET | `/links` | 依据目标类型、目标 ID 或证据过滤，稳定分页 |
| POST | `/links` | 提交目标、证据、备注、项目修订号和幂等键，创建用户关联 |
| GET | `/links/{link_id}` | 返回关联和两端状态、来源信息 |
| PATCH | `/links/{link_id}` | 按修订号更新备注；不能变更关联两端 |
| DELETE | `/links/{link_id}` | 显式解绑；原数据、快照、证据和文献不删除 |

重复相同幂等键与请求体返回原结果；同键不同内容或项目修订冲突返回 409。跨项目对象与不存在对象统一返回 404；失效证据不得建立新关联，返回 422。上限和请求格式错误使用现有安全错误，不暴露文件路径或凭证。分页有固定上限和稳定排序，历史记录读取不触网、不调用模型。

本版不要求语言模型利用关联生成回答。将来需要基于个人文献调用模型时，应另行定义可见文本、引用验证、用户选择与服务商数据流；不能从用户创建关联推导出发送全文的授权。

## 5. 数据库、归档与恢复

V0.8 使用 SQLite schema 4，升级前一致性备份；新增关联表及必要索引，本次确定为schema5，新增project_links/project_link_requests；启动迁移前保存 `migration-v5-<UTC时间>.sqlite3`。本轮未启动应用或迁移个人库。迁移应事务化，保留会话、快照、流程、文档版本与证据；迁移失败回滚，未知更高版本拒绝写入。仅在隔离临时库使用脱敏真实结构与合成数据验证，不操作日常库。旧版程序不能直接降级写入新 schema，应停服后在独立目录恢复升级前备份。

现有格式 3 项目包含 `manifest.json`、`project.json`、`conversations.json`、`snapshots.json`、`workflows.json` 和 `knowledge.json`。V0.9 定义格式 4，新增固定 `links.json`，保存关联、两端关系和失效状态，列入清单哈希。支持导入格式 1–3：旧包导入后关联为空；格式 4 导入新项目并重映射项目、会话、轮次、快照、流程、文档版本、证据及关联 ID，保留原 ID 与 `imported_unverified` 来源。

格式 4 继续支持明确区分的完整备份和仅元数据包。完整备份含已有知识库原文版本，先显示数量与字节并由用户确认；原文缺失或哈希不符则拒绝声称完整。仅元数据包导入后文档及相关证据显示不可用，保留原始哈希和关联，不生成虚假可用引用；只有重新提供同哈希原文件并经过版本/位置验证后才可恢复。索引可重建，不能由索引文本冒充原文件。

V0.8 不支持格式 4。仅当项目不存在关联时，才可显式选择按 V0.8 条件导出格式 3；任何不受支持的数据都不能静默丢弃后称作完整备份。归档沿用 32 MiB 压缩、128 MiB 解压、64 MiB 单成员限制，以及固定成员、去重、路径、实际字节数、哈希、引用、严格 JSON 与原子导入校验；超限时给出具体原因，不返回半包。导入不自动执行流程、检索、模型或远端查询。

所有新增关联及其操作记录计入现有 256 MiB 业务预算；当前代码限制每项目最多1000关联、3000创建请求历史、每次列表最多100项（页面25项）。达到限制返回明确错误，不自动清除旧数据；具体参数以实现和验收结果为准。

## 6. 安装、维护与支持范围

V0.9 文档交付须覆盖：Windows 与 Linux 各自的 Python / Node 前后端安装、独立启动、固定本机监听、浏览器访问、环境变量配置、FTS5/trigram 检查、首次升级与故障提示；版本和依赖以实际验收环境为准，不将某次本机版本推广成全部兼容范围。

提供清晰的两类恢复：SQLite 一致性数据库备份用于整库恢复；项目格式 4 完整包用于单项目迁移。两种方案分别在独立临时目录演练，验证恢复后的文档字节、引用、快照、流程和来源。卸载说明分别列出程序、环境、项目数据库及用户导出文件的位置与影响，默认不自动删除用户数据；实际删除由用户明确执行。

维护文档需说明：单用户、单 worker、本机 SQLite；解析器平台资源限制；知识库词法检索与 PDF 提取局限；SIMBAD 主站与镜像按实际记录；外部服务和模型不可用时的降级。整理问题清单，按复现条件、影响、规避方法和处理状态区分；不以“零已知问题”的口号替代记录。

## 7. V1.0 候选契约与评估

V0.9 为 V1.0 提供候选接口/数据契约：列出支持的 API 路径及字段、错误、SQLite schema 与迁移、项目归档格式、导出格式、证据位置、截断和失败语义，并标记是否承诺向后兼容。通过变更清单和旧版本样本核对；若后续必须变更，单独记录影响与迁移步骤。候选冻结不等于 V1.0 已实现或已经发布。

固定独立评估集，覆盖两条科研流程、SIMBAD / ADS / Gaia 的成功与失败、项目恢复、中文与英文知识检索、缺失原文、无答案拒答和引用失效。至少选取代表性真实可使用文献与合成边界样本；保留文件授权及人工标注，不把个人文献提交仓库。记录每项输入、预期、引用位置、实际输出和失败原因；检索命中不作为内容支持性判断。评估指标包括前五证据覆盖、无答案拒答、引用可回原文比例、无效引用与人工核对情况；阈值在评估前根据样本和任务确定，记录版本，不在结果出来后调低。

现有 V0.8 合成评估记录属于旧基线；其 24 条正例和 8 条无答案结果不能推断真实文献表现。新集与旧集应分别报告，以便比较；外部服务波动、网络失败和测试环境差异单独标明。

## 9. 测试与发布门槛

项目当前约定为“开发阶段不主动运行测试，发布前由用户安排验收”；本轮仅编辑源码/文档、格式化和生成接口类型，未运行测试、构建、评估、备份恢复或个人库迁移。下列内容为待执行计划：

- **离线回归：** 原聊天、SIMBAD / ADS / Gaia、两种流程、项目与知识库；验证同项目关联、幂等、并发修订、解绑、删除后失效、旧版本引用和跨项目拒绝。模型/外部 HTTP 在默认测试中禁用。
- **归档与迁移：** schema 4 升级、一致性备份、迁移失败回滚与未知版本拒绝；格式 1–4、完整与元数据包往返，检查新旧 ID 映射、原文件哈希、缺失状态及关联；坏成员、路径、重复、超限、损坏引用必须拒绝并回滚。
- **真实 HTTP / 浏览器：** 使用临时服务与合成数据完成建项目→查询或导入结果→运行流程→上传文献→检索→显式关联→原文定位→导出→独立恢复→核对；覆盖 Chromium / Edge、窄屏、键盘、长文件名、警告、服务中断与清理。
- **检索和科学检查：** 运行预先固定的独立评估集，逐条核对原文页/行、无答案、状态和人工标注；不把匹配当成员关系或因果证明。联网检查需显式启用并记录模型费用及来源；外部失败不得改写成通过。
- **安装与恢复：** 在列明版本的 Windows / Linux 干净或隔离环境分别验证前后端构建、启动、库迁移、备份恢复、无凭证基本界面及数据保留的卸载说明；不使用个人库或私人全文作为可公开证据。
