# 对话附件（待验收）

## 用户操作

工作台输入框右下角、发送按钮旁新增纸夹按钮，也可将文件拖入输入框。
支持 PDF、DOCX、TXT、Markdown、CSV 和 JSON，每轮最多 3 个文件，单个最多 10 MiB。
选中后显示解析状态、文件名及文本预览入口，发送前可移除，失败后可重试。
仅附件也可发送，默认问题为“请阅读附件并概括要点”。

## 数据与上下文

- 选择文件仅调用本机解析接口，不调用回答模型；用户点击发送后才将预览中的文本随问题发送给所选模型。
- 每个文件最多向模型提供 16 KiB UTF-8 文本。超过时标注“部分内容”，预览及模型输入均保留截断提示。
- PDF 复用有时间与内存限制的本地解析子进程，保留物理页标记；DOCX 只读取有大小限制的正文 XML，不解包执行内容。
- 不进行 OCR，不提取图片内容；文档版式、公式及复杂表格可能不完整，实际警告在预览中显示。
- 附件文本、名称、类型、文件大小、摘要和解析警告保存到轮次 JSON，无需数据库表迁移。附件是用户输入，不能作为科学数据库认证或授权额外工具。
- 后续模型切换使用同一会话历史窗口，包含窗口内已发送附件文本；原有轮数和字节预算仍生效。
- 会话保留发送文本快照。原始二进制文件只用于本次本地解析，不作为聊天原件归档；需原件管理时使用项目知识库。
- 待发附件按会话保留在页面内存中，不写浏览器持久存储。切换会话不会把它们发到另一会话；刷新页面后须重新选择未发送文件。
- 断线重试固定原请求编号、模型及附件文本，避免重放不同内容。未使用的草稿和文件选择不创建正式会话。

## 接口

`POST /api/v1/chat/attachments` 接受仅含 `file` 的单文件 multipart，返回有界 `ChatAttachment` 文本快照。
上传实际传输字节由本机访问中间件在解析前限制，解析并发最多 2 个。
会话 `TurnRequest.attachments` 可提交最多 3 个快照；对应 JSON 接收上限为 128 KiB。
附件内容纳入请求摘要，旧请求省略或提交空附件列表时仍兼容原请求编号。
