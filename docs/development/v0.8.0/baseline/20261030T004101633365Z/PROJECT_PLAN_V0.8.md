# AstroAgent 开发文档 V0.8：个人知识库与证据检索

**文档日期：** 2026-10-30  
**文档状态：** 开发规划；功能、测试及发布尚未完成  
**基线：** V0.7.0，编写时本地 HEAD 与标签均为 `9b16fe9`  
**目标版本：** `0.8.0`；实施时再更新包和接口版本  
**目标：** 在项目中导入本地文献，以可核对的页码或段落检索原文，保留来源和解析边界。

本文承接 [V0.7 开发文档](PROJECT_PLAN_V0.7.md) 和[版本路线图](ROADMAP.md)。实施前核对实际基线、工作区和测试状态；本文是开发契约，不作为已完成的证据。

## 1. 范围与当前基础

V0.7 已提供 Vue 工作台、FastAPI、SQLite 项目与会话、固定科研流程、快照和格式 1 / 2 项目归档。本版将知识库限定在用户选定的项目内，保留旧聊天、项目、流程和科研数据导出接口。

V0.7 [测试记录](test-records/v0.7.0/README.md)记载离线、浏览器、真实流程和归档等当次验收；实施 V0.8 时须重新回归，不能把旧报告当成本版通过。编写时标签为 `v0.7.0`，远程发布状态与后续改动应在实施前重新核验。

### 1.1 交付

1. 浏览器选择并上传本地文本型 PDF 或 UTF-8 Markdown，按项目保存文件、元数据、解析状态和 SHA-256。
2. 将实际提取出的文本分段，记录 PDF 物理页码或 Markdown 行号及章节路径；显示空页、解析失败和未索引范围。
3. 本地索引和检索中英文关键词，返回可打开原文定位的证据，明确命中范围和排序方法。
4. 对问题生成带引用的**摘录式回答**：只展示实际命中原文及其出处；没有足够证据时明确说明未找到，不能凭模型记忆补答。
5. 文档替换建立新版本，删除或重建时同步处理索引；已有历史引用可核对，失效时明确标记。
6. 扩展项目归档，允许用户明确选择包含原文的完整备份，并验证导入与恢复。

本版不自动下载论文、读取 Zotero、绕过访问权限、OCR、解析图片中的公式或表格、在线爬取、使用向量数据库或进行跨项目全文检索。首版回答不调用语言模型、不将文献上传给模型服务；语义生成与远程嵌入待后续另定数据流及验收契约。用户上传的文件应由用户自行确认有权使用。

## 2. 使用流程

```mermaid
flowchart LR
    A[选择项目和本地文件] --> B[大小与格式检查]
    B --> C[保存文件及内容哈希]
    C --> D[按页或行解析并记录状态]
    D --> E[建立本地检索索引]
    E --> F[问题或关键词检索]
    F --> G[展示摘录与页码或行号]
    G --> H[打开原文核对]
    E --> I[显式导出含原文的项目归档]
```

项目页新增“知识库”：上传、文档列表、解析状态、搜索框、证据结果及定位入口。可显示标题、作者、年份、DOI 等用户填写的元数据，未知项留空；文件名不是论文标题的可靠证明。页面需区分“用户文档原文”“ADS 摘要”“数据库测量”和“模型回答”。旧聊天接口不会自动引用知识库；用户通过独立证据入口查询，避免悄悄改变旧接口的数据流。

上传按钮明确说明文件副本存储于本机项目数据库，归档包含原文需单独确认。PDF 打开定位使用项目文档受控读取接口和物理页号，Markdown 展示对应原始行；定位不到时提供已存原文和页码/行号，不伪造高亮位置。

## 3. 文档、版本与数据

| 实体 | 保存内容 |
| --- | --- |
| `KnowledgeDocument` | UUID、项目 ID、文件名、用户元数据、当前版本 ID、创建/更新时间与状态 |
| `DocumentVersion` | UUID、原始字节及 SHA-256、媒体类型、大小、提取器版本、解析时间、页数/行数、逐项状态与警告 |
| `TextUnit` | 版本 ID、原始提取文本、PDF 物理页码或 Markdown 行号范围、章节路径、分段版本与内容摘要 |
| `SearchIndex` | 可重建的索引条目、算法及版本；不作为原文真实性证明 |
| `EvidenceRecord` | 查询、项目、文档版本、命中单位、原始文本位置、生成时间、索引版本；不保存密钥或模型推理 |

同项目相同字节哈希重复上传时返回现有文档及提示，用户可选择创建独立文档记录；跨项目互不泄露。文件内容按版本不可变；替换文件新建版本，保留历史版本与证据引用，当前索引只覆盖当前版本。恢复旧版本属于显式操作，需重建索引并记录。文件名、标题和作者只作文本处理，不作为服务器路径或可执行内容。

默认原始文件、抽取文本、索引及项目业务数据全部存入本地 SQLite 或由数据库管理的私有存储，业务配额统一核算；实现必须明确持久化布局和迁移办法。删除文档需确认影响：撤销当前检索、清理所有版本与索引，并将引用标记为“原文已删除”，保留最小溯源元数据与哈希；不声称可恢复原文。SQLite 空闲页、旧备份和已导出归档可能仍含原文件，界面说明删除范围，不能声称安全擦除。

## 4. 提取与定位

PDF 只处理未加密、可提取文本的文件。候选提取器采用 `pypdf`，实施前固定兼容版本并验证许可、依赖和资源约束；不把解析库安装等同验收。按 PDF 物理页从 1 开始记录，另存页内顺序；印刷页码与物理页不一致时以物理页为准。无文本页标记 `no_text`；损坏或不支持的页保留失败原因。若整份无可检索文本，提示可能为扫描件，不宣称已阅读全文。

Markdown 支持 UTF-8 及 UTF-8 BOM，保留原始文件和一基行号；抽取标题层级与段落，代码块作为数据保留，不执行其中内容。PDF 数学公式、双栏、脚注和表格可能提取错序或缺漏，页面明确显示提取文本供核对；不能把 OCR、排版恢复或引用准确性视为已保证。[pypdf 的文本提取说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)指出了图像页和复杂布局的限制。

分段限制在单页或相邻 Markdown 行范围内；每段目标不超过 1200 个 Unicode 字符、重叠最多 120 字符，实际分隔符与算法版本写入元数据。检索使用规范化副本，展示和引用保留原始提取文本、实际偏移与行号；不得把索引归一化后的字符串冒充原文。页码只定位到页面，未实现可靠坐标前不承诺 PDF 精确高亮。

解析过程不执行 PDF 脚本、外链或 Markdown HTML。受限子进程解析并设定时间与输出上限；必须在 Windows / Linux 验证超时终止和内存限制方式，不承诺仅限制上传体积即可防止解析内存膨胀。若平台不能可靠实施所需资源限制，上传/解析明确不可用，不静默取消保护。[pypdf 文档](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)提示 PDF 内容流解压可能占用大量内存。

## 5. 检索与证据回答

首版使用本地 SQLite FTS5 词法索引，包含 Unicode 文本及三字符片段两种索引模式；英文词和长度足够的中日韩连续字符可按相应模式搜索。两字符及单字符中文查询不依赖 trigram 索引，使用经配额限制的项目内确定性扫描；查询太宽或超资源上限时明确要求增加关键词。FTS5 和 trigram 可用性需在支持的 Windows / Linux Python SQLite 环境实测，缺失时知识库索引功能返回明确错误，不影响旧项目/聊天。FTS5 是全文检索模块，tokenizer 及实际构建选项见 [SQLite 官方文档](https://www.sqlite.org/fts5.html)。

统一 Unicode 规范化和大小写规则，使用参数化查询并将用户文本视为检索词，不直接执行 FTS 查询语法。每次最多返回 20 段，同分按文档 ID、版本 ID、位置稳定排序；相邻重叠段合并显示时保留可追溯的原文位置。检索模式、词项、过滤条件、索引版本、总命中是否截断及时间写入结果。精确英文词、中文短语、大小写、重复及缺失场景必须使用中英评估样本校验；不声称支持同义词、跨语言语义或理解图片。

“回答”按问题中用户输入的关键词检索，输出“找到的相关原文”及证据编号、文档、物理页或行号；不按固定模板把不相关片段组合成事实结论。没有命中或只有空文本时返回 `insufficient_evidence`，提示修改关键词或补充文档；命中不等同回答正确或支持用户命题。不得伪造文献、页码、引用、摘要或研究结论，也不将证据表称为文献综述。

点击证据先验证项目、版本、位置及文本摘要；替换文件不重定向旧引用到新文件。旧版本仍存储时可打开旧版本；原文删除、版本不可用或哈希不一致时提示失效，不展示新内容冒充原证据。上传/检索/引用过程中不调用模型、ADS 或外网，文献里的指令不能改变权限或触发工具。

## 6. 接口设计（待实现）

新增接口使用现有 `/api/v1`、项目归属、Host/Origin 检查和安全错误结构；所有 ID 使用 UUID，未知字段拒绝。旧接口不增加必填字段。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /projects/{project_id}/documents` | `multipart/form-data` 上传单文件及可选元数据；创建文档版本和解析任务记录 |
| `GET /projects/{project_id}/documents`、`GET .../documents/{document_id}` | 列表及版本、状态、页数/行数、警告 |
| `POST .../documents/{document_id}/versions` | 显式上传新版本，旧版本保留 |
| `GET .../documents/{document_id}/versions/{version_id}/content` | 读取该项目拥有的原始文件，安全下载或本地受控预览 |
| `POST .../documents/{document_id}/reindex` | 用户显式重建当前版本索引 |
| `DELETE .../documents/{document_id}` | 按修订号删除全部版本与索引，保留失效引用元数据 |
| `POST /projects/{project_id}/knowledge/search` | 项目内搜索，返回证据、位置与解析警告 |
| `POST /projects/{project_id}/knowledge/answers` | 生成摘录式回答及引用，无命中为 `insufficient_evidence` |
| `GET /projects/{project_id}/knowledge/evidence/{evidence_id}` | 校验并读取原始引用、上下文和有效性 |

以上缩写路径均以 `/api/v1` 为前缀，`...` 指同一项目路径。上传按实际接收字节限制，解析与建立索引可在当前请求内执行；单项目一次解析，超时/中断记录状态，允许用户显式重试，不引入持久后台队列。重试使用请求 UUID 防重复；相同键异体为 409，已完成返回原结果，服务重启后不自动执行。新版本和删除使用项目修订号避免覆盖并发变更。

不存在/越权归属为 404；修订/幂等冲突为 409；文件或实际解压超限 413；不支持媒体 415；损坏、加密或字段无效 422；索引不可用、解析器忙或存储不可用 503。部分页面解析失败以文档 `partial` 记录，整份失败保留文件及错误，不能报告“全部已索引”。错误不暴露路径、堆栈或凭证。

## 7. 资源、索引与隐私边界

建议设计上限：单文件上传 20 MiB、每项目最多 100 个文档及 200 个版本、PDF 最多 500 页、Markdown 最多 200,000 行、单版本提取文本最多 20 MiB；项目内索引查询最多扫描 20 MiB 已提取文本。所有原始文件、文本、索引和执行预留计入 V0.7 的全库 256 MiB 业务预算，超限时拒绝或明确记录部分解析，不能截断后标为完整。采用流式上传并限制 multipart 额外开销；文件类型以内容和解析结果联合验证，不能只信扩展名。

索引视为派生数据，可按版本重建；更新/删除在事务或可恢复状态机中保证旧索引不再对外返回。崩溃后不自动重试外部操作；本地重建前核对文件哈希、版本与配额。检索不对文献作科学认证。所有来源、标题、作者、页号和外部内容必须安全展示，禁止把用户 Markdown/HTML 当页面脚本运行。

原文件只在本机保存和处理；前端 `VITE_` 配置、日志和测试证据不含凭证、个人文献或全文。若未来引入在线模型或嵌入，必须事先明确发送哪些内容、用途和用户选择，不能沿用本版“本地处理”的表述。

## 8. 项目归档、迁移与恢复

V0.7 项目归档格式 2 包含会话、快照、流程和持久输出；V0.8 规划格式 `3`，增加知识库元数据、原始文档版本、证据引用和哈希。索引及解析中间结果可重建，不是唯一原文来源。归档包含原文件时须在导出前明确显示文件数量和大小并获得用户主动确认；这会产生含用户文献的可复制 ZIP，应由用户自行管理。

默认项目导出提供明确选择：**完整备份（含原文）**或**仅元数据（不含原文）**。仅元数据包须在清单及导入界面标记不完整，导入后引用为原文不可用，不静默创建空内容或声称可恢复全文；需用户重新提供同哈希文件才可恢复对应版本。完整备份的原文和所有版本、证据引用须可校验恢复。

格式 3 的固定成员和原始文件映射在实施时按实际大小上限具体定义，必须禁止重复路径、路径穿越、软链接、未知版本、压缩膨胀、坏哈希、无效引用及部分提交；V0.7 原 32 MiB 压缩、128 MiB 解压和 64 MiB 单成员上限继续生效。超过时明确失败，不以隐式去掉原文解决。导入创建独立新项目并重映射所有 ID，保留原始哈希与 `imported_unverified`，不执行外部链接或自动查询。

V0.8 应兼容导入既有格式 1 / 2 项目；旧包导入后知识库为空。V0.7 不能读取格式 3；仅当项目不存在知识库及相关引用时，才可显式导出兼容格式 2，不能丢弃知识库后称完整备份。格式 3 与 SQLite schema 均需明确版本、升级前一致性备份、失败回滚和高版本拒绝；实施前固定具体 schema 及迁移文件。旧版恢复在独立目录使用迁移前备份，不直接降级写入。

## 10. 验收与评估计划

本项目当前 README 记载开发阶段不主动运行测试，发布前由用户安排验收；本次仅写文档。以下均为实施后需要完成的计划，不是已执行结果。

离线验收使用用户可公开使用或人工编写的合成文件：多页 PDF、扫描样本、混合空页、加密/损坏文件、中英文 Markdown、长行及恶意文本。检查原文哈希、页码/行号、段落、文件版本、部分提取、重复上传、删除/失效、无结果拒答与命中可回原文。验证 pypdf 进程超时/内存限制、异常中止、实际接收及解压超限，解析器不访问网络。

固定独立评估集至少 30 条查询，覆盖英文术语、中文单字/双字/三字、精确短语、无答案、跨页、元数据缺失和抽取缺陷；为每条预先标注目标文档、页/行和可接受证据。记录命中率、前 5 条证据覆盖率、无答案拒答率、无效引用数及查询耗时；正式阈值应在看到本版评估结果前固定并解释，避免事后移动门槛。摘录式回答不做未经证据支持的结论；评估样本和脚本版本与报告一同保存。

真实 HTTP 验收在临时数据库中完成上传→解析→查询→定位→替换→旧引用核对→删除→失效→完整/仅元数据归档导出与恢复；另测中断、并发冲突、坏包、配额和旧归档。验证整个过程不访问外网或模型，逐项比较文件哈希和来源；关闭临时进程并核对端口。
