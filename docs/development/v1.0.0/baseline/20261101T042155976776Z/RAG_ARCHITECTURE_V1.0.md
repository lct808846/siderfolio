# AstroAgent V1.0：RAG、数据库与个人使用体验

**日期：** 2026-11-01  
**状态：** 开发契约，尚未实现或验收  
**基础：** [V1.0 主计划](PROJECT_PLAN_V1.0.md)、[V0.8 知识库](PROJECT_PLAN_V0.8.md)、[V0.9 项目关联](PROJECT_PLAN_V0.9.md)

V1.0 必须实现完整的检索增强生成：从用户选择的文献提取和索引内容，结合问题检索证据，按用户确认的范围交给模型生成回答，保留可回查的引用与问答历史。数据库需要可配置、可检查、可恢复。现有 V0.8 词法摘录不是本功能的完成证据。

## 1. 个人使用的完整流程

1. 首次进入工作台：配置本机 PostgreSQL 数据库连接，检查数据库、pgvector、磁盘、嵌入模型和回答模型配置；无配置时提供清楚的设置入口。
2. 新建项目，导入本地 PDF / Markdown；查看解析成功、空页、失败页、页码及版本。明确提示扫描件目前不支持 OCR。
3. 按用户操作准备本地嵌入模型；若首次需要下载，先显示来源、版本、预计体积与网络需求，用户确认后下载并核对文件标识。加载本地已下载模型时不得偷偷联网。
4. 点击“构建知识索引”，显示排队/处理/完成/失败、已处理/总分段、可继续或重建操作。已解析的词法检索始终可独立使用。
5. 在项目中打开“知识问答”，选择全部已索引文档或指定版本，输入问题，先查看检索片段和将发送的模型服务及内容；用户确认后生成。
6. 阅读回答及逐条引用，点击跳到固定文档版本的 PDF 物理页或 Markdown 行。支持追问、查看先前问题和证据、保存到项目。
7. 在设置查看数据库与索引状态，显式备份、恢复或重建；失败时说明影响、已保存内容和具体下一步。

以上均为 V1.0 必须开发的用户功能。导入、索引、预览或默认旧聊天不会自动向外部发送文献；每次发送前的确认覆盖本次实际片段和服务商。

## 2. 数据库选型与配置

| 组件 | V1.0 基础方案 | 保存内容 |
| --- | --- | --- |
| PostgreSQL | 本机服务，作为业务数据唯一权威来源，负责事务、版本迁移与数据约束 | 项目、用户文档原文、分段、文件版本、问答、引用、操作与来源 |
| pgvector | 安装并启用于同一个 PostgreSQL 数据库的扩展 | 可重建的分段向量、项目/文档版本过滤字段和索引版本 |
| 本地嵌入模型 | 使用 Sentence Transformers 兼容的多语言模型，CPU 可运行；候选 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` | 模型文件保存在用户配置的本机目录，不混入业务数据库 |
| 回答模型 | 沿用已配置的 DeepSeek 服务作为默认生成端；通过服务端配置访问 | 实际只接收用户确认的问题、必要历史和检索片段，不持久化密钥到前端 |

PostgreSQL + pgvector 是 V1.0 的目标方案，pgvector 在 PostgreSQL 内提供向量相似性查询；实施前须在目标 Windows / Linux 实测安装、扩展权限、重启、事务和故障恢复，不能只安装客户端便宣称数据库完成。模型名是可测试候选，最终选择须根据中文/英文天文文献效果、体积、设备资源、许可和可下载性评估并固定具体版本和文件哈希。官方资料：[pgvector](https://github.com/pgvector/pgvector)、[PostgreSQL 全文检索](https://www.postgresql.org/docs/current/textsearch.html)、[Sentence Transformers 多语言模型](https://www.sbert.net/examples/sentence_transformer/training/multilingual/README.html)。

在支持矩阵中记录 Python、PostgreSQL / pgvector、CPU/内存、模型大小、磁盘需求及实际系统版本；首次体验支持 CPU，不把 GPU 作为门槛。数据库中原始文件及文本是权威数据，向量是可重建派生数据；无法验证索引一致时回退到词法检索并显示原因。V1.0 后端仍限定单进程单 worker，数据库默认本机访问。

设置通过服务端配置提供数据库连接、嵌入模型本地路径、检索开关和资源上限。开发时固定环境变量名；例如 `ASTROAGENT_DATABASE_URL` 仅为待实现的服务端配置，采用独立账号和最小权限，不能放进前端 `VITE_` 配置。文档应列出本机 PostgreSQL / pgvector 安装启动、创建数据库/账号、初始化扩展、连接检查、重启规则、凭据设置、备份恢复及故障排查命令；命令需实际在 Windows 和 Linux 验证后交付，不假设已安装 Docker。配置不能接受任意网页指令、SQL 或 Python 代码；不把数据库密码或模型密钥写进源码、浏览器持久存储、日志或报告。

V1.0 运行时不使用 SQLite 或 Qdrant；PostgreSQL 服务和 pgvector 是本版数据库功能的必需依赖。V0.9 及更早版本已有的 SQLite 文件只作为一次性迁移输入与可恢复的原始备份。仅安装 PostgreSQL 或启用 pgvector 不代表用户旧数据已迁移、RAG 已可用或备份已验证。

## 3. 索引构建与一致性

复用现有文档版本和有页/行位置的分段，分段唯一身份由项目 ID、文档版本 ID、分段 ID 和内容 SHA-256 确定。保存嵌入模型名称、固定版本/文件哈希、维度、归一化方式、分段策略、索引版本及构建时间；不同模型或维度不得混查。索引项只放向量与必要过滤标识，不以向量库存储文献正文为权威数据。

上传/替换先提交 PostgreSQL 原文件及解析结果，向量构建采用明确的 `pending/running/ready/failed/stale` 状态和可持久化的操作记录。本地嵌入计算不持有数据库事务；完成后在 PostgreSQL 短事务中校验来源和模型版本、写入向量及更新状态。批次全部核对通过后方可标记 `ready`；中途故障保留待恢复记录，重启后显示中断并由用户显式继续或重建。重复操作使用幂等 ID，不能形成重复分段或让旧模型数据混入新索引。

删除/替换文档或项目时在 PostgreSQL 事务中撤销可检索权限并使相关引用失效，然后清理或重建向量；查询侧必须按当前项目、版本、删除状态和哈希校验，杜绝跨项目或已删除文献进入模型上下文。旧版本若显式允许检索，应由用户选择并明确标识，不能因新文件同名而重定向。

索引重建固定目标文档版本与模型版本，在隔离的索引代中生成、验证后原子切换；失败时保留之前可用的索引代和错误信息，不能使用半成品。记录向量目录体积、索引数、未完成项、模型和上次核查时间；默认业务库 256 MiB 上限不静默扩大，向量与模型目录另设明确磁盘预算，首次安装前显示真实下载和磁盘需求。超过任一预算应拒绝并说明，不删除用户文件。

## 4. 检索与回答

检索范围始终是单个项目，用户可指定文档或版本。问题先经过有限长度和空输入校验，同时执行 PostgreSQL 词法检索和 pgvector 语义检索；每路保存算法、索引版本、实际过滤条件、候选数和得分。中文单字/双字及专业词的分词方案须明确设计并以独立样本与旧检索对比，不假设 PostgreSQL 默认分词等价于 SQLite FTS5。默认各取最多 20 个候选，按确定性的倒数排名融合（RRF，`k=60`），去重后最多选择 8 段，发送前再次检查 PostgreSQL 中的归属、版本、哈希与原文位置；这些数字为初始配置，需经评估后固定。

明确区分 `no_results`、未建立索引、部分文档解析失败、向量库不可用、模型不可用和证据不足。混合检索一条路失败时界面标记降级，只提供实际可用结果；是否允许基于降级结果生成须由用户看到实际证据后决定，不把失败显示为完整双路成功。模型、文献、导入归档与检索结果均不具备系统指令权限，不得因文档文本调用工具、泄漏密钥或跨项目读取数据。

发送前向用户展示模型服务、问题、会发送的各段原文、文档/页行及可能包含的最近对话；提供取消。确认后才通过服务端将所示内容发送至 DeepSeek。只按用户确认的证据生成，要求模型以服务端生成的证据编号引用每条事实，并标示资料不足、文献未覆盖和解析限制；不根据模型记忆编造天文测量、文献结论或来源。

服务端校验所有引用 ID 属于本次证据集合、对应项目及固定版本/位置且当前可读取；无效引用不生成可点击来源。没有有效引用或明确证据不足时返回“证据不足”，不输出伪装成可靠结论的正文。程序校验引用存在不等于证明每句话被引用支持，界面应提示用户回原文核查；引用支持度和错误结论需通过独立人工评估。模型超时、失败、证据被删除或确认后版本改变时应安全失败或要求重新确认，不能静默改发新内容。

问答记录保存问题、回答、使用的历史范围、证据 ID / 版本 / 页行 / 哈希、模型名称与版本（供应商可提供时）、索引版本、时间、状态、失败和是否用户确认；显示引用已失效或原文缺失。明确区分原文、模型解释、数据库测量与用户备注。追问绑定项目和当前文献范围，使用有界历史；旧问答引用的文档更换或删除后不得指向新文档。

## 5. 接口、配置和兼容

在现有项目 API 下设计独立的 `/rag` 接口族：配置/状态检查、模型可用状态、索引构建/任务状态/重建、检索预览、明确确认后生成、问答历史与删除。实施前在 OpenAPI 固定每个路径、请求/响应、状态码、幂等键、分页与并发边界；不能以这段文字冒充已经实现的 API。上传、索引和检索预览不调用远程模型；生成必须携带对预览内容、模型与版本的确认令牌，过期或证据发生变化则返回冲突并要求重新预览。

旧 `/api/v1/chat`、现有词法检索与摘录接口默认语义不变；V1.0 RAG 新入口与旧对话隔离，用户可显式选择项目并开启。模型/向量库未配置时返回明确配置错误，旧界面、原文预览和词法检索继续可用。全链路限制输入、上下文、调用次数、执行时间与输出长度；不把模型超时改为成功回答。

迁移工具仅一次性只读 V0.9 SQLite schema 5 一致性备份，导入新建空 PostgreSQL 数据库；先记录源文件哈希，导入后核对项目/会话/轮次/流程/快照/文献版本/引用/关联数量、外键、时间、JSON 语义、文件哈希及来源。数据库迁移与 FTS 检索重建分别报告，不把导入成功等同检索质量通过。中断或校验失败回滚目标导入，原库不可写；迁移重试不产生重复记录。正式切换前用户可检查结果，回滚至 V0.9 需使用旧库备份，切换后新写入不会自动回流。项目归档需保存问答记录与固定版本引用，兼容旧格式导入，不能静默丢弃历史；仅元数据恢复不能假装原文或向量可用。

整库备份采用 PostgreSQL 一致性备份工具，保存业务数据、向量、版本及嵌入模型标识；恢复至隔离的新数据库并检查 pgvector 版本、模型维度、数量、外键和文件哈希，不覆盖现有数据库。也可明确选择不保留向量并在恢复后重建，须在清单标明。密钥和模型文件分开处理；恢复后的模型缺失时显示需要重新准备，不能自动联网下载或悄悄换模型。

## 6. 独立评估与验收

在用户安排的发布前测试中，先固定多篇可合法使用的中英文天文论文和人工独立标注的查询集、版本、分母和阈值；覆盖中文问题检索英文论文、专业名称、无答案、矛盾证据、跨文献、复杂 PDF、提示注入、过期引用和跨项目隔离。分别评估词法、向量、混合检索 Recall@5、引用位置有效性、回答忠实度、无答案拒答率、时延和资源；模型回答的证据支持性由人工独立核查，引用链接有效不等于结论正确。合成集与真实文献分开报告。

离线检查须覆盖本地模型、PostgreSQL / pgvector 持久化重启、向量事务和索引中断重建、旧库迁移、替换/删除/并发、权限隔离、无证据、错误引用、提示注入和资源耗尽；网络拦截验证用户确认之前无文献片段外传。真实模型检查仅显式启用并告知费用，记录用户同意、服务、输入范围、目标版本与输出；失败和不确定结论如实保留。

浏览器验证从全新数据目录、准备嵌入模型、上传文献、索引、预览证据、确认发送、带引用回答、追问、重启恢复到备份/重建完整闭环，覆盖 Windows / Linux 和桌面/窄屏，核对失败状态与键盘可用性。测试使用公开授权材料或合成数据，不使用用户日常库。开发期间遵循项目约定不主动运行测试；发布前由用户安排验收。

### 完成标准

- [ ] 首次向导与设置可配置 PostgreSQL 和 pgvector，模型下载/离线加载、配额与状态可检查。
- [ ] 文档导入、增量索引、版本变更、删除、幂等重建和异常恢复可核对，索引与业务数据不会交叉泄漏。
- [ ] 混合检索、证据预览、用户确认、模型生成、有效引用、证据不足及历史追问完整可用。
- [ ] 不发送未经确认的文献；前端、日志、归档和测试证据不含密钥；来源与科学边界明确。
- [ ] 旧 API、知识库摘录、项目、工作流、单轮导出与数据库/归档迁移兼容通过。
- [ ] 独立检索与回答评估、Windows/Linux 安装、浏览器全流程、备份恢复及真实服务验收达到预先确定的门槛。
- [ ] 用户手册、操作命令、接口、配置、已知限制和版本化测试记录与实际实现一致。

上述均是待实现/待验收的 V1.0 要求，当前工作区尚不具备对应 RAG 或向量库功能。
