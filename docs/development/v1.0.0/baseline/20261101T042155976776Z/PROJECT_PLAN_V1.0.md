## 1. V1.0 的产品边界

V1.0 以既有 Vue 3 / TypeScript / Vite 前端和 FastAPI API 为基础，将业务与向量存储规划为 PostgreSQL + pgvector，面向可信本机、单用户、单后端进程和单 worker。除已有能力稳定化外，必须实现检索增强生成（RAG）、数据库配置和 V0.9 数据迁移，以及首次使用到备份恢复的完整体验。具体契约见 [V1.0 RAG 与数据库设计](RAG_ARCHITECTURE_V1.0.md)。

| 能力 | V1.0 必须交付和验证的范围 |
| --- | --- |
| 查询与对话 | 单轮聊天、连续会话及 SIMBAD、ADS、Gaia DR3；保留工具错误、实际参数和来源 |
| 项目与数据 | 会话归属、命名快照、单工具重跑、比较、项目总览及用户显式关联 |
| 固定科研流程 | 名称/坐标→Gaia 候选源与图表；ADS 单页检索与摘要证据表；可检查步骤和显式恢复 |
| 本地知识库 | 用户上传的文本型 PDF / UTF-8 Markdown、词法检索、摘录及页/行定位；不自动传给模型 |
| RAG 知识问答 | 用户明确选择项目文献后，混合检索、基于证据生成回答、逐条引用和原文回查；证据不足时拒答 |
| 数据库与首次配置 | PostgreSQL 管理业务数据，pgvector 保存向量；提供初始化、状态、索引构建、故障提示、备份与恢复 |
| 导出与备份 | 单轮数据/图表 ZIP、项目归档、数据库一致性备份、独立目录恢复及完整性核对 |
| 稳定交付 | 支持矩阵、用户手册、版本化 API / 数据契约、迁移和兼容性记录、独立验收及已知问题 |

V1.0 不承诺多人、公网部署、生产级身份权限、云同步、队列、自动恢复长任务、OCR、远程全文检索、任意代码/SQL 执行、自动全文下载、Zotero 写入或自动科研结论。V1.x 可按需求分别立项；V2.0 的多用户与生产运行仍另行设计。

## 3. Gaia 超时：诊断、修复与验收

### 3.1 现状与诊断原则

现有 Gaia 代码固定访问 ESA `gaiadr3.gaia_source` 同步 TAP，使用有界连接/读取超时、固定查询模板和响应大小限制。`GAIA_TIMEOUT_SECONDS` 默认 20 秒，连接/读取限制不是整个聊天的总耗时保证。保留固定服务、TLS 校验、有限字段/行数和错误降级，不能为了通过测试无限增加等待、吞掉异常或伪造结果。

先做分层、可复现诊断：记录系统、时间、运行环境、代理配置是否存在（不记录密钥或代理认证信息）、DNS 解析、TLS 连接、能力端点与固定最小真实同步查询的 HTTP/错误和耗时；分别记录 Windows 与 Linux 的结果。诊断使用受控超时和固定无敏感输入，不把健康检查成功当查询成功。能力页、网络工具和应用的测试分别保存，避免将其中任一结果推断为另一项通过。

对能确认的失败阶段再检查：请求参数与服务协议、固定 ADQL、响应解析、超时/取消、代理与证书、网络路径或服务端实际状态。只根据直接证据描述原因；无法区分时标记“根因未确定”。修复前保留失败记录及原始安全错误，修复后对目标代码复测。

### 3.2 变更决策

优先修复经证据支持的应用缺陷；网络或服务异常则保持用户可理解的失败和可重试状态，并在网络恢复后复验。若考虑备用服务、异步 TAP 或不同超时策略，先核对官方端点、数据发布版、表、字段/单位、查询语义、隐私和失败边界，补写独立设计与测试；不因 SIMBAD 已有镜像就假设 Gaia 存在可互换镜像。是否变更服务地址由实际证据决定，不能让用户输入任意端点。

任何修复都必须保留精确 DR3 `source_id` 字符串、圆锥范围、固定列、真实 ADQL、UTC 时间、单位、截断/溢出及 `total_found` 未知语义。名称→Gaia 仍需本次 SIMBAD 真实坐标，失败即停止依赖步骤；已有成功工具结果在部分失败时保留。

### 3.3 V1.0 退出条件

在当次目标环境显式执行真实 Gaia 精确源与圆锥查询、质量筛选、名称→Gaia、三工具联合查询、固定流程、导出/引用链路，并记录实际请求条件、来源、状态及耗时；各项按原断言独立报告。离线替身、单一能力接口、截图或旧版成功不能替代真实查询。超时降级也须独立覆盖。

**V1.0 默认要求真实 Gaia 成功路径通过。** 若届时仍受外部条件阻挡，保留失败报告和未完成项；只能由用户在了解当次证据和影响后另行决定是否带限制发布，且不得将失败改为通过。

## 4. 稳定功能与科研边界

### 4.1 查询、工作流与对话

原 `POST /api/v1/chat` 继续无状态；会话聊天按既有预算和历史窗口执行。V0.7 两个固定模板仅执行固定步骤，不执行文献中的指令或模型生成代码。流程成功、单次查询状态与图表/导出状态分别显示；缺失输入、失败、跳图、中断和继续条件必须可见。

Gaia 圆锥结果是位置候选源，不能直接称为星团成员；统计只针对实际交付行。视差负值或零值为测量的一部分，条件式倒数距离是程序近似，保留质量筛选、未校正与适用性说明。ADS 证据表只基于实际书目与摘要，不宣称阅读全文或穷尽文献。

### 4.2 知识库与项目关联

V0.8 的本地词法检索和摘录式回答继续使用用户选定的 PDF / Markdown；保留原文件版本、哈希、PDF 物理页或 Markdown 行号、提取警告及删除后失效语义。扫描件未 OCR、复杂排版/公式/表格的提取不保证完整；检索命中不等于支持科学命题。

V0.9 的 `user_reference` 是用户显式关联，不能提升为“支持/反驳/因果证明”；本地原文不因关联而自动发送给模型。页面区分数据库测量、原摘要、用户文献原文、用户备注和模型文字。外部文献、工具结果及归档内容只作数据，不执行内部指令。

V1.0 新增独立的知识库问答入口：用户主动选择项目与文献范围，先看到将发送给所选模型服务的具体片段，再明确同意本次生成。默认嵌入和索引在本机运行；缺模型或取消授权时仍可使用原有词法检索与摘录。未经核对的模型总结不能冒充文献原话，回答中引用可返回固定文件版本及页/行。完整设计、索引一致性和验收标准见 [RAG 与数据库设计](RAG_ARCHITECTURE_V1.0.md)。

### 4.3 原始数据与可复查性

所有查询保留真实条件、时间、服务来源、错误、缺失值、截断与交付数量。项目和流程中的引用需固定到具体版本及位置；删除、移动、导入和仅元数据恢复时正确显示失效，不跳转到同名新对象。哈希只验证字节一致性，不证明来源真实性或科研结论。

## 5. API、数据与兼容契约

以 V0.9 [候选兼容契约](V1_CANDIDATE_CONTRACT.md) 和当次实际 OpenAPI 为基线，整理 V1.0 正式契约。旧 API 族涵盖 `/health`、`/docs`、`/openapi.json`、`/api/v1/chat`、会话及轮次、单轮导出与产物、项目/快照/重跑/比较、固定流程、文档/知识库以及项目总览/关联/归档。保留已有请求必填项、字段语义、错误结构、幂等和修订冲突规则。

实施前保存 V0.9 的 OpenAPI 快照和代表性输入/输出，机器比较字段类型、必填、枚举和状态码，并对高价值旧客户端场景作行为回归。新增可选字段不能改变旧字段的含义；若确需破坏性改动，先写兼容层或新接口、变更原因、迁移文档和对应测试，不能仅更新版本号。

V0.9 基线为 SQLite schema 5，项目归档默认格式 4，支持格式 1–4 导入；单轮导出沿用已有独立契约。V1.0 以 PostgreSQL 为运行时唯一业务数据库，从旧 SQLite 数据库一次性只读迁移；不在 V1.0 运行时维护 SQLite 回退或双写。迁移前冻结旧库并制作一致性备份，导入独立的新 PostgreSQL 数据库，逐项核对计数、关系、JSON、文件字节/哈希、来源、失效状态与配额；失败时保留旧库并回滚目标导入。回到 V0.9 时恢复迁移前备份，V1.0 期间的新数据不会自动回写，必须明确告知这一回滚边界。新 schema 与归档版本在实现前固定；兼容旧格式导入，不能静默丢弃任何历史。向量索引为可重建派生数据，不是原文的唯一副本。

完整备份需明确包含用户原文并由用户确认；仅元数据备份恢复后应标记原文不可用，允许按原哈希和位置契约验证后恢复。导入创建独立副本、正确重映射所有 ID 并保留 `imported_unverified`；不执行归档内链接、流程或模型请求。保留现有包体和业务预算限制，超限明确失败，不返回半包或自动删除旧数据。

## 6. 支持矩阵、安装与数据维护

V1.0 最终支持矩阵以当次实际验收为准。候选目标为 Windows 和 Linux、Python 3.12+、Node 24.15+ 的受支持 24.x、Chromium 与 Windows Edge；精确 OS、Python、Node、PostgreSQL、pgvector、浏览器与依赖版本应在报告中记录。不能把某个环境的通过写成所有版本或所有 Linux 发行版均已验证。

知识库需要 PostgreSQL 的词法检索及 pgvector 能力；中英文和短中文检索必须经评估验证，不能假设默认分词器等价于旧 FTS5。PDF 解析需对应平台的子进程资源保护。数据库或扩展不可用时应明确诊断，不得退回其他数据库冒充正常。用户手册需覆盖 PostgreSQL 与 pgvector 安装、连接和权限、前后端独立安装、配置、启动/停止、无模型密钥可用范围、API 文档、首次项目与示例流程、证据检索和故障排查。仅运行本机单 worker，不将监听到所有地址描述为安全部署。

V1.0 增加首次使用向导和设置页面：检查 PostgreSQL 连接、权限及 pgvector、嵌入模型、数据库磁盘预算、模型服务配置和外部服务连通性；解释凭据仅保存在服务端以及 RAG 文本发送范围。用户可配置数据库连接、显式初始化/重建向量索引、查看模型与索引状态、备份和恢复。各步骤应显示进行、成功、失败及可执行的下一步；数据库已配置但无模型密钥时仍可管理数据和查看本地摘录。

首次迁移前对 V0.9 旧库使用 SQLite 一致性备份并验证可读；V1.0 正常备份/恢复采用 PostgreSQL 一致性备份工具。现有 `scripts/manage_data.py` 是旧 SQLite 工具，须扩展或提供新的 PostgreSQL 工具，不能直接宣称支持 PostgreSQL。完整数据库备份/恢复与项目 ZIP 是不同用途，须分别演练；恢复不得覆盖用户已有目标。卸载说明区分程序、数据库服务、原文、备份和用户下载文件，默认保留数据。

## 7. 评估与验收方案

按用户与项目现有约定：**开发阶段不主动运行测试，发布前由用户安排测试验收**。以下为实施与当次验收计划，本文编写不启动服务、不操作个人库、不触发联网或模型调用。

### 7.1 本地回归与故障

- 在隔离数据库运行后端离线测试、Ruff 检查/格式和依赖检查；回归旧 API、幂等/修订、来源、科学规则及失败降级。
- 前端依次完成锁文件安装、类型检查、lint、单元、构建与 OpenAPI 类型契约；浏览器覆盖 Chromium / Edge、桌面与 390px 窄屏、键盘、断线、长文本、所有关联目标和失效恢复。对截图逐张人工核查，记录实际覆盖范围。
- 使用临时服务和合成数据完成聊天→项目→两类流程→导出→知识检索→显式关联→完整备份→独立恢复→原文定位；核对完整字段、数据版本、哈希和来源，结束后确认服务及端口清理。
- 单独覆盖请求/存储限额、解析子进程保护失效、恶意和损坏归档、未知 schema、事务中断、索引缺失、重复请求及部分写入回滚；不能以少数成功示例称为全部边界穷尽。

### 7.2 安装、迁移与灾备

在列明环境的 Windows 与 Linux 干净或隔离环境分别安装 PostgreSQL / pgvector、源码与前端，检查数据库权限、扩展可用性和平台能力；从 SQLite schema 5 的脱敏/合成样本迁移至空的 PostgreSQL 数据库，核对原记录及迁移前备份，注入失败验证目标回滚和原库不变。

独立演练数据库备份恢复、格式 1–4 项目导入、格式 4 完整/仅元数据恢复和允许的旧格式导出，逐项检查会话、完整快照、流程、文件哈希、引用、失效状态和 ID 映射；对已存在目标拒绝覆盖。若 V1.0 实际新增格式，按第 5 节增加对应测试。不要使用个人日常数据库或将其归档到仓库。

### 7.3 文献检索和科学评估

固定独立评估集及人工标注，覆盖中英文术语、单/双字中文、无答案、空页、扫描件、复杂排版、引用版本与失效、同项目隔离；至少包含多篇可合法使用的真实文献和合成边界数据，明确来源与许可。标注人员优先通过原文独立确定页/行与预期，不能仅以同一提取器的结果作为真值；无法独立标注的条目单列。

另按 [RAG 评估契约](RAG_ARCHITECTURE_V1.0.md) 分别检查词法、语义、混合检索及生成问答：记录召回、引用有效性、回答可追溯性、拒答、提示注入、隐私和延迟；生成正确性需独立人工评估，程序检查引用 ID 存在不能证明结论被文献支持。

在运行前固定数据集版本、预期、覆盖率/拒答率/无效引用等指标、分母和门槛；分别报告合成和真实材料、解析失败及人工抽查结果。不能用相关片段数量推断结论正确，也不能把两篇论文的旧试评外推为真实文库表现。保留可公开的题目、哈希与报告，不提交未经许可的论文全文或私人数据。

### 7.4 真实外部服务

真实联网显式开启，分别检查 SIMBAD、ADS、Gaia 精确源/圆锥、名称→Gaia、三工具联合与两个固定流程，随后检查来源、快照、图表和归档。需要模型或 ADS 凭证的场景单列并记录费用及失败；不将没有凭证或外部超时默默标为跳过成功。该组检查与默认离线隔离，每次记录实际环境、时间、目标提交和服务来源。

### 7.5 问题处理与证据

建立问题台账，记录复现、影响、状态、修复提交、验证和规避方法。阻断安装、数据丢失、静默数据损坏、凭证泄露、错误归属或伪造科研来源属于发布阻断；其他遗留问题须标明适用范围与风险，由用户在当次发布决策中知悉。无法确认根因的外部问题保留原错误与复验计划。

记录至 `docs/test-records/v1.0.0/<类型>/<UTC时间>/`，包括本地、浏览器、迁移/备份、检索评估、联网、图表和发布审计；每次新建目录并保留失败。不得将真实密钥、私人会话或未经许可的全文写入报告、源码或发布文件。临时服务的 PID、端口与退出情况应有直接证据。
