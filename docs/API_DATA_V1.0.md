## 数据库与兼容层

运行入口只创建 `PostgresRepository`，schema版本固定为6，由 `astroagent_meta` 保存。未配置、连接失败、缺扩展或未知schema均明确失败；不创建或打开日常SQLite，不双写、不自动迁移旧库。首次建表必须在设置页确认，目标已有业务表时拒绝初始化；已经初始化的schema6仅恢复中断状态，不重新创建表。

连接串仅服务端配置，限localhost/127.0.0.1/::1；会话级advisory lock限定单进程，事务级锁串行化应用写入。读取事务使用repeatable read，写入使用read committed并先取得应用锁。旧业务记录继续保存原JSON与字节；内部SQL适配层只接受程序固定SQL，替换占位符、JSON读取和二进制类型，不处理用户SQL。内部插入顺序列不进入原API或归档。

SQLite仓储保留给旧版本备份/迁移和明确的旧契约测试替身，生产入口不会选择它。普通旧API测试与旧浏览器fixture不因此成为PostgreSQL运行时验证；专用PostgreSQL集成另列。

词法检索改为PostgreSQL `simple` 全文候选与CJK子串，再校验NFKC/casefold、全部词匹配、字边界、原文与位置；保留旧词法接口的摘录语义，但不能声称与SQLite FTS5的中英文排序等价。新算法标识 `nfkc-pg-simple-cjk-substring-v1`，此变更必须独立回归与评估。该实施选择使用 [PostgreSQL全文检索](https://www.postgresql.org/docs/current/textsearch.html) 与 [pgvector](https://github.com/pgvector/pgvector) 官方接口，未在本轮连接服务器验证。

## 新接口

已有聊天、项目、会话、流程、知识库、关联与科学导出入口保留；RAG不修改 `ChatResponse`，不因用户关联而自动向模型发送文献。所有下列接口仍受原Host/Origin、JSON接收与安全错误规则约束。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/v1/setup/status` | 无凭据的配置/数据库状态，不访问科研服务、不加载模型 |
| POST | `/api/v1/setup/initialize` | `confirmed:true`后在配置的空本机库建schema6及扩展 |
| GET | 项目`/rag/status` | 索引代、活动代、问答数量、全库向量预算 |
| POST | 项目`/rag/indexes` | 项目修订、请求UUID及确认；同步本地构建，无开放任务队列 |
| DELETE | 项目`/rag/indexes/{id}` | 确认删除该代，保留原文和问答；活动代删除后只剩词法检索 |
| POST | 项目`/rag/previews` | 问题/文档/版本/历史范围，本机双路检索并保存固定发送预览 |
| DELETE | 项目`/rag/previews/{id}` | 取消预览，不调用回答模型 |

字段机器契约见生成的 [OpenAPI](../frontend/openapi.json)。生成接口文件不等于类型检查、契约比较或测试通过。

2026-11-02 待验收扩展：新预览记录 `RetrievalTrace.version=pg-rrf-v2` 和可空的 `embedding_cache_hit`。旧 trace 仍默认为 v1 / 缓存未知。单个 ASCII 英文词或编号没有原文字面匹配时，预览为 `no_results`、`semantic_status=literal_query_unmatched`，提示补充上下文，不视作已证明文献无答案；完整自然语言和中文问题仍可做纯语义检索。缓存仅复用同项目/模型/维度/问题的向量，模型身份、文献范围和引用状态仍逐次核对。schema6 与格式5成员不变，新旧 trace 兼容边界见 [改进说明](development/v1.0.0/ACCEPTANCE_IMPROVEMENTS.md)。

## 索引与确认

索引按项目当前可用文档形成不可变代，记录模型名称/整目录文件SHA-256、维度、归一化、源分段摘要和时间；状态为pending/running/ready/failed/stale/interrupted。CPU计算不持有数据库事务；全部分段核对通过后短事务写向量并切换活动代。失败保留旧活动代；来源变化后旧代停止被查询。向量不是权威原文，不放进项目ZIP。

索引不支持用户Python、远程自定义模型代码或自动下载。模型由显式维护工具按固定Hub提交准备，运行时固定本地文件哈希；子进程只允许已知Sentence Transformers模块、禁用远程代码/联网并优先safetensors权重。CPU工作进程限120秒、3 GiB和固定输出；同一进程最多一项嵌入任务。文件SHA验证身份，不能认证模型效果或学术结论。实际模型/平台资源适配尚未验证。

检索每路最多20候选，RRF k=60融合最多8段；余弦距离上限初值0.65，可通过服务端配置，属于待评估参数。默认当前版本，可显式选择保留历史版本；该版本无向量覆盖时显示降级。部分解析、未索引、模型缺失、向量失败和无结果分别标记，不能把单路结果称为完整双路成功。

预览保留10分钟，固定问题、服务、模型、系统协议摘要、具体证据、历史和索引参数。用户确认令牌后再次校验项目、文件版本、摘要和位置；确认内容或模型变化时409要求重新预览。生成中先持久化running及64 KiB预留，再发起一次模型请求；服务重启只记interrupted，原编号重放只读取结果，不自动重试不确定调用。

回答要求普通文本与本次E1–E8标签，未知/缺失/不一致引用、截断或模型表示不足时不展示未核对正文。程序只验证引用身份及原文可用性，不证明每句话被引用支持；回答忠实度须独立人工评估。问答保存检索算法/模型摘要、问题/范围、引用身份、历史ID、模型/供应商版本、时间及确认摘要；不复制原文正文到问答记录，查看时重新从权威原文核对。

删除或替换文档时撤销预览、停止旧索引检索并清理相应向量；历史问答保留模型文字并显示失效引用，不改指向新文件。这不意味着已导出的回答、旧备份或数据库空闲页被安全擦除。

## schema6 与格式5

新增 `rag_indexes`、`rag_active`、`rag_vectors`、`rag_previews`、`rag_answers`、`rag_answer_requests`。业务预算仍256 MiB，包含原始文件、文本、JSON、操作预留及词法GIN索引；模型目录默认2 GiB、向量载荷及索引默认128 MiB另列，不自动扩容。物理数据库、事务日志、备份和临时文件还需额外磁盘空间，业务预算不是整个磁盘上限。

每项目最多100条问答、1000条生成请求记录、100次索引操作、20份未过期预览。问答删除保留最小操作历史，禁止旧键重新调用；清理索引代不删除原文，重建时需容纳新旧两代。不自动删除用户数据腾空间。

默认项目格式5：旧格式4的七成员增加 `rag.json`。保存问答、生成请求及固定引用身份；不导出未确认预览、向量或模型文件。格式1–4导入后无RAG记录；格式5重映射问答、操作、历史与软引用ID，保持imported_unverified。完整/仅元数据继续作用于知识库原文件：仅元数据包仍可能包含用户问题、模型解释、旧聊天和检索词，不是匿名化备份。缺原文时引用不可用，向量需明确重建。

有问答或请求历史时拒绝格式1–4导出；有V0.9关联历史继续拒绝更早格式。保留32 MiB压缩、128 MiB展开、64 MiB单成员和固定成员/严格JSON/哈希/引用/原子导入边界。整库PostgreSQL备份另用维护工具，不能把项目ZIP当数据库灾备。
