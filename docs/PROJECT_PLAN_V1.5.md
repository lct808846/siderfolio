## 1. 当前行为与设计范围

当前会话创建默认为“新会话”；首轮问题提交时，服务端的 `conversation_title()` 依据用户输入生成标题，使用 `metadata_revision` 处理后续修改。用户可以在侧栏手动重命名。普通聊天模型及 SIMBAD、ADS、Gaia 工具调用仍由既有 Agent 路径处理；V1.0 文献嵌入模型是检索用模型，与本版用于生成文本的 4B 小模型是两个独立组件。

本版首期交付：

1. 可选安装和配置本地千问 4B 推理服务，提供本机状态、模型身份和资源提示。
2. 新会话首条用户问题提交后异步生成简短标题；失败时保留已有规则标题，聊天继续进行。
3. 从用户问题中提取明确给出的查询条件，并给出任务类型建议；建议需经程序校验，缺失或歧义时追问。
4. 在界面提供明确的轻量文本操作：对用户选定文本进行**拟标题、抽取式简短摘要、原文格式整理**。用户主动选择操作和输入范围，结果供查看、复制或再次编辑。
5. 本地模型开关、运行状态、超时/失败提示，以及清晰的本地/远程任务边界。
6. 使用 Docker Compose 部署完整项目，持久化数据库和模型，保持 RAG、科研查询和隔离绘图的完整使用路径；详见[项目容器化部署方案](CONTAINER_DEPLOYMENT_V1.5.md)。

“简单事务”首版包括上述条件提取、任务类型建议和明确列出的文本操作，不包含根据模型猜测自动执行文件操作、删除/发送、运行代码、自动调用科研工具，或直接给出需真实查询支持的天文测量结论。不得用小模型记忆冒充数据库结果，不将它自动作为科研查询或 RAG 的可靠性保证。

## 2. 模型选择与运行方式

2026-11-09 实施补充：实际采用已下载的 **Qwen3-4B-Instruct-2507 / Q4_K_M**，Ollama 0.40.15 已安装在D盘并离线注册；注册摘要、路径及默认8192上下文见[实施记录](development/v1.5.0/IMPLEMENTATION.md)。以下“初步”文字保留选择阶段背景；性能与质量仍未实测，不能将安装注册视为评估通过。

初步候选 **Qwen3-4B-Instruct-2507**，属于约 4.0B 参数的非思考模式指令模型；以 [Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507) 为准。本版候选不代表用户已确认具体千问代际、量化方式或权重来源；需对中文标题、文本质量、硬件占用、许可及加载速度实际评估后锁定。模型标称上下文长度不等于本项目可在目标机器上使用该长度。

初步采用 **Ollama 本机推理服务**，由 AstroAgent 后端通过 `127.0.0.1` 请求本地 API，前端只与 AstroAgent 交互。Ollama 的 [`/api/chat`](https://docs.ollama.com/api/chat) 和 [结构化输出](https://docs.ollama.com/capabilities/structured-outputs)可作为接口依据；具体版本、模型标签、量化文件、模型摘要与 API 支持需在目标机器核实后固定，不能把示例标签当作已经安装或已验证兼容。

实施 M0 只读检查操作系统、CPU、可用内存、GPU/显存、磁盘、已有 Ollama/模型与现有服务，不打印敏感配置；按真实条件比较 CPU 和 GPU 推理以及量化质量。下载体积、运行内存、延迟、显存与许可证以所选具体权重和实测为准，不提前给出性能保证。模型和缓存放在用户可配置的数据目录，不写入源码、个人数据库备份、Git 或发布包；不自动覆盖已有 Ollama 配置。

默认关闭自动下载和自动启动服务；首次设置显示来源、模型/量化标识、预计体积、存储路径和资源需求，由用户明确触发下载。支持用户已有本地模型；离线模式不得偷偷下载或切换远程模型。模型仅用于本地计算，不让 Ollama 调用工具或执行代码。

## 3. 会话自动命名

### 3.1 触发与内容

新建会话的首条用户消息成功持久化后，继续沿用规则标题作为立即可见的兜底；在该轮正常响应路径之外提交一次低优先级命名任务。输入默认仅为首条用户消息的有限前缀（最多2000字符且4 KiB）；不发送完整会话、数据库原始结果、论文全文或密钥。模型标题目标8–14字符，严格4–18字符；汉字、字母、数字和标点均计1字符，规则兜底同样最多18字符。长编号无法容纳时以对象类别和任务概括，可省略但不能截成另一个编号；短对象名称优先保留。人工改名仍使用原80字符契约，不批量改写旧名称。

模型返回经约束的 JSON，例如 `{"title":"M45 自行与候选源"}`。后端严格解析，仅接受单行纯文本、去除前后空白和多余引号、拒绝空值/控制字符/超长/包含提示词或明显错误格式。内容不可信，界面按文本渲染。无法生成合格标题时保留原规则标题，不改为凭空虚构的天体或论文名。

### 3.2 竞态与覆盖规则

请求创建时记录会话 ID、首轮 ID、原规则标题、`metadata_revision`、任务 ID 与输入摘要；完成时在数据库事务中原子核对：会话仍存在、首轮未变、当前标题仍等于本次规则标题、元数据修订号未变、用户未手动改名，且任务仍为该会话有效任务。全部成立才更新标题并递增修订号；否则丢弃结果并记录 `superseded`。即使用户后来把标题改回原文字，也不能覆盖其手动操作。删除或重新归档会话后结果不能写入错误对象。

用户在侧栏手动改名永远优先；自动任务失败、中断、服务重启或响应重复不会覆盖用户标题。按用户最新要求，命名与科研查询并行开始，首轮结果写入完成状态和返回前同步收束命名：优先使用已生成标题；若尚未结束，额外等待不超过本地模型超时且最多60秒。等待超限或首轮失败则采用现有简短标题并废弃迟到结果，不能在结果展示后继续跳名。多标签页按元数据修订处理，不以旧缓存覆盖新标题。旧会话不批量改名；重命名弹窗仅保留人工输入与保存，移除单独的本地模型标题建议按钮和接口。

### 3.3 失败与恢复

默认本地模型不可用、未下载、超时、输出无效或资源繁忙时，标题维持既有规则结果，状态显示可理解的提示；不自动把文本发送到远程模型。重启后未完成任务标记 `interrupted`，不自动批量重放。服务仅允许一个命名/文本推理任务运行，队列满时丢弃自动命名并保留兜底，手动任务明确提示忙。取消或浏览器断开不等于推理已停止；不因此重复启动任务。

## 4. 轻量文本操作与路由

### 4.1 首期：查询条件提取与任务类型建议

查询条件提取输出严格 JSON：天体名称或编号、坐标、半径、年份及用户明确提出的筛选等；每项同时保留原文依据和单位，缺失或含糊标为 `null` / `ambiguous`，不得补造坐标、半径、年份、质量筛选或查询结果。例：“查 M45 附近 5 角分的 Gaia 数据”只提取名称 `M45` 和半径 `5 arcmin`；坐标仍需实际 SIMBAD 查询。

任务类型建议仅限 `object_query`、`literature_search`、`gaia_query`、`plot`、`knowledge_search`、`other_or_unclear`；多意图可返回多个建议，无法判断时返回 `other_or_unclear`。建议用于展示或辅助主模型理解，不能直接执行查询、绘图、文件操作或发送数据，也不能作为跳过工具校验、用户确认及科学来源要求的依据。后端校验 JSON、枚举、字段类型和原文依据；格式错误、服务不可用或可信度不足时丢弃建议，由现有路径处理或向用户询问。模型自报置信度不能作为真实性证明。

### 4.2 第二批候选

在首期评估后再单独设计并决定是否纳入后续版本：生成 ADS 检索词、根据已有摘要整理研究对象/方法/关键词、格式化实际结果、提取绘图需求，以及用户笔记改写。用户需能核对实际检索式；摘要整理明确标注“基于摘要”、缺失留空；结果整理保留原数值、单位和来源；绘图需求不能猜测列或单位。候选并非 V1.5 已交付功能，具体版本取决于评估和后续决定。

### 4.3 执行边界

首版通过用户显式选择进入本地文本操作，且页面标注“本地模型生成，需自行核对”；输入可来自用户粘贴文本或明确选定的当前会话文本。输出需提示可能遗漏信息，不能自动保存、替换原对话或执行生成内容；科学数值、单位和来源应按原文保留，无法确认时说明不确定。

路由由程序基于显式操作选择控制，不把所有自然语言交给小模型自行判断后执行。普通聊天、SIMBAD/ADS/Gaia 查询、绘图工具、RAG 文献问答继续走原有路径和授权，联网/数据库相关任务不能因为“小模型认为简单”被静默截获。用户选择本地轻任务时缺服务返回可恢复错误；不自动调用远程模型或产生费用。模型调用不包含任何工具定义，输出不能授权网络请求、访问本机文件、修改项目或控制其他服务。

## 5. 配置、接口与持久化

候选配置由服务端提供：本地功能开关、服务地址、模型标签、连接/总超时、输入/输出上限、并发和队列上限；具体变量名与默认值在实现时核对并写入 `.env.example` 和设置页面。原生模式仅允许明确的本机回环地址；容器模式只允许经服务端配置的固定内部服务地址，具体安全边界见[容器化方案](CONTAINER_DEPLOYMENT_V1.5.md)。两种模式均拒绝重定向及来自前端的任意服务 URL。调用前检查配置与服务状态，不在请求日志、错误或测试报告写入对话内容与密钥。

可新增独立的本地模型状态/建议标题/文本操作接口，实际路径和响应在实施时写入 OpenAPI；默认不改变旧聊天和会话创建/改名协议。状态区分 `disabled`、`unavailable`、`model_missing`、`ready`、`busy` 和错误；状态检查不能隐式下载模型。自动命名状态及错误使用有界持久记录，必要时增加 PostgreSQL 迁移；升级前一致性备份，迁移失败回滚，旧库/旧客户端兼容并记录回退边界。个人会话和模型文件不进入源码、公开测试数据或发布资产。

异步任务实现需明确后端单 worker 的生命周期、退出清理、任务超时与全局资源限制；推理在网络调用/等待期间不持有数据库写事务。状态/任务 API 不得泄露完整问题，页面隐藏内部路径和异常堆栈。用户可在设置中关闭自动命名，并可随时手动改名。

## 6. 项目整体容器化部署

V1.5 将采用 Docker Compose 作为个人本机部署入口，协调前端、FastAPI 后端、PostgreSQL + pgvector、本地 Ollama 推理服务和专用绘图执行组件。数据库及模型数据独立持久化，RAG 嵌入模型只读挂载；默认只向本机发布网页端口。数据库初始化、已有数据迁移和模型导入均由用户明确执行，不覆盖现有数据。

容器内的回环地址不能指向其他容器；前端代理、后端本地模型地址和 Host/Origin 校验需要按固定服务身份适配，不能简单放开校验。现有绘图使用 Docker 创建隔离任务，容器化后必须通过专用执行组件实现受限调用，不能将宿主 Docker 控制接口直接交给 Web 后端。若安全执行边界未完成，绘图必须显示不可用，项目整体部署也不能视为完整验收通过。服务划分、数据与备份、资源、安全、实施和验收要求详见[容器化部署方案](CONTAINER_DEPLOYMENT_V1.5.md)。

## 8. 测试与验收计划

遵循项目现有约定：开发期间不主动运行测试，由用户安排发布前验收。本轮只使用用户已下载的安装程序和权重完成环境准备、离线注册及身份读取；没有发起模型推理或质量/性能测试。以下为待执行计划。

- **离线与兼容：** 使用本地推理替身验证首条消息标题、错误 JSON、空/超长输出、超时、禁用、服务不可用及模型未下载；既有聊天、RAG、绘图和手动改名回归不触网。
- **竞态：** 模型执行中手动改名、改回原字、删除会话、多标签页修改、重试、重启、重复回包；验证只在元数据修订和身份均匹配时更新，绝不覆盖人工标题。
- **安全边界：** 原生模式校验拒绝非回环地址，容器模式校验仅允许固定内部服务目标；两种模式均检查重定向、外部工具调用、文档/用户内容中的指令和异常日志泄漏，验证未配置或失败时不会调用远程服务。
- **真实本机：** 记录硬件、模型精确身份与量化、资源、冷/热启动耗时、单次生成时间、内存/显存、并发下聊天体验和实际下载体积。CPU/GPU 支持分别记录，不能根据参数规模推断设备可用。
- **质量评估：** 预先固定至少 50 条中英文/混合问题与人工标准，覆盖天体名、编号、长文本、歧义、个人信息、恶意指令；统计标题格式合格率、主题保留、虚构/不恰当内容、人工接受率和失败率，分别比较现有规则标题。轻任务另测信息保真、数值/单位保持与不支持操作。门槛在测试前确定，人工复核独立记录。
- **条件提取与建议：** 独立标注包含 M45、坐标/单位、缺失半径、相对年份、多个工具及模糊对象的输入；逐项评估原文依据、字段准确率、遗漏和虚构率、多意图建议与无法判断处理。断言建议本身不会触发工具调用，错误建议不会改变原有科研工具校验与执行路径。
- **浏览器和恢复：** 使用隔离数据库在桌面与窄屏检查自动标题更新、手动覆盖、关闭开关、缺模型状态、轻量操作及重启恢复；不访问日常会话库或将私人文本归档。
- **整体容器部署：** 按[部署验收清单](CONTAINER_DEPLOYMENT_V1.5.md)检查干净环境部署、数据持久化与备份恢复、RAG、小模型、科研查询和 Python/Gnuplot 绘图预览与保存；验证服务故障与隔离安全边界。仅容器启动成功不算完整验收。

每次证据保存于 `docs/test-records/v1.5.0/<类型>/<UTC时间>/`，保留失败和覆盖范围；本地检查、目标提交及标签 CI、模型身份和来源、密钥/私人数据扫描及当次用户授权仍为发布门槛。
