# AstroAgent V1.1：观测日志界面重构

**日期：** 2026-11-02  
**状态：** `1.1.0.dev0`，本轮界面源码已写入，未验收、未发布  
**范围：** 个人科研工作台的视觉层级、导航可读性和窄屏体验；沿用已有查询、RAG、数据库与归档契约。OpenAPI 仅同步开发版本号。

## 设计方向

目标用户需要在天体查询、文献和测量结果之间反复核对。界面采用“观测日志”：低饱和纸色承载正文，深绿色区分全局导航，细线与编号组织操作，少量暖色标记可操作或需要关注的内容。中间突出当前任务，左右分别承载会话与证据；不使用虚构观测数据作为装饰。

后续根据用户“过于简陋，希望增加高斯模糊或毛玻璃”的反馈，在此基础上增加玻璃质感：静态柔和渐变作为背景，深色半透明导航、浅色磨砂侧栏、细高光边缘、浮起的输入区和分层阴影。正文与科学表格保持接近实色的阅读底；不模糊文本或原文图片。设计重点是面板之间的空间和材质区别，而非增加装饰数据。

字体精修使用本机已有的可变字体：Noto Sans SC负责界面和正文，Noto Serif SC点缀大标题，Bahnschrift用于品牌及小标题，Cascadia Mono用于编号、代码与科学数据。统一字重、字距和行距，数据数字使用等宽排布。字体仅从本机加载，不请求远程字体服务；其他机器缺少字体时使用系统字体回退，实际呈现需分别验收。

用户要求界面体现专业性：文案采用明确的科研功能描述，优先展示任务、数据状态、单位和来源；减少诗意标语、装饰轨道及无数据的模拟图表。专业性以清晰、准确和可核查为标准，不以深色背景或复杂装饰代替。

与之比较的两个备选方向是强调空间和仪器感的“星图控制台”，以及以阅读、文献引用为中心的“论文工作台”。本轮先选观测日志，以兼顾查询、长文本阅读和结果核查。

首次范围为共用视觉样式、工作台空状态、会话侧栏、输入区与结果区，并让项目和知识库等使用相同视觉变量。保留原有路由、已有结果、错误提示、导出和用户确认流程。不得将模拟数据或服务不可用状态描述为科研查询成功。

后续根据DeepSeek与ChatGPT参考截图，查询工作台调整为对话优先：默认收起结果，允许折叠会话栏，压缩头部、空状态和输入框的占用；正文最大宽度1120像素。工作台在980/981像素切换整页面板与侧栏，1440像素起允许结果并列；其余工作区继续使用原有规则。源码实施及未验收边界见 [布局说明](development/v1.1.0/CONVERSATION_LAYOUT.md)。

## 本轮实施范围

- 全局导航复用同一组件，提供查询工作台、项目归档、本机设置与接口文档。进入具体项目后，直接切换项目记录、来源关联、科研流程、本地知识库和文献问答；标明当前入口。
- 项目、知识库等工作区在1200 CSS 像素及以下使用独立面板切换，保留各面板实例与输入状态；项目列表不再挤占项目记录。主查询工作台以后续对话优先布局为准。头部按内容决定高度，适应项目导航及小屏换行。
- 各面板切换使用原生按钮并标明选中状态，保留键盘焦点样式；项目导航在窄屏可横向滚动。
- 知识库、流程、问答证据和设置页沿用纸色、深绿导航和细线层级；保留真实原文、版本、单位、科学限制及发送前确认。
- 新增统一玻璃样式层，覆盖导航、宽屏侧栏、输入区与弹窗背景；圆角、边缘高光和阴影同步调整。背景使用静态渐变，未增加图像资源、动画光斑或依赖。小屏关闭大面积面板模糊；不支持背景滤镜、系统要求减少透明效果或强制颜色模式时有对应样式，实际显示与性能尚待验收。
- 设置页区分状态未确认、读取中和已返回状态。读取失败时撤下旧就绪信息，避免把未知状态说成未配置或仍就绪；显示最近成功读取时间。填写配置不等于模型或外部服务已验证。
- Python 开发版本为 `1.1.0.dev0`，前端为 `1.1.0-dev.0`；仅标明开发进度，不生成稳定标签。数据库仍为 schema6，项目包仍为格式5，无需本轮迁移。
