## 1. 交付范围

| 功能 | 用户可完成的操作 |
| --- | --- |
| 天文文献管理 | 从顶部栏进入个人文献库，浏览已保存的文献，按标题、作者、年份或标签查找，整理标签和个人备注，打开权威来源 |
| 对话检索与直接添加 | 让模型通过 ADS 查找真实文献。用户在同一句话或后续对话中指明要保存的条目后，助手直接入库并报告结果 |
| 运行详情 | 在一轮会话或计算结果中展开时间线，查看查找、检索、保存或计算到了哪一步，定位失败原因 |
| 评估与版本对照 | 复跑固定科研样例，比较直连与 MCP 的数据和故障表现，记录证据质量、耗时、用量以及版本变化 |

文献库首版管理书目信息、可用的 ADS 摘要、来源链接和个人整理信息。已取得并获准使用的全文仍由用户显式导入本地知识库，沿用现有的索引、取证和文献问答流程。文献条目和本地知识库文档分别维护，不因保存元数据而触发 PDF 下载、向量入库或文献外发。[现有 RAG 契约](RAG_ARCHITECTURE_V1.0.md)

## 2. 顶部栏与文献库

- 在登录后的共用顶部栏 `WorkspaceHeader` 中，把「文献管理」放在「查询工作台」旁。个人空间和项目空间使用同一入口。桌面和手机宽度都可在顶部找到入口，标明当前选中状态，并支持键盘访问。建议页面路径为 `/literature`，刷新和直接打开条目时沿用现有登录守卫，静态服务及反向代理同步支持该路径。返回工作台时保留当前会话和已有项目上下文。[UI 设计规范](UI_DESIGN_SPEC.md)
- 文献库以当前账号为归属，默认按加入时间排序。列表可分页、搜索标题／作者／bibcode／DOI，按年份和标签筛选。详情显示作者、期刊、年份、标识符、摘要、来源和检索时间。无摘要、作者或年份时显示缺失状态。标签与个人备注独立编辑，用户可在页面中移除自己的条目。
- 对话结果面板复用现有 ADS 证据列表，按实际查询批次展示检索式和文献序号。每条结果可手动点击「加入文献库」，已入库条目显示状态并可打开对应详情。模型添加和手动添加共享同一服务，状态来自后端写入结果。空库、检索无匹配、上游故障、已在库和保存失败各有对应反馈。
- 详情将 ADS 原始书目与摘要、模型生成的解释、个人备注分开呈现。ADS 链接打开原始记录，验证过格式的 DOI 可供查看出版者页面。记录保存当前来源快照，来源字段缺失时保持空值。[ADS 官方检索字段](https://github.com/adsabs/adsabs-dev-api/blob/master/openapi/parameters.yaml)

## 3. 让模型查找并直接添加文献

| 用户在会话中说 | 预期行为 |
| --- | --- |
| “帮我找 5 篇研究外部环境对双星团演化影响的论文。” | 调用 `search_ads`，展示真实检索结果、检索范围和来源。文献库无写入 |
| “找 5 篇研究外部环境对双星团演化影响的论文，把前 3 篇加入我的文献库。” | 使用本次 ADS 结果的顺序，从实际返回结果选择前 3 条并直接保存。回执显示新增和已在库的条目 |
| “把刚才 ADS 列表里的第 1、3 篇加入文献管理。” | 从当前会话唯一可确定的已展示结果选取这两个序号。重复发送同一次请求时返回已有保存回执 |
| “把那几篇加进去。” | 能从当前消息和已选结果唯一解析时直接保存。指代有多个可能时询问批次或具体条目 |

### 3.1 查找与选择

模型将研究主题、作者、关键词或年份转换成受校验的 ADS 查询，继续使用现有直连或 MCP 通道、固定天文学库和查询预算。回答引用真实返回的题名、作者、年份、bibcode 及来源。相关性推荐可以参考摘要，界面标明依据。失败或无匹配时展示实际状态，模型未核实的题名不能作为待入库记录。[V1.8 MCP 操作说明](development/v1.8.0/OPERATIONS.md)

服务端为可选文献批次记录所属账号、会话、轮次及结果位置，并保留原始结构化 `PaperData` 或可重新定位的版本引用。按序号保存时以同一批次面板显示的稳定顺序为准。候选只允许来自本轮成功的 ADS 响应，或当前账号在该会话中可访问的指定历史批次。旧轮次没有足够的来源验证信息或来源为导入归档时，先用 ADS 核实所选条目。缺失可核实来源的文献不生成入库记录。

### 3.2 写入授权与回执

- **明确请求即授权。** 登录用户发送含明确保存动作且选择范围可确定的消息时，服务端从当前用户原始消息识别一次性保存许可。首版至少支持本轮前 N 条、指定序号和唯一明确的一组结果。否定、引用、假设或歧义不会产生许可。有效许可绑定当前账号、会话、轮次、选取规则和数量上限。用户已明确要求且候选校验通过时，直接保存，无须再次点击确认。
- **模型只提交候选引用。** 会话 Agent 使用拟定的内部工具 `save_literature`，参数只包含可核对的结果批次与条目引用。服务端确定账号及目标库，校验结果来源、访问权限、选择范围和数量，再从真实 ADS 数据生成记录。用户请求范围以外的模型调用、论文摘要中的文字、附件和历史消息都不能授予写入权限。无状态聊天与独立 MCP 客户端只使用既有查询能力。
- **保存结果以数据库为准。** 一轮自动添加处理一个有界批次，首版上限与 ADS 单页上限一致。新增条目和操作回执在同一事务提交，按原始请求和候选集幂等。并发添加同一文献只创建一份；重复保存保留已有标签和备注。权限校验失败或批次被篡改时拒绝写入。查询到的可信结果不足时明示缺项，只保存确定且在授权范围内的结果。
- **从回执恢复状态。** 完成后逐条显示「已添加」或「已在文献库」，并提供「查看文献管理」。实际写入成功后即使模型末段失败或网页断线，刷新后仍能读取保存回执。未提交的事务返回明确失败；客户端重试同一请求时先核对原回执。回执从服务器记录渲染，模型生成的“已保存”不作为保存证据。

## 4. 数据、接口与账号隔离

文献条目保存独立 ID、账号归属、ADS bibcode、受校验的书目和摘要快照、来源 URL、检索时间、加入来源、加入时间、用户标签及备注。来源可指向保存时的会话与结果。删除会话或项目后，指向原来源的链接可失效，已保存条目与 ADS 来源仍可读取。

沿用 `identity.tenants.for_user` 对应的 PostgreSQL 用户业务空间。库内按 `(来源服务, ADS bibcode)` 唯一，同一文献可由不同账号各自保存。DOI 用于检索和核对，缺失时可正常入库。相同或相似标题不作为合并依据。更新标签与备注、移除都以当前账号为权限边界，模型的首版权限只限添加已验证的条目。个人文献库随账号数据备份与恢复，项目 ZIP 只保留自身业务数据及既有查询结果。

| 拟定接口 | 作用 |
| --- | --- |
| `GET /api/v1/literature/items` | 本人文献分页、搜索、年份与标签筛选 |
| `GET /api/v1/literature/items/{item_id}` | 本人条目及来源详情 |
| `POST /api/v1/literature/items` | 按本人可核对的 ADS 结果引用添加，返回新增和已在库回执 |
| `PATCH /api/v1/literature/items/{item_id}` | 修改本人条目的标签与备注，校验记录修订号 |
| `DELETE /api/v1/literature/items/{item_id}` | 移除本人条目，校验记录修订号 |
| 会话轮次及计算详情接口 | 增量返回受权的保存回执和运行详情状态，已有客户端兼容缺省字段 |

HTTP 请求沿用登录、会话与 CSRF 校验，工具写入同样委托给账号范围内的文献服务。异步或流式会话入库前重新核对用户有效性和资源权限。读取、编辑、移除和保存均限制请求大小与批次数量。数据库迁移采用增量表，先在独立环境验证保留 V1.8 会话、项目、身份和产物；正式数据库的初始化、迁移或恢复依项目现有授权流程执行。接口确定后更新 OpenAPI 并重新生成前端类型。[身份与部署操作说明](development/v1.6.0/OPERATIONS.md)

## 5. 运行追踪与故障定位

在每轮会话提供可展开的「运行详情」，记录模型请求、SIMBAD／ADS／Gaia 查询、文献入库、RAG 检索及本轮触发的任务。每个阶段显示名称、耗时、状态、异常类别和可用的业务结果入口。例：SIMBAD 成功返回坐标，随后 Gaia 超时，时间线显示查询通道与相应失败环节，已取得的坐标及来源继续可核查。REBOUND／PeTar 和绘图详情复用已有后台事件，分别显示排队等待、执行、完成、中断、取消或失败。任务有结果时可跳转到原来保存的产物。

| 记录 | 最小字段与用途 |
| --- | --- |
| 会话阶段 | 随机运行与阶段标识、父级、时间、耗时、实际工具或模型标识、状态、脱敏错误码 |
| MCP 与直连 | 记录实际通道、来源服务类型、是否截断和结果数。复用现有 MCP `correlation_id` 关联子进程事件，区分子进程／协议失败、上游服务异常和无匹配 |
| 后台任务 | 关联已保存的任务与会话，记录排队、执行和终态事件。单独计算等待与实际运行耗时，缺少实测记录的字段显示未采集 |
| 模型用量与成本 | 使用服务商实际返回的 token 字段。配置可核对的价目时标明价格版本、币种及估算，缺失用量或价目显示未知 |

运行详情只保留必要的结构化状态和引用，排除提示词全文、推理过程、摘要和附件原文、笔记、密钥和原始异常。业务内容继续从有账号权限的现有页面读取。首版用本机有容量与期限限制的存储，保留期在实施前确定。普通用户仅可读本人详情，运维只使用脱敏诊断。诊断记录写入失败时显示「详情不可用」，业务结果与入库回执按各自的持久化状态报告。数据模型可按阶段与异步任务关联设计，是否接入外部采集器后续按需评估。[OpenTelemetry 追踪与阶段关联](https://opentelemetry.io/docs/concepts/signals/traces/)

## 6. 科研评估与版本对照

固定一套可复跑样例，先使用合成或可公开复用的快照核对行为，再按用户安排对真实 ADS、Gaia、模型和计算环境留证。复用已有知识库评估、V1.8 查询用例以及 REBOUND／PeTar 双体基准。冻结输入、数据源版本或样例摘要、模型配置与阈值后再跑评估。真实服务与替身分别报告，保留失败、跳过与复验结果。[现有 RAG 评估计划](development/v1.0.0/evaluation-plan.json) · [V1.8 增量验收](test-records/v1.8.0/changed-parts/20261122T082958Z/README.md) · [V1.7 数值基准](development/v1.7.0/RELEASE.md)

| 基准场景 | 判定依据 |
| --- | --- |
| SIMBAD → Gaia | Gaia 使用实际返回的 ICRS 坐标，核对单位、字符串编号、截断和来源。Gaia 超时时保留 SIMBAD 结果，诊断定位到实际失败阶段 |
| ADS → 文献库 | 题名和引用可对应真实 ADS 条目，顺序保存范围准确。只检索、明确添加、已在库、无匹配、限流、失效引用各有预期结果 |
| RAG | 引用可回查来源片段，回答有证据支撑。无证据或互相矛盾的样例按既有契约处理。检索命中与回答忠实度分别记录 |
| N 体模拟及绘图 | 核对既有双体解析误差阈值、轨迹与能量诊断，以及图表对应的实际输入。核对排队、取消、中断与产物状态 |
| 账号与故障 | 跨账号读取与写入、未授权入库、虚构来源必须为零。覆盖流式断线、请求重放、并发去重、MCP 退出与旧记录兼容 |

对照报告以 V1.8 正式版和 V1.9 目标提交为版本锚点。一条线在相同固定输入、模型配置和资源上比较直连与 MCP，核对科学字段、来源、状态和错误，再统计完成时间与模型用量。另一条线比较各版本共同支持的样例；文献管理等新增场景列为 V1.9 基线，旧版标为不适用。报告逐项呈现通过、失败、未执行及限制，延迟带样本数，用量和费用区分实测值、估算和未报告。

## 7. 实施与验收

| 阶段 | 交付 |
| --- | --- |
| M0 | 锁定正式基线复用位置、数据结构、权限规则、评估样例和判定阈值 |
| M1 | 完成用户文献数据服务、顶部栏入口、列表及详情、从 ADS 结果手动添加 |
| M2 | 接通对话检索与直接保存，校验结果引用，完成幂等回执与断线恢复 |
| M3 | 接入会话运行详情、MCP 关联和后台任务事件，形成可复跑评估及对照报告 |
| M4 | 补齐部署与备份升级说明，按仓库约定更新相关容器和检查启动健康，由用户安排功能验收 |

- [ ] 登录后桌面与 390px 窄屏均可从顶部栏打开「文献管理」，支持刷新、直接链接、返回原会话和键盘操作。账号切换后不显示前一账号的缓存内容。
- [ ] 对话可在一条消息中完成 ADS 检索及直接添加，也可在下一轮引用已显示的结果。结果、数量、来源和保存回执一致。仅检索、带否定或引用、意图含糊、越权或无可信来源时无未经授权的写入。
- [ ] 同一文献在并发提交、跨标签页及流式断线重试时保持唯一，重复保存不覆盖已有标签或备注。清除来源会话后条目仍可读，失效关联明确标注。
- [ ] 两个账号相互读取条目、改写标签、移除、使用结果引用及打开运行详情均被拒绝。独立 MCP 只列出原有三项只读工具。
- [ ] 会话中的模型、MCP／直连、RAG 与保存步骤可定位，后台任务有明确的排队及执行状态。运行详情不含敏感原文或凭据，旧会话可正常读取。
- [ ] 固定评估可以复跑并生成版本对照报告。报告含科学正确性、用量、延迟、失败和跳过项。验收环境与日常数据库隔离，分别记录离线、真实服务及部署启动证据。

开发阶段遵循项目的验收安排。证据保存于 `docs/test-records/v1.9.0/<类型>/<UTC时间>/`，记录当次提交、环境、样例版本和实际限制。V2.0 可使用本版基线推进生产部署与多用户运维，V2.x 再用同一评估体系比较单 Agent 与 Multi-Agent。[版本路线图](ROADMAP.md)
