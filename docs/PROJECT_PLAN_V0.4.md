# AstroAgent 开发文档 V0.4：查询结果可视化与可复现导出

**文档日期：** 2026-10-28

**文档状态：** 开发契约与实现说明；本地导出已验收，SIMBAD 限制经用户授权随源码发布

**代码基线：** V0.3 发布提交 `ee70400`；当前开发版本 `0.4.0`
**本次目标：** 将已有查询结果转为可核查的数据文件与基础科学图表，保留查询条件、来源、样本边界和错误记录。

[V0.1 路线图](PROJECT_PLAN_V0.1.md) 只明确了 V0.2、V0.3 与 V1.0，没有指定 V0.4。本版先补齐结果交付能力，再进入 V1.0 的科研工作流、知识库和用户界面。本文接口、模块、依赖与脚本已在工作区实现；是否通过验收以 [V0.4 实测记录](test-records/v0.4.0/README.md) 为准，不等同于已发布。

## 1. 当前状态与版本目标

### 1.1 已有能力与前置问题

当前代码提供单次、无状态的 `POST /api/v1/chat`，通过 SIMBAD、ADS、Gaia 三种工具返回带来源的结构化结果。Gaia 固定查询 DR3，最多交付 100 行，并提供程序统计与按条件启用的视差倒数近似距离。模型仅看到前 10 行 Gaia 数据，API 保留完整交付样本。

[V0.3 本地验收记录](test-records/v0.3.0/README.md) 记载离线测试 290 项通过、15 项默认跳过；完整 Gaia 联网测试为 5 项通过、2 项失败，原因是当次本机访问 SIMBAD 超时。V0.3 后经用户明确授权带该已知限制发布，当前基线已为 `ee70400`。本轮重新实测 Gaia / ADS 查询和导出成功，SIMBAD、名称链路及三工具完整成功路径仍失败；这些失败记录保留，不改写成通过。

原完整联网门槛要求补齐名称链路、SIMBAD回归和三工具成功路径。用户于2026-10-28在获知再次联网失败后明确要求“直接发布吧”，据此允许本版带已记录的SIMBAD超时限制发布；这些成功路径仍未通过，不能以“导出功能通过”替代。其他本地检查与目标提交/标签CI要求保留。

### 1.2 必须实现

- 导出完整查询快照 JSON，以及 SIMBAD、ADS、Gaia 的固定列 CSV。
- 对用户明确选择的 Gaia 结果生成自行散点图、视差直方图和观测颜色—星等图。
- 一次下载 ZIP，内含数据、图表、中文说明和文件 SHA-256 清单。
- 图表和表格使用 API 的完整交付行，逐项记录未参与绘图的行及原因。
- 导出保持原查询状态、失败结果、单位、UTC 来源时间、实际 ADQL / ADS 检索式和截断信息。
- 保留现有聊天协议、三工具预算、配置和失败降级行为，导出自身不调用模型或外部数据库。

### 1.3 本版范围之外

本版不增加 Web 前端、会话历史、用户系统、云端文件存储、长期下载链接、任务队列、MCP、RAG 或多 Agent 编排。不增加自动翻页、任意绘图代码、自定义服务地址、任意文件路径、论文全文下载、PDF / Word 报告或 BibTeX / Zotero 写入。

不增加成员判定、绝对星等推断、消光校正、视差零点校正、贝叶斯距离、拟合或参数反演。导出的图表用于描述交付样本，不能自动给出星团年龄、质量、距离或成员结论。

## 2. 使用流程与兼容性

用户先按现有协议查询，保存响应，再显式提交该响应生成导出包。两个请求独立，服务端不保存跨请求状态。

```mermaid
flowchart LR
    A[完整自然语言问题] --> B[现有 POST /api/v1/chat]
    B --> C[完整 ChatResponse 快照]
    C --> D[计划新增 POST /api/v1/exports]
    D --> E[验证与固定列导出]
    E --> F[用户选择的 Gaia 图表]
    F --> G[ZIP 与校验清单]
```

| 场景 | 预期行为 |
| --- | --- |
| 只导出数据 | `plots=[]`，生成 JSON、CSV 和说明，不生成图片 |
| Gaia 圆锥样本 | 明确选择某次 Gaia 调用及图种，使用该次全部交付行 |
| 多次 Gaia 查询 | 按结果索引分别导出，不合并视场、不跨查询去重 |
| SIMBAD / ADS 结果 | 导出实际字段、检索条件和来源，不推测缺失内容 |
| 部分查询失败 | 成功数据照常导出，原失败状态和错误留在快照与清单中 |
| 绘图所需数据不足 | 跳过对应图，写明原因，仍返回可用数据文件 |

`ChatRequest` 保持只有 `message`，`ChatResponse` 不新增必填字段，`results`、`literature_results`、`gaia_results` 仍分别保存三类结果。导出请求不注册为 LLM 工具，也不占用或增加工具调用预算。本版聊天接口仍不直接返回图片或下载地址；自然语言中只提出“画图”不会自动完成第二个请求，使用方式必须在 README 说明。

## 3. 导出接口契约

### 3.1 `POST /api/v1/exports`（已实现）

请求为 `application/json`。定义独立 `ExportRequest`，拒绝未知字段；嵌套快照也须逐层拒绝未知字段，不能仅依赖当前响应模型的默认行为。

| 字段 | 类型 / 默认值 | 规则 |
| --- | --- | --- |
| `schema_version` | 字符串，必填 | 本版固定 `"1"`，用于导出契约演进 |
| `snapshot` | 对象，必填 | 完整 V0.3 / V0.4 `ChatResponse` 语义结构；不接受模型裁剪视图 |
| `plots` | `list[PlotSpec]`，默认 `[]` | 最多 3 项，不接受重复的“索引 + 图种” |
| `plots[].gaia_result_index` | 严格整数，必填 | 从 0 开始，必须落在 `snapshot.gaia_results` 范围内 |
| `plots[].kind` | 固定枚举，必填 | `proper_motion`、`parallax_histogram`、`observed_cmd` |

请求构造示例，`response` 代表前一步实际得到的完整响应；以下是客户端伪代码，不能把占位对象当作真实查询结果：

```python
export_request = {
    "schema_version": "1",
    "snapshot": response,
    "plots": [
        {"gaia_result_index": 0, "kind": "proper_motion"},
        {"gaia_result_index": 0, "kind": "observed_cmd"},
    ],
}
```

成功返回 HTTP 200、`Content-Type: application/zip`、固定 `Content-Disposition: attachment; filename="astroagent-results.zip"`，并设置 `Cache-Control: no-store`。OpenAPI 将成功响应描述为二进制文件，错误使用既有 `ErrorResponse` 格式。包内 `manifest.json` 表达导出是否有图表跳过；HTTP 200 不改写快照的查询状态。

导出独立于 `get_agent` 和模型密钥校验，不构造 Agent，不读取密钥，不执行快照中的 URL、检索式、ADQL 或文本指令。没有密钥时仍可导出有效快照。

### 3.2 快照验证与来源边界

导出输入由客户端提交，不能证明其确实来自本服务或原数据库。所有包固定标注 `provenance="client_supplied_snapshot"`、`source_authenticity_verified=false`。SHA-256 仅用于核对包内文件是否变化，不是来源签名，也不是对科研结论的认证。

输入检查至少包括：

- 三类查询结果总数最多 12，匹配现有 `AGENT_MAX_TOOL_CALLS` 的配置上限；单次 Gaia 最多 100 行，单次 ADS 最多 10 篇。超过导出上限直接拒绝，不静默裁剪。
- `returned_count` 与实际列表长度一致；成功 / 无匹配 / 失败状态的数据和错误组合符合现有服务契约。同一次 Gaia 结果不得有重复 `source_id`。
- `source_id` 为合法有符号 64 位正整数字符串，不能转为 JSON 数字；测量值为有限数值或 `null`，误差与单位符合 V0.3 规则，禁止 NaN / Infinity。
- Gaia `query` 重新按 `GaiaQuery` 验证，发布版、表、端点和固定单位符合既有契约；保存的 ADQL 只当作记录，不执行。ADS 参数重新按 `LiteratureQuery` 验证。
- 如有 `analysis`，用已有纯计算函数对提交行和查询参数复算，核对样本数、统计、距离开关、计算/跳过数量与逐源距离。计数和原因精确匹配，有限浮点数使用 `rel_tol=1e-12`、`abs_tol=1e-12` 比较。不一致则拒绝，不覆盖原值冒充原始结果；复算一致仍不代表观测真实性已认证。

快照缺失必要元数据、索引越界、字段矛盾或格式不兼容均为 HTTP 422。导出只保证支持本契约的 V0.3 / V0.4 结构，不承诺直接接收更早版本缺少 Gaia 字段的任意 JSON。

## 4. ZIP 内容与数据格式

### 4.1 包结构

```text
astroagent-results.zip
├── manifest.json
├── snapshot.json
├── README.md
├── tables/
│   ├── simbad-000.csv
│   ├── ads-000.csv
│   └── gaia-000.csv
└── figures/
    ├── gaia-000-proper-motion.png
    └── gaia-000-observed-cmd.png
```

后缀 `000` 对应各自结果列表的从零索引；文件名全部由程序生成。每次成功查询各有一份 CSV；无匹配或失败的查询不生成伪数据表，其状态、错误和未生成文件的原因保留在清单。未请求或已跳过的图表不生成占位 PNG。即使所有查询失败，也可生成快照与审计说明。

`snapshot.json` 保存通过验证后的完整查询响应语义，包括自然语言回答、失败项、来源及全部交付数据；UTF-8、无 BOM、严格 JSON、禁止非有限值，不裁剪摘要或作者。它不是原 HTTP 字节副本，字段顺序与空白可能改变。说明文件区分“模型回答”“数据库测量”“程序派生量”，不将模型解释升级为测量事实。

### 4.2 固定列 CSV

| 文件 | 数据范围与列规则 |
| --- | --- |
| SIMBAD | 单次成功调用 1 行；含查询索引、输入名称、`ObjectData` 全字段、来源 URL 与查询 UTC 时间 |
| ADS | 单次实际返回论文；含查询索引、`PaperData` 全部书目字段、来源 URL / UTC 时间；作者与 DOI 列编码为 JSON 数组字符串 |
| Gaia | 单次全部交付行；按 `GaiaSourceData` 定义顺序包含全部字段，再附已有的距离值、随机误差、方法、校正标记和跳过原因 |

单位、实际参数、ADQL、ADS 检索式、筛选、返回数量、`total_found`、截断和溢出状态保留在快照与清单的查询元数据中；不能将 Gaia 的未知总命中数改成交付行数。距离未启用时派生列为空，并明确 `estimate_distance=false`，不在导出时额外计算距离。跨查询的同一源保留各自上下文。

CSV 使用 Python 标准库 `csv`，固定逗号分隔、CRLF、UTF-8 BOM 和确定的列顺序；逗号、引号和换行按 CSV 规则引用。`null` 写为空单元格，数值不为显示效果舍入；JSON 是区分空字符串、空值和原文本的完整副本。[Python CSV 官方文档](https://docs.python.org/3.12/library/csv.html) 说明了标准库的引用及空值转换行为。

文本字段在电子表格中有公式解释风险：对于以 `= + - @`、制表符或回车开头，以及去除前导空白后以公式触发符开头的字符串，输出加前导单引号；记录变更的文件、数据行号和列名。真正的数值负数保持数值，不进行这项文本处理。Gaia `source_id` 的 CSV 显示值统一加前导单引号并在清单声明该策略，避免直接打开表格时当作长整数处理；无前缀的精确字符串保留在 JSON。仅加双引号不视为长编号精度保障，也不承诺所有表格软件自动识别类型。

### 4.3 清单与可复现性

`manifest.json` 至少包含：

- `schema_version`、实际导出器包版本、Git 提交（可取得时）、UTC 导出时间、Python / Matplotlib / NumPy 版本与绘图样式版本。
- 固定的来源真实性标记、快照查询状态与独立的 `export_status`；未请求图表或全部成功为 `success`，存在跳图为 `partial`。
- 各次查询索引、状态、来源时间、查询条件、单位、样本数、截断、溢出及既有科学警告。
- 每个文件的相对路径、字节数和 SHA-256；清单不对自身计算哈希，避免自引用。
- 每张请求图的种类、查询索引、状态、使用字段、有效/跳过行数、参与绘图的编号、未参与编号及原因、绘图参数和输出路径。
- CSV 文本保护策略与变更位置，以及所有图表跳过原因。

校验值对实际写入 ZIP 的文件字节计算。固定输入和绘图参数应复现相同选行、坐标、分箱与统计；时间戳、依赖、字体和图片元数据可能变化，不承诺跨平台 ZIP 或 PNG 逐字节相同。清单中的版本与哈希用于核对实际产物。

## 5. Gaia 图表与科学规则

图表从完整 `gaia_results[index].data` 选行，不能从 `gaia_view()` 的前 10 行模型视图取数据。每次调用独立绘制，不隐藏添加 RUWE、视差信噪比或离群值筛选；原查询已应用的筛选必须显示在说明中。

| 图种 | 横轴 | 纵轴 | 选行与显示规则 |
| --- | --- | --- | --- |
| `proper_motion` | `pmra`，mas/yr | `pmdec`，mas/yr | 两值均非空且有限；保留负值，等比例坐标，不重复乘赤纬余弦 |
| `parallax_histogram` | `parallax`，mas | 实际行数 | 有限视差；保留负/零视差，画零点参考线；不归一化为概率密度 |
| `observed_cmd` | `bp_rp`，mag | `phot_g_mean_mag`，mag | 两值均非空且有限；G 轴反向，亮源在上；仅用已有 `bp_rp`，缺失时不另行补算 |

散点图至少 1 个有效点；视差直方图至少 2 个有效值，否则 `insufficient_data`。有效视差范围非零时使用 `min(10, ceil(sqrt(n)))` 个等宽箱；全部相同时以该值为中心绘制宽 1 mas 的单箱。最终箱边界与各箱计数写入清单，计数总和必须等于参与直方图的行数。极端有限值如导致轴限、分箱或渲染计算不可表示，跳过该图并记录 `unrepresentable_range`，不能静默丢掉极端行。

固定 PNG 为 1200×900 像素、150 DPI、白底，使用随 Matplotlib 分发的 DejaVu Sans 和固定英文轴名，中文解释写入包内 README。图内显示图种、Gaia 结果索引、有效/交付数量与 `returned rows only`；截断或服务端溢出时加入醒目标记。长 ADQL、URL、中文名称和质量说明放在清单与 README，避免文字挤压绘图区。

每张图的说明必须明确：

- 图表只描述该次实际交付样本；最多 100 行且可能截断，不代表整个视场、星表或总体分布。
- 圆锥源是位置候选源，不能称为已确认匹配或星团成员；自行聚集本身不能完成成员判定。
- `pmra` 已含 `cos(dec)`；未做自行传播。颜色—星等图使用视星等，未校正消光，不标为绝对星等 HR 图，也不据此拟合年龄。
- 视差直方图不是距离分布；负视差是测量结果的一部分。图中不自动绘制距离、拟合曲线或误差条；可用测量误差随 CSV / JSON 导出。

### 6.1 改动位置

新增显式运行依赖 `matplotlib>=3.9,<4`；Windows Python 3.12 环境实际安装 3.11.2 并通过本地检查，Linux CI 尚未触发，依赖范围不等于已测试全部版本。使用已有 NumPy 和标准库 `csv`、`json`、`zipfile`、`hashlib`、`io`，不为导出引入 pandas、数据库或外部图表服务。

渲染使用 `Figure` 与非交互 `FigureCanvasAgg`，不调用 GUI、`pyplot.show()` 或外部 LaTeX。Matplotlib 的 [后端文档](https://matplotlib.org/stable/users/explain/figure/backends.html) 和 [服务端示例](https://matplotlib.org/stable/gallery/user_interfaces/web_application_server_sgskip.html) 支持该使用方式；其 [线程说明](https://matplotlib.org/stable/users/faq.html#work-with-threads) 要求调用方处理线程间竞争。因此同一进程中的导出使用一个非阻塞互斥锁，完整覆盖绘图及相关样式操作，忙时立即返回 503，不建立等待队列。资源在 `finally` 中释放，不保留 Figure、缓冲区或导出历史。

### 6.2 固定资源上限

| 项目 | 本版上限与行为 |
| --- | --- |
| 请求体 | 2 MiB，按实际接收字节累计；超出返回 413，不先整包读入再判断 |
| 压缩请求体 | 不支持非 identity 的 `Content-Encoding`，返回 415 |
| 查询/数据规模 | 总调用 ≤12，单次 Gaia ≤100 行，单次 ADS ≤10 篇 |
| 图表 | 每包最多 3 张，固定像素和 DPI；不允许用户覆盖画布、字体或样式文件 |
| 包体 | 全部成员未压缩字节合计及最终 ZIP 均 ≤16 MiB，写入过程中检查，超限返回 413 |
| 并发 | 每进程同时 1 次导出，忙时返回 `export_busy`；多进程资源量需另行评估 |
| 持久化 | 导出包在内存生成并作为响应返回，不创建服务器历史文件或公共下载目录 |

请求体限制必须在 JSON 解析前覆盖无 `Content-Length` 和分块请求；不能只检查请求头。可采用仅包裹该路由的 ASGI 接收计数层，设计依据为 [Starlette 请求流接口](https://starlette.dev/requests/)。非法 JSON、过深嵌套和解析异常需受控处理，不能泄漏原始快照或内部异常。

文件名与 ZIP 路径固定，不从输入名称拼接路径。来源链接仅保存为文本，不抓取 URL；导出不加载外部图片、字体或脚本。以上约束用于限制本地导出工作量，不构成生产吞吐、严格总耗时或峰值内存的保证；单进程本机开发仍是本版部署范围。

### 6.3 错误与部分交付

| 情况 | 行为 |
| --- | --- |
| 非法 JSON、未知字段、坏索引、不一致快照 | HTTP 422；无 ZIP |
| 请求或包体超限 | HTTP 413，`export_too_large`；无半成品 ZIP |
| 错误媒体类型或不支持的内容编码 | HTTP 415，`unsupported_export_media_type` |
| 进程内导出锁正忙 | HTTP 503，`export_busy`，允许客户端稍后重试 |
| 导出核心序列化、打包、哈希失败 | HTTP 500，`export_failed`，仅返回清理后的错误 |
| 单张图数据不足、查询失败、范围不可表示或渲染失败 | HTTP 200；保留数据文件，清单逐图记录跳过原因，`export_status=partial` |

可用的逐图原因包括 `query_not_successful`、`insufficient_data`、`unrepresentable_range`、`render_failed`。原快照 `status=partial/error` 不自动令文件生成失败；导出状态与查询状态分别记录。打包完成并核对清单后才发送响应，避免返回一个看似成功的残缺压缩包。

## 8. 测试与验收设计

### 8.1 离线测试

默认继续禁止外部 HTTP，不需密钥。测试目标是验证导出后的可用数据和科学规则，不能仅断言函数调用次数或文件存在。

| 测试组 | 核心断言 |
| --- | --- |
| 快照契约 | 未知嵌套字段、坏状态、错误计数、重复编号、非有限值、错误单位、浮点编号、分析矛盾被拒绝 |
| JSON / CSV | 完整字段与顺序、中文/引号/换行、作者 DOI 数组、空值、负数、公式文本、长编号精度策略；读回后与快照核对 |
| 数据范围 | 100 行样本不缩成模型的 10 行；两次查询有相同编号仍分别保留；哨兵行不进入包 |
| 图表数据 | 合成样本的有效/跳过编号、坐标、直方图边界与计数、负/零视差、常量样本、单点/全缺失、极端范围正确 |
| 渲染 | PNG 可解码、1200×900、非空；自行等比例、G 轴反向；每种图至少保存一张供人工检查 |
| 清单 | ZIP 成员路径固定且无重复，字节数/哈希可重算，文件与图表索引一致，无清单自引用 |
| HTTP 边界 | 无密钥可用；超大/分块/错误编码、并发忙、渲染失败、打包失败与异常后锁释放符合契约 |
| 原能力回归 | 健康、OpenAPI、三工具及失败降级不变；导出全程无外部网络和模型调用 |

图表测试优先核对实际绘制数据、坐标语义和 PNG 解码，不做脆弱的跨平台像素完全一致断言。合成测试数据必须标明性质，不能用作真实 Gaia 图例或联网验收证据。

### 8.2 真实 HTTP 与联网验收

已实现 `scripts/verify_v04.py`：默认启动临时本机服务，以标明为合成数据的快照检查导出接口；`--live` 显式执行真实查询→导出链路，会产生模型用量。`--live --only cone exact` 可仅复测指定场景，报告明确记录范围，不能替代完整联网验收。

默认 HTTP 场景至少包含健康/OpenAPI、三类数据导出、三种图、无密钥、图数据不足、部分失败、无匹配、坏快照、超限及逐文件哈希核对。真实 Uvicorn 的分块超限检查须补充到进程内 TestClient 测试之外。

`--live` 验收至少使用当次 Gaia 圆锥响应生成三种图和 CSV，用精确源检查单点及跳图；再验证 SIMBAD、ADS 和三工具结果的完整导出。需要 `DEEPSEEK_API_KEY`、`ADS_API_TOKEN` 和三个数据源的网络访问，显式启用后缺凭证或外部失败记为失败，不能静默跳过。现有三个联网开关仍各自独立，默认导出验收不启用它们。

报告保存真实请求/响应、包、清单校验结果、依赖/Git 状态、实际命令与 UTC 时间；人工逐张打开 PNG，检查轴、单位、计数、文字裁切、负值和截断标记，并保存检查说明。图片未完成检查时明确标为“视觉验收待完成”。脚本在 `finally` 停止自己启动的服务，核对 PID 退出和端口关闭。

V0.4 记录保存到 `docs/test-records/v0.4.0/<类型>/<UTC时间>/`，类型为 `offline-tests`、`acceptance-v04`、`live-export-tests`、`figure-review`；同版本复测新建目录，失败历史不覆盖。不得把 V0.3 报告复制改名为 V0.4 验收。
