# AstroAgent V1.6 开发文档：邮箱注册、登录与后台管理

**日期：** 2026-11-14

**目标版本：** V1.6.0
**状态：** V1.6开发版源码已接入；未构建、测试、部署、迁移个人数据库或发布。实际基线为 `ea1eeec`，实现与范围说明见[实施记录](development/v1.6.0/IMPLEMENTATION.md)、[部署维护说明](development/v1.6.0/OPERATIONS.md)和[待验收清单](development/v1.6.0/ACCEPTANCE.md)。下文保留设计契约，不能将源码接入当作验收通过。

## 1. 版本目标与范围

在现有 Vue + FastAPI + PostgreSQL/pgvector 基础上提供账号系统：用户使用邮箱注册，通过邮件激活后登录；**未登录前不能使用网站任何业务功能**；管理员通过直接输入后台地址进入管理界面，网站中不提供后台入口。普通用户只能使用和管理自己的科研数据，管理员权限由服务端控制。

本版交付邮箱注册和激活、密码登录和退出、找回密码、会话管理、强制登录、管理员后台、按用户隔离数据、现有个人数据安全迁移及部署说明。注册与登录的页面体验可参考常见 AI 产品，但不依赖特定产品的内部实现；本版不包含第三方账号登录、付费订阅或组织协作。

V1.6 必须具备实际的多账号数据隔离；这不等于已达到 V2.0 的生产规模、可靠性与多租户运维标准。单靠隐藏后台地址、前端路由守卫或部署容器都不能替代认证与授权。

## 2. 登录前访问边界

匿名访问只开放完成身份验证所必需的页面及接口：登录、注册、邮箱激活、重发激活邮件、找回/重置密码及其静态资源。匿名用户访问首页或任何业务页面时跳转登录，登录完成后可返回安全的站内原页面；禁止外部跳转和循环跳转。未激活、已禁用、已退出或会话失效的用户按未登录处理。

后端默认拒绝匿名访问：聊天、科研查询、项目、历史、文献、RAG、模型操作、绘图、预览/下载、导入/导出、配置和管理 API 均需有效登录；不得仅隐藏页面。旧无状态聊天和导出等历史接口也需纳入鉴权清单。浏览器直连 API、猜测资源 ID、刷新、深链、跨标签页和已有缓存都不能绕过。文件下载和流式响应在开始前验证身份与资源权限，长任务及流式连接在账号禁用等状态变化时按明确策略终止或阻止结果读取。

反向代理所需的最小健康探针只供容器内部使用，不返回业务数据，不能通过公开网页入口访问；交互式 API 文档和 OpenAPI 如提供，必须受管理员权限保护或默认关闭。数据库、Ollama、绘图执行器及内部服务不暴露为绕过登录的网页入口。数据库不可用、鉴权服务异常或迁移未完成时安全拒绝业务访问，不能降级为匿名模式。

## 3. 邮箱注册与激活

1. 注册页填写邮箱；后端统一验证格式、长度及邮箱唯一性。规范化策略仅做有标准依据且可逆的处理，保留原始展示地址，不对邮箱别名进行猜测性合并。
2. 创建待激活账号，生成高随机强度的单次激活凭据；数据库只保存摘要、用途、账户、到期时间及使用状态。激活链接使用配置的可信站点地址构造，不使用未经校验的请求 Host。
3. 通过服务端邮件服务向注册邮箱发送激活邮件。页面统一提示“如果邮箱可用，请查收激活邮件”，避免通过注册、登录、重发和找回接口枚举账号。邮件明确产品名称、动作和有效期，不包含密码。
4. 用户打开邮件中的链接后先看到确认页面，**只有主动点击确认**才通过 POST 原子消费令牌并激活账号，避免邮件安全扫描器预先消费链接；不在 GET 请求中改变账号状态。激活成功进入登录页，由用户使用邮箱和密码登录。
5. 未激活、过期、无效及已使用链接显示可理解的处理方式；允许用户限频重发，生成新令牌并使此前未使用令牌失效。已有激活账号不能被重复注册重置密码或替换资料。待激活注册若重复提交，不能让攻击者在邮箱持有人激活前固定或覆盖其密码：采用邮箱验证后设置密码，或重发时作废旧凭据并要求邮箱持有人在激活后自行设置密码；最终采用**邮箱验证后设置密码**方案。

因此实际注册流程为：填写邮箱 → 收到邮件 → 打开链接并确认 → 设置密码 → 原子完成激活 → 前往登录。未激活账号不可访问业务；注册时不要求提前设置密码。激活凭据有效期建议 30 分钟，可通过服务端配置；使用 HTTPS，令牌不写日志、统计、第三方资源或 Referer，确认页设置严格的 Referrer-Policy，使用后从地址栏移除敏感参数。激活与设置密码需要防止重放和竞态，确认步骤可换取短期受限的一次性设置凭据，并在最终提交时事务完成。

邮件发送由管理员配置 SMTP 或等价邮件服务，启用加密传输与认证；设置发件地址、固定外部站点地址、超时和发送限额，密钥只保存在服务端。注册与邮件发送使用可靠的事务发件箱/队列和幂等处理，明确待发送、已提交服务商和失败状态；服务商接收不等于用户收件箱送达。失败不算激活成功，提供限频重发及管理员可查看的脱敏诊断；不可把邮件正文、令牌或真实用户邮箱输出到公开日志。未配置邮件时禁止新注册并告知服务暂不可用，不允许绕过激活；已有账号仍可登录。

## 4. 登录、密码与会话

- 邮箱与密码登录；错误、账号不存在、未激活和禁用的公开响应统一，服务端记录分类的脱敏事件。按账号及来源实施限频、退避和告警，防止撞库与邮件滥发；代理来源地址仅信任明确配置的代理。
- 密码由用户设置，按 NIST 指南以不少于 15 个字符作为单因素密码下限，允许至少 64 字符、粘贴及密码管理器，拒绝常见/泄露密码；不强制大小写和符号组合。使用 Argon2id、独立随机盐及可升级的参数存储密码摘要，明文不落库、不记日志、不发邮件。
- 采用服务端可撤销的随机会话令牌，通过 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie 传输，设合理的空闲与绝对有效期；数据库只存令牌摘要。登录和权限提升时轮换会话；退出、密码重置和账号禁用时撤销相关会话。浏览器关闭与持久登录策略须在界面说明。生产或远程部署强制 HTTPS；本地 HTTP 开发必须使用明确的本地专用配置，不能当作远程安全配置。
- Cookie 认证需 CSRF 防护：同源检查、现有 Host/Origin 约束与 CSRF token 配合；CORS 不使用携带凭据的通配符。认证前已有的前端缓存、下载链接和临时数据不得跨用户复用；退出清除客户端缓存并撤销服务端会话。
- 找回密码使用同样的单次、限时邮箱令牌与统一响应，设置新密码后撤销所有旧会话并发送安全通知；不得把旧密码发回邮箱。更改密码需当前密码或安全的近期重新认证。管理员高风险操作要求近期重新认证；本版为管理员提供并要求启用 TOTP 双因素认证，含一次性恢复码，恢复码摘要保存、仅显示一次，丢失时走受控离线恢复。

## 5. 后台地址与管理员权限

后台采用例如 `/admin` 的固定路由，用户通过手动修改网址访问；**主站导航、用户菜单、登录后页面及其他公开页面均不展示后台入口或后台链接**。可配置后台路径用于部署，但路径不作为密码，不承诺无法被发现；禁止在公开文档或响应中暴露内部诊断信息。

未登录访问后台，先进入登录页，成功后只将授权的管理员送回后台；普通用户即使知道地址也不能查看页面数据或调用任何管理 API。服务端逐请求校验已激活、未禁用的管理员角色及权限；前端隐藏只是界面行为。未授权返回统一的拒绝或不存在提示，不泄露账号及敏感信息。

后台 V1.6 最小功能：

| 功能 | 范围与限制 |
| --- | --- |
| 管理概览 | 账号数量、待激活数量、近期脱敏安全事件、邮件服务状态；不展示用户对话或文献内容 |
| 用户管理 | 分页查询用户、查看邮箱脱敏/状态/注册及最近登录时间；启用、禁用账号并撤销其会话；操作前确认并记录原因 |
| 角色管理 | 仅现有管理员可授予/撤销管理员角色，敏感操作重新认证并审计；禁止禁用或降权最后一位有效管理员及自己造成的锁死 |
| 邮件状态 | 查看服务配置状态、投递失败计数及错误类别，重试受限；不显示凭据、令牌或邮件内容 |
| 审计日志 | 记录操作者、事件类型、目标标识、时间、结果和必要的脱敏来源，限制读取、设保留期；不记录密码、会话、链接或科研内容 |

管理员默认不能查看或修改其他用户的会话、文献、科研结果或导出；需要此能力时另行明确授权与设计。后台不提供执行任意命令、任意 SQL 或读取服务端密钥的功能。

**首位管理员初始化：** 安装者先通过普通邮箱注册并激活账号；通过仅在服务器本地运行、受操作系统权限保护的管理命令，指定该已激活账号授予管理员角色。该命令只在尚无管理员时可进行首次初始化，显示目标身份并要求明确确认；不得设默认账号密码、公开初始化 API、自动提升首位注册用户或通过网页参数提升权限。管理员遗失权限时使用单独的本机受控恢复流程并记录审计，不能仅凭邮箱自动提升。初始管理员登录后绑定 TOTP 后才允许进入管理功能；绑定与恢复不能产生业务数据绕过。

## 6. 数据归属与兼容迁移

每个用户有不可猜测的稳定 ID；为项目、会话、轮次、快照、流程、文档及版本、检索索引、问答、附件、绘图任务与产物、本地助手任务、导入/导出等建立明确归属或经父对象强制校验归属。数据库查询和写入必须在服务端按当前用户过滤；不能相信前端传入的用户 ID。父子关系须同时核验，拒绝跨用户关联、重放、引用及下载。后台任务提交时绑定用户与对象，执行和读取时再次校验权限；账号禁用后阻止其任务结果被读取。

RAG 的向量检索、词法候选、缓存键、引用与预览都必须先限定用户/授权项目范围；不得先全库检索再仅由前端过滤。导出只包含本人授权数据；导入视为当前用户的新数据，重新映射 ID、校验引用和限制，不能通过归档注入其他人的归属。数据库连接串、邮件服务与模型系统配置属于管理员运维范围，不让普通用户读取或修改全局密钥。

旧版为单用户数据，升级时不自动赋予首个注册账号：先备份数据库与绘图产物，在隔离环境验证迁移；由本机受控命令指定一个**已激活的既有账号**，预览数据数量与目标身份，明确确认后以事务/可恢复的迁移步骤建立归属。迁移失败停止业务访问并提供恢复办法；不删除旧备份，不将历史个人数据暴露给所有新注册用户。待归属数据不能被任何普通账号查询。升级完成后检查所有旧资源、索引、文件和任务的归属；降级前明确新增账号、角色与数据隔离字段的兼容及数据丢失风险，不自动回滚到可匿名访问的旧版。

## 7. 部署与配置

延续 V1.5 整体容器化方案：前端、后端、PostgreSQL、模型及绘图执行器按现有组件管理，新增邮件服务连接配置与认证相关密钥；SMTP 可使用外部服务，是否自建邮件服务不作为本版默认要求。所有密钥和会话签名/加密材料由部署者生成并安全注入，不写入仓库、前端构建、镜像或日志；重建容器不丢失账号、令牌状态、用户数据和审计。健康检查只暴露最小状态。

本机访问可用开发模式；如开放给其他设备或公网，须先配置可信域名、HTTPS、代理与 Host 白名单、邮件发信域名及 DNS、备份恢复、限流和监控，并完成对应安全验收。V1.5 的本机回环限制与 Host/Origin 校验需有明确的受信部署模式，不得为了注册功能而关闭。公开注册的配额、发信成本与滥用控制须有管理员可调上限；达到上限时显示明确可恢复的服务状态。

## 8. 实施阶段与验收计划

| 阶段 | 实施内容 | 完成条件 |
| --- | --- | --- |
| M0 | 梳理全部页面、API、文件和任务入口；核对 V1.5 实际基线及迁移方案 | 认证白名单、资源归属清单与兼容方案可审查 |
| M1 | 数据库账号、角色、会话、邮件令牌、限流和迁移 | 有备份与回退方案，所有旧数据先隔离 |
| M2 | 注册/邮件激活/登录/重置密码、统一认证与前端页面 | 匿名不能使用业务；邮件失败和令牌生命周期可恢复 |
| M3 | 每用户数据与任务隔离、历史数据归属 | 全业务 API、检索、导入导出及文件按用户授权 |
| M4 | 隐藏入口的管理员后台、首位管理员初始化、TOTP 与审计 | 服务端角色校验和敏感操作保护完整 |
| M5 | 容器配置、用户/管理员手册及用户安排的验收 | 以实际环境和版本保留完整证据与限制 |

遵循项目约定：开发期间不主动运行测试、构建或迁移个人数据库；由用户安排发布前验收。以下均为待执行项目：

- [ ] 匿名逐一访问所有页面、旧 API、WebSocket/流式入口、文件和导出链接，业务均被拒绝；例外仅限身份流程及内部探针。
- [ ] 真实邮箱完成注册、邮件送达、点击确认、设置密码与登录；覆盖重复注册、重发、扫描器 GET、过期、重放、并发、邮件故障及限频；无邮箱枚举和令牌泄漏。
- [ ] 登录失败、暴力尝试、CSRF、会话固定/过期、退出、多标签页、密码重置及禁用账号后撤销均按契约生效；管理员 TOTP 和恢复可用。
- [ ] 主站无后台入口；直接访问后台时匿名、普通用户、管理员分别符合权限，所有后台 API 可独立抵御越权；最后管理员保护和审计完整。
- [ ] 至少两个独立账号相互尝试访问项目、会话、快照、文献、向量检索、RAG 引用、绘图及下载、缓存、后台任务、导出导入，均无法越权。
- [ ] 在隔离数据库演练旧数据备份、指定账号迁移、故障中断恢复与回退；核对原记录、索引和产物，日常个人库不被自动修改。
- [ ] 前后端重启、容器重建及邮件服务不可用时用户数据和账号状态正确；本地和目标 HTTPS 部署各自验证，凭据不泄露。
- [ ] 聊天、SIMBAD/ADS/Gaia、知识库、RAG、本地模型与 Python/Gnuplot 绘图在认证后按既有契约回归，记录外部依赖失败及未覆盖项。

验收记录放在 `docs/test-records/v1.6.0/<类型>/<UTC时间>/`，注明代码提交、部署环境、测试账户和邮件方式，保留失败、限制和证据；不用真实私人数据或令牌作为公开样本。
