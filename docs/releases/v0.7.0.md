# V0.7.0 开发说明：可追溯科研流程

本版在 v0.6.0 基础上新增两条固定科研流程；源码发布前验证本地测试、真实查询及目标提交和标签 CI。2026-10-30 本地和联网结果见 [本版测试记录](../test-records/v0.7.0/README.md)。

## 新增代码

- 项目内新增“科研流程”工作区，提供两个固定模板。创建只保存参数，启动和继续均需明确确认。
- Gaia视场：名称或ICRS坐标互斥，半径/数量必填；复用SIMBAD名称解析、Gaia查询、程序统计、完整快照与原有三类图表/ZIP导出。名称解析失败停止依赖步骤，保持主站故障转哈佛镜像的既有策略。
- ADS摘要证据表：使用确认的实际检索式、排序与单页范围，保留书目、原摘要、来源、缺失标记，导出UTF-8 BOM CSV与保留完整原值的JSON。CSV危险文本使用原有保护策略，超过32766字符的文本明确记录预览变更。
- 持久化运行、步骤、尝试、执行请求与文件；分别记录查询和导出状态、输入/依赖/软件版本/UTC时间/耗时/哈希/警告/错误。
- 显式继续时核对成功检查点；失败/中断步骤新建尝试，历史记录保留。重启只标记中断，不自动再次访问外部服务。断线核对保留原幂等请求编号。
- 文件按项目/流程/UUID下载，服务端核对长度与SHA-256；网页下载再次核对哈希。PNG预览与ZIP内的图片来自同一份保存产物。

这两条流程不调用语言模型。Gaia位置候选源不等于成员，统计和图表只描述交付样本，坐标未做自行传播；ADS证据表不代表全文阅读或系统综述。

## 存储与兼容

SQLite schema3新增四张流程相关表。首次启动前先用SQLite一致性备份接口保存 `migration-v3-<UTC时间>.sqlite3`，失败回滚；本轮未启动应用或迁移个人库。回退V0.6需停服并在独立目录恢复schema2备份，不能直接把schema3交给旧版写入。

项目归档默认格式2，固定五成员：`manifest.json`、`project.json`、`conversations.json`、`snapshots.json`、`workflows.json`。流程文件以带哈希的base64内容保存在最后一项；导入逐层重映射身份、保留原始来源映射，创建独立项目，标记 `imported_unverified`。导入不访问外部科研服务、不执行流程；导入流程只读，重新查询需复制参数到本机新运行。

仍支持格式1导入。无流程项目可显式选择格式1导出，有流程时拒绝旧格式导出，避免无提示丢失记录。V0.6不能读取格式2。

限制：每项目50次运行、每步5次尝试、每运行20次执行请求、每模板4步；流程记录和单文件16 MiB，共用全库256 MiB业务预算、20会话及原快照配额，所有查询共用两个执行槽。快照保存会建立独立会话。删除流程及专属文件保留快照/会话；引用中的快照要先删除关联流程，运行中拒绝删除相关项目或实体。
