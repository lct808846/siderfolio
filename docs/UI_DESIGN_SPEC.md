# AstroAgent UI 设计规范

规范版本：1.0 · 制定日期：2026-11-15 · 适用于所有新增、修改的前端界面。

本文是跨版本维护的界面设计基准，覆盖查询与绘图工作台、项目归档、来源关联、科研流程、本地知识库、文献问答、本机设置、本地助手、身份页面、账号安全和管理控制台。设计目标是让相同信息与操作在不同页面有相同的外观、位置和反馈。

**执行约定：**“必须”是开发与审查要求；“建议”允许按任务调整；“既有例外”仅适用于指定区域。本文规定目标，不表示现有页面全部符合或已通过视觉验收。本次只新增规范及文档入口，不修改界面。

## 1. 设计方向与规则优先级

- 面向长时间阅读与重复科研操作，保持安静、清晰、紧凑；优先呈现问题、数据、来源和当前任务。
- 延续深绿导航、灰白阅读面、低饱和辅助背景。绿色表达主要操作和选中状态，红色表达危险，棕黄色表达警告。
- 页面结构统一为“导航 → 当前任务标题与操作 → 内容 → 结果或证据”。不同科研任务可以采用不同列数，但不能另起一套按钮、字体或状态语言。
- 用留白、标题和分隔线建立层级。禁止为了装饰增加无任务意义的卡片、渐变、光晕、星空背景和持续动画。
- 不把服务器内部配置、实现细节或调试信息放进普通用户的主要操作流程；诊断信息按权限放入详情区域。

规则发生冲突时，先遵守任务明确要求和安全、数据语义约束，再遵守本文。旧版本视觉实施记录保留为历史证据；新增或修改界面的通用设计取值以本文为准。样式最终生效的值必须通过实际层叠核对，不能只读取某个文件的第一条规则。

## 2. 统一来源与职责

| 内容 | 当前维护入口 | 使用约定 |
| --- | --- | --- |
| 共用颜色、间距、圆角、表面和基础控件 | `frontend/src/workspace-theme.css` | 通用视觉值在这里集中维护，页面引用变量 |
| 字体、阅读与数字排版 | `frontend/src/typography.css` | 使用既有字体变量及本地字体回退 |
| 全局与项目导航 | `frontend/src/components/WorkspaceHeader.vue` | 工作区复用导航，不复制页面私有版本 |
| 标题、副标题与操作区 | `frontend/src/components/WorkspacePaneHeader.vue` | 常规面板优先复用，按语义选择 `level` |
| 窄屏面板切换 | `frontend/src/components/PanelSwitcher.vue` | 同类工作区复用选择状态和交互 |
| 会话布局与绘图布局 | `frontend/src/conversation-layout.css`、`frontend/src/workbench-plot.css` | 负责区域、滚动与任务布局，不重新定义全局主题 |
| 身份、账号与管理界面 | `frontend/src/identity.css` | 仅维护该页面族差异，不覆盖其他工作区 |
| 操作解释 | `frontend/src/components/InteractionHints.vue` | 复用提示能力，避免重复气泡 |
| 回答、附件、结果、模型选择 | `frontend/src/components/` 内对应组件 | 保留现有行为与语义，优先扩展已有组件 |

当前样式由 `frontend/src/main.ts` 顺序加载，`workspace-theme.css` 后面仍有绘图和身份样式。不得通过在加载末尾新增整套覆盖文件来解决局部差异。修改通用值应回到共用入口；页面样式使用页面前缀，避免无范围的 `button`、`h1`、`input` 等选择器。

## 3. 颜色与语义变量

下表为当前共用主题的基准。业务组件必须引用变量，禁止重复写入相同色值或自行创建近似绿色、灰色。白色反色文字、透明度和科学图表色板可按明确用途单独定义。

| 角色 | 变量 | 基准值 | 用途 |
| --- | --- | --- | --- |
| 主文字 | `--ink` | `#253b37` | 正文、标题、字段值 |
| 次要文字 | `--muted` | `#64766f` | 说明、辅助元数据，不承载唯一关键信息 |
| 主操作 / 链接 | `--accent` | `#356b56` | 主要按钮、链接、选中强调 |
| 主操作悬停 | `--accent-hover` | `#285542` | 主操作悬停 |
| 选中背景 | `--accent-soft` | `#e9f2ec` | 当前记录、选择项、处理中区域 |
| 普通边界 | `--line` | `#dae3de` | 表格线、分组线、表面边框 |
| 控件边界 | `--line-strong` | `#c2d1c8` | 输入框和需要辨识的控件边框 |
| 主阅读面 | `--paper` / `--panel` | `#ffffff` | 主内容区域 |
| 辅助面 | `--soft` | `#f3f7f4` | 次级底色、禁用背景、代码区域 |
| 页面底色 | `--bg` | `#eff3f1` | 外层背景 |
| 侧栏面 | `--surface-sidebar` | `rgb(245 249 246 / 90%)` | 工作区侧栏 |
| 证据面 | `--surface-evidence` | `#fbfcfb` | 结果与证据区域 |
| 危险文字 / 底色 | `--danger` / `--danger-soft` | `#a33c37` / `#fff3f0` | 删除、失败、风险提示 |
| 警告文字 / 底色 | `--warning` / `--warning-soft` | `#8a642a` / `#fbf6ea` | 部分完成、限制、待确认 |
| 成功文字 / 底色 | `--success` / `--success-soft` | `#21583b` / `#ebf6ef` | 明确完成或就绪提示 |
| 中性提示文字 / 底色 | `--info` / `--info-soft` | `#294e3c` / `#eef5f1` | 一般操作状态与只读说明 |
| 键盘焦点 | `--focus-ring` | `#398269` | 可交互元素的可见焦点 |

补充要求：

- “成功”必须有明确完成文案；普通绿色选中态不等于执行成功。现阶段可复用主色家族，不在页面中另造成功色系统。
- 状态必须同时通过文字或图标表达，不能只依赖颜色；中性信息不能统一套用警告样式。
- 深色导航中的文字与选中态统一由导航样式维护，不直接套用浅色面上的文字颜色。
- 图表按数据类别、数值范围和科学语义配色，必须有图例、单位或色标；不强制把科研曲线全部改为品牌绿。同一数据系列跨图保持颜色一致。
- 新增常用语义色时，先更新本表及共用主题，再使用；不因单页偏好扩充色板。

## 4. 字体与信息层级

| 场景 | 字体 / 字号 | 行高与约束 |
| --- | --- | --- |
| 普通正文、表单值 | `--font-ui`，14px | 约 1.65；常规字重 400 |
| 回答、长篇证据与用户消息 | `--font-ui`，14px | 1.9–1.95；保留段落与引用层级 |
| 面板主标题 | `--font-ui`，17px / 550 | 1.5；窄屏 16px |
| 内容章节标题 | `--font-ui`，17–20px / 550–600 | 不得大过页面主标题的视觉层级 |
| 表单标签、按钮文字 | `--font-ui`，13px | 标签清晰，按钮不使用全大写装饰 |
| 辅助说明、表头 | `--font-ui`，12px | 约 1.5–1.65；不得替代正文 |
| 版本、计数等低优先级元数据 | 10–11px | 仅限辅助信息，不用于操作名称、错误或字段值 |
| 空白起始页标题 | 可用 `--font-editorial`，24–30px | 每个起始区最多一处，不用于数据密集页 |
| 代码、编号、原始数值 | `--font-mono`，通常 12px | 数值列使用等宽数字；科学正文与原文摘录不强制等宽 |
| 品牌字标 | `--font-brand` | 仅用于品牌区域 |

必须使用 `typography.css` 的本地字体及回退链，不引入远程字体服务。每个可见主内容区只有一个主标题，子面板使用较低标题级别。标题层级由语义决定，不能为了字号跳级。

长项目名、邮箱、文件名、引用 ID 必须有换行或省略策略；省略后提供完整内容的可访问入口。科学计数法、负号、上下标、单位和有效数字不因排版被改写。缺失值显示“—”并在必要处说明原因，不以 `0` 代替。

## 5. 间距、形状与表面

| 项目 | 基准 |
| --- | --- |
| 通用间距阶梯 | `--space-1` 至 `--space-6`：4 / 8 / 12 / 16 / 24 / 32px |
| 工作区外框与面板间距 | `--workspace-padding`、`--workspace-gap`：10px；≤680px 为 6px |
| 内容区内边距 | `--pane-padding`：`clamp(20px, 2.4vw, 32px)`；≤680px 为上下 20px、左右 16px |
| 控件圆角 | `--radius-control`：9px |
| 主面板圆角 | `--radius-surface`：14px |
| 对话框圆角 | `--radius-dialog`：18px |
| 普通边框 | 1px；不以加粗边框制造常规层级 |
| 工作区表面阴影 | `--glass-shadow`；普通内容分组不额外叠加阴影 |

间距优先使用阶梯变量；10px 工作区间距等已有结构尺寸按上表保留，不强行凑成 4 的倍数。不要为“看起来差一点”新增 13px、15px、23px 等通用间距。

每页允许“外层工作区面板 + 一层有意义的内容分组”。组内优先使用行、列表、分隔线和留白，禁止连续嵌套有边框、阴影的卡片。半透明与模糊只用于侧栏、导航或模态遮罩，正文、表格与证据阅读面保持稳定背景。渐变仅保留品牌、导航等既有区域。

## 6. 页面骨架与响应式

常规工作区必须复用 `WorkspaceHeader`。当前项目上下文通过项目导航及面板副标题展示，不在多个位置重复堆叠标题。`WorkspacePaneHeader` 左侧放任务标题和必要副标题，右侧放当前区域操作；同一操作区最多一个实心主按钮，其余使用次要或文字按钮。

| 视口条件（CSS px） | 设计行为 |
| --- | --- |
| ≥1440px | 查询与归档工作台在空间允许时展示侧栏、主内容和结果列 |
| 981–1439px | 查询与归档优先主内容；结果按需在当前网格内展开，避免挤压到不可阅读 |
| ≤980px | 查询工作台按现有会话布局切换侧栏和主区；不能机械套用其他页面断点 |
| ≤1200px | 使用 `PanelSwitcher` 的多面板页面按现有结构切换内容、证据或结果 |
| ≤680px | 移动端密度；导航可横向滚动，操作可换行，主要阅读区域单列 |

以上是页面族规则，不是要求所有页面使用同一断点。绘图、账号已有 1100px、860px 等专用断点时可以保留；新增专用断点必须说明解决的实际拥挤问题。

- 导航主行桌面最小高度 56px；移动端主行最小高度 52px，允许导航换行后总高度自然增长。
- 内容标题栏桌面最小高度 60px、移动端 56px。长标题和操作换行后必须增高，禁止固定高度裁切。
- 查询消息与输入区沿用最大宽度 880px。宽屏多余空间用于阅读留白或证据面板，不把长篇回答拉满整屏。
- 布局中的可缩内容使用 `min-width: 0`，内部滚动区域使用 `min-height: 0`。单个区域明确滚动归属，避免正文出现两层纵向滚动条。
- 全页面不出现横向溢出；数据表、代码和科学图可在自身容器内横向滚动，并保留可见的滚动入口。
- 抽屉和浮层基于当前内容网格定位，不假设导航永远是固定高度。关闭浮层后保留选择、滚动位置和输入内容。
- 屏幕键盘打开时仍可到达输入区和主要操作；不能依赖悬停完成移动端任务。

## 7. 通用组件契约

| 组件 | 必须统一的行为与外观 |
| --- | --- |
| 主按钮 | `.button-primary`；普通工作区最小高度 36px、9px 圆角；文案用具体动作，如“保存修改”“开始查询” |
| 次要按钮 | 透明或白色背景、普通边框；同组按钮高度、间距一致；不要与主按钮争夺强调 |
| 危险按钮 | `.button-danger`；危险色 + 明确动作词；不能仅因重要就使用红色 |
| 图标按钮 | 同类图标保持同一线条风格，通常 16–20px；必须有可访问名称；常规命中区至少 36×36px，触控主要操作建议 44×44px |
| 输入 / 选择 | 普通控件最小高度 40px、9px 圆角；真实标签 + 必要说明；占位符不能替代标签 |
| 多行输入 | 延续正文排版；允许内容增长或内部滚动；发送、换行和输入法组合状态行为一致 |
| 标签 | 只用于短状态、类别、计数；状态词统一；非交互标签不得伪装成按钮 |
| 列表项 | 行标题、元数据、尾部操作位置一致；选中态同时有底色与语义状态；悬停不等于选中 |
| 数据表 | 表头 12px，单元格基准内边距 11px 13px；文本左对齐，数量值右对齐；单位放表头，操作单独成列 |
| 提示条 | 中性、处理中、成功、警告、失败分别表达；位置靠近相关操作，不仅在页面最上方显示 |
| 菜单 / 模型选择 | 复用现有结构；开启、选中、键盘关闭和焦点行为一致；模型选择保持既有轻量外观 |
| 对话框 | 清晰标题、影响范围、取消与确认；桌面操作右对齐，取消在前、确认在后；小屏允许按相同顺序换行 |
| 空状态 | 说明当前为空的原因，并给出一个可执行的下一步；不把加载失败显示成“暂无数据” |
| 工具提示 | 使用共用提示；鼠标与键盘均可触发、可关闭；必读限制和错误不能只藏在提示中 |

点击提交后，相关提交按钮必须防重复提交并保持宽度稳定，文字改为“正在保存…”等具体状态。只禁用受影响的操作，不无理由冻结整页。失败后保留可重试输入；敏感密码与验证码按身份安全流程处理。

不要为统一外观改变任务行为：绘图方案审阅、文献发送确认、导入只读标记及数据操作授权均保留。设计调整不构成数据库初始化、迁移或删除的授权。

## 8. 状态、反馈和文案

| 状态 | 用户应看到的内容 |
| --- | --- |
| 初始 / 空 | 当前对象或范围 + 下一步，例如“该项目还没有文档”与“添加文档” |
| 载入 | 指明正在载入的对象；无真实进度时不显示伪造百分比 |
| 执行中 | 当前阶段、已知进度、可用的取消或返回方式；阶段变化通过状态区域播报 |
| 成功 | 具体完成结果；短暂操作可用就地反馈，持久结果保留在记录中 |
| 部分完成 | 成功部分、失败或缺失部分及后续处理方式，不能显示为全部成功 |
| 失败 | 可理解的原因 + 可执行的重试或修正方式；详细错误按需展开 |
| 不可用 / 无权限 | 说明限制及允许的下一步；不显示用户无权访问的对象详情 |
| 过期 / 失效 | 明确状态与重新获取方式；不悄悄替换原有引用或数据版本 |

统一使用简体中文界面和既有功能名称：“查询工作台”“项目归档”“来源关联”“科研流程”“数据绘图”“本地知识库”“文献问答”“本机设置”“本地助手”“账号安全”。SIMBAD、Gaia、ADS 等来源名称保留原文。按钮尽量采用“动作 + 对象”，避免含糊的“确定”“处理”，连续身份步骤可使用“继续”。

时间展示说明时区；记录与下载的精确时间保持可查。错误提示不泄露密钥、密码或内部堆栈。邮件“已提交发送”与“对方已收到”、操作“已请求”与“已完成”必须区分，不使用未经状态证实的成功文案。

## 9. 科研内容的专用规则

- 数据结果、原始证据、模型解释和用户备注明确标注，不能用相同标题和无区分的文本块混在一起。
- 文献证据保留来源、版本、页码或行号、引用 ID 与打开原文入口；模型回答不能伪装成文献原文。
- Gaia 位置检索的候选源不标作已确认成员；图表和统计必须表达所用筛选、单位、样本范围及已知缺失。
- 图像预览保持原始纵横比，坐标轴、色标和标题可读；放大与下载入口位置一致，不裁切科学图像以适应卡片。
- “生成方案”“执行中”“产物可用”“执行失败”“导出失败”各有状态。导出失败不掩盖已经保存的数据和可用产物。
- 文件名、来源链接、引用定位和状态不能只在悬停时显示。未经验证的导入、降级检索及失效引用必须持续可见。

## 10. 可访问性、动效与浮层

以下是本项目的设计验收目标，不代表现有界面已完成符合性认证：

- 普通文字与背景对比度目标至少 4.5:1，大字号文字至少 3:1；可交互边界、焦点及状态指示目标至少 3:1。辅助背景线不承担控件唯一识别责任。
- 所有操作可用键盘到达，焦点顺序符合阅读顺序。共用焦点基准为 2px 外框、3px 偏移；专用输入框可保留等效可见焦点，禁止移除后无替代。
- 使用真实 `button`、链接、标签和标题；当前页面使用 `aria-current`，选择按钮使用 `aria-pressed` 等匹配语义，不能只增加 CSS 类。
- 字段错误关联输入框，提供 `aria-invalid` 和说明关系；阻断错误使用适当的警报语义，普通反馈使用状态语义，避免不断重复播报。
- 模态框优先使用现有原生 `dialog`：打开后焦点进入框内、背景不可操作、关闭后回到触发位置；默认允许 Escape 和取消。避免新建浏览器原生确认框样式，既有确认框后续逐步迁移。
- 层叠关系为正文 < 粘性标题 < 页面抽屉 / 菜单 < 模态层与其提示。优先使用原生顶层机制，禁止通过不断增加 `z-index` 解决遮挡；修改浮层时核对所在堆叠上下文。
- 普通颜色、边框反馈使用约 150ms 过渡；布局展开建议 150–220ms。禁止持续漂浮、闪烁、装饰性缩放及明显位移。
- 所有新增动画遵守 `prefers-reduced-motion`；减少动态效果时直接切换状态并保留必要反馈。
- 在 200% 缩放、长中文、英文 ID 和本地字体回退条件下，文字和主要操作仍完整可达。

## 11. 已登记的页面族例外

例外只调整指定区域的形状或布局，不豁免状态、对比度、焦点与文案要求。

| 范围 | 允许的既有差异 | 边界 |
| --- | --- | --- |
| 全局导航、版本标识、起始页示例 | 胶囊圆角 | 不扩展到所有按钮或内容卡片 |
| 登录、注册等身份表单 | 52px 高胶囊输入框、浮动标签；身份主标题可用 30px | 仅身份步骤；普通科研表单仍使用 40px 基准 |
| 账号安全与管理页面族 | 账号安全嵌入设置内容区，以分组列表呈现，编辑和认证用原生对话框；MFA 复用设置开关；管理页保留独立身份页头及主卡片 | 共用字体、语义颜色和交互规范；不在设置内再嵌套独立页头和主卡片；开关反映服务端真实状态，确认前不伪装已生效 |
| 会话输入区 | 20px 外框圆角，最大宽度 880px | 仅复合输入容器，内部控件按对应契约 |
| 新建会话入口 | 既有 11px 圆角与轻度强调表面 | 不作为普通按钮的新尺寸档位 |
| 设置章节卡片 | 可保留现有一层 16px 圆角章节容器 | 不再在卡片内部叠加装饰性卡片 |
| 本机设置分类页 | 共用工作区导航下使用固定分类侧栏与独立滚动内容区；≤680px 分类改为横向导航 | 内容用设置行与分隔线，不增加嵌套卡片；顶部不再重复显示本机设置入口，账户菜单保留入口 |
| 科学图预览与专用发送控件 | 允许任务所需尺寸与显示方式 | 不牺牲命中区、完整内容与可访问名称 |

新增例外必须在修改说明中写清“区域、原因、与共用规则的差异”，并在本表登记；相同例外出现于第二个页面时，先判断是否应提升为共用变体。

## 12. 开发和维护流程

1. 开发前先阅读本文，识别所属页面族、可复用组件及需要覆盖的状态。复制旧页面前先核对其是否为遗留例外。
2. 新界面先组合既有导航、标题和业务组件，再补充局部布局。相同结构在两个页面重复时，优先抽为共享组件或已有组件的变体。
3. 所有通用颜色、间距、圆角先复用变量。确需新增通用值时，同时更新共用主题和本文；新增字号、控件尺寸等系列值应集中定义，避免散落在页面中。
4. 同类规则在原位置修改或合并，禁止反复追加同一选择器进行覆盖。原则上不新增 `!important`；确需修复既有层叠问题时说明原因与范围。
5. 修改共享样式时，在变更说明列出受影响页面族；修改身份样式必须核对对普通工作区无泄漏，反向修改也一样。
6. 开发阶段依仓库约定不主动运行测试或验收。按用户 2026-11-15 最新要求，完成开发后构建并更新当前相关容器，检查启动健康状态。源码审阅、构建及健康检查不能记作视觉或功能验收通过；授权验收后按下方清单留证。
7. 规范变化与界面变化在同一次修改中同步。文档不能依赖口头约定；未完成统一的遗留项必须有明确状态。

局部样式应表达布局，不重复定义主题，例如：

```css
.example-workspace .example-section {
  display: grid;
  gap: var(--space-4);
  padding: var(--space-5);
  color: var(--ink);
  background: var(--paper);
  border: 1px solid var(--line);
  border-radius: var(--radius-surface);
}
```

其中类名仅为文档示例，不表示仓库已新增该组件。
